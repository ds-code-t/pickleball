## Design philosophy

Fix bugginess through simplicity and one shared code path. AI-agent confusion caused by Workbench/MCP syntax or output is a bug. Output must be concise and token-efficient.

## Shared launcher path (S1–S3 priority)

One shared path for all one-shot commands (`help`, `plan`, `hint`, `status`, `query`, `events`, `workspace-*`):

- `discover` / `workspace-seed` (or the first successful Maven resolve) writes a cached classpath file (e.g. `.pickleball/classpath.cache` or per-run) via the wrapper’s dependency classpath mechanism.
- Subsequent one-shots detect the cache and launch with plain `java -cp @cache tools.dscode.launcher.PickleballWorkbenchLauncher <args>` (or the extracted controller entry point). No Maven startup.
- `help` can short-circuit from the existing static `WorkbenchCliHelp` table when no project context is required, but still uses the same launcher binary.
- `isolate` / full `discover` / `confirm` continue to use the wrapper when a full build or worker launch is required.
- Prefer this single path over per-command hacks.
