# Functionality Change Checklist

Use this checklist for changes to Pickleball behavior. Coding agents should complete it automatically rather than asking the user to repeat it.

## Understand

- [ ] Read `AGENTS.md`.
- [ ] Read the relevant row in `docs/agent/feature-map.md`.
- [ ] Identify the existing behavior from source, tests, consumer scenarios, and documentation.
- [ ] Identify public contracts and backward-compatibility risks.
- [ ] Resolve discrepancies among source, tests, examples, and documentation.

## Implement

- [ ] Register a new Workbench verb in the command line, help, CLI inventory, and guidance golden. Keep `docs/consumer-agent-guide.md` at most 5120 UTF-8 LF bytes. Do not add `--follow` or `--warm` to the major flag lists. `events --follow` and `export-guidance --warm` are documented on their help pages. `gc-runs` accepts only `--dry-run`; any other flag is rejected and deletes nothing.
- [ ] Agent replies use one `items` list (drop an equal duplicate). `--fields` returns only those keys. `--budget` caps the JSON. Prefer short ids. Cursors are per channel. Push rows include `sessionId`.
- [ ] MCP `session` or `sessionId` is the live start host or isolate worker. Do not require a paused worker when that session is up. A strict miss is `unknown session`. CLI `--session` falls back to the current live session. `budget`, `limit`, `timeout`, and `depth` are a whole number or that string.
- [ ] Remaining MCP counts (events afterSequence and limit, inspect maxElements and limit, leaseSeconds, record index, ui ttl, ui_poll after and wait) accept a number or a string. A whole number is forwarded without `.0`. A blank record field is omitted. An omitted refine action is inferred, and an omitted pop action is popout.
- [ ] A placement (`highlight`, `border`, `magnifier`, `label`, `spotlight`) must not expand a short id to the accessible name. Use the element id, or `frame:backend`. `act --query` and `--ref` accept the same short id. A live magnifier scales the copied target around its center. `snap --depth` does not charge a document, shadow root, html, body, or head. An icon-prefixed link resolves to the anchor. explain and act share shown-or-not visibility. `watch` mutation and change notice a replaced iframe document and a changed selected tab. A spinner or loading class is a covering mask, and `act --timeout` is that wait. `confirm` and `discover` summary counts are this launch only. A start that does not become healthy names the stage and stops the partial Chrome. screenshot --out is closed before the reply. `isolate` and `session-start` seed a missing run id. Discover, confirm, and the first isolate take as long as the run and the workspace copy. A live page uses `start`. No faster copy is claimed.
- [ ] Person-facing controls use `sending`, then `delivered` when the push channel or store takes the event, then `read` when the agent consumes it. The step editor and a popped-out chat use the same states. `ask-and-wait` splits `--choices` on commas or a JSON array into one button each, returns only the clicked choice, shows `Answer sent: <choice>` for about 1.5 seconds, and recovers a stored answer. A guide input ends on Enter, blur, or `expect` (not a typing pause), finds a digit-leading id, refuses a missing current target without listing it in Steps, and removes field step-done badges when the guide ends. Input, change, select, and Enter/Tab/Escape are not pushed unless recording is on. `events --follow` and `ui-poll` start at now unless `--cursor` or `--after` is set. `--until=human` is a non-agent chat message, an answer, or an agent-UI click, not a keystroke. `chat-turn` skips a message the panel already shows as Read, and popping chat back in keeps that Read mark. Pin, checklist, and status are cards; `--id` is the placement id and `--check` is the 1-based `data-pkb-check` row. Cards stay clear of the top-left logo. A reload rebinds `pkbSurface`. `record --editor` is the live step list. `--edit`, `--move`, `--nest`, `--outdent`, `--add`, and `--delete` write it back. `--popout --panel=editor|chat` and `--popin` move that panel. Person-facing instructional text quotes a concrete value (`Enter "abc"`) and paints that quote as a `.pkb-value` chip (`HumanValue`, page `appendDistinguished`). Agents emit the quotes. The stored answer stays the clicked label. Injected UI carries `data-pkb-meta="true"`, an overlapping `data-pkb-purpose` (`panel`, `guide`, `placement`, `editor`, `callout`, `recorder`, `layer`), and a `pkb-` id when an id is assigned. Recording skips those nodes. Query them with `[data-pkb-meta="true"]` or `[data-pkb-purpose~="guide"]`. Panel tabs read Chat, Guide, and Recorder. The step editor is the Steps window. A minimized or closed panel or editor leaves a corner pill that reopens it. The recording bar says Recording or Paused, with Pause/Resume, Keep step, and Drop step. A finished guide leaves the Guide list. An unread count survives pop-in.
- [ ] The historical dashboard stays one static HTML file. Filters stay pinned, the timeline is colored, entity and case rows fill the entity filter, an error row fills the text filter, and run links are grouped as Features, Data, Artifacts, and Commit. It does not start a server and it does not change the store. `dashboard query` returns lean JSON (`name`, `ref`, `scenarios`, `artifacts`, `data`, `summary`) for a time range, status, feature, entity, text, or element hint. MCP `workbench_dashboard_query` only forwards that command. `dashboard xref` accepts an id, a selector, or a role and name, and returns runs, scenario paths, log excerpts, screenshot paths, overlapping runs, summary, overlay, and chat. `--window` writes one HTML file. MCP `workbench_dashboard_xref` only forwards that command. `dashboard overlap` groups runs that share a time and lists a failure line only when at least two of those runs share it. MCP `workbench_dashboard_overlap` only forwards that command. For an intermittent failure, run overlap, then xref for the element.
- [ ] The page engine is Chrome DevTools. Do not pass `--engine=` or `--browser=selenium`. `observe --request` and `--response` filter traffic (`*` keeps that kind). `observe --follow` and `log-tail --follow` return in this process. `selftest ui --component=feedback` checks sending, delivered, and read without Chrome. `confirm` keeps the larger failure count. Replies unescape one quote level and prefer the short id over a long ref or string handle. The consumer recording example is `maven-consumer-project/src/test/resources/features/recorded-collaboration.feature` (`URL.dynamicSteps`, `site/dynamic-steps.html`). A person click or type inside a content iframe is that inner element and frame (`in the "<id>" IFrame`), not a hover on the iframe host. Hover and focus are not recorded unless noise mode is on. The panel, editor, recording bar, and placements are not recorded. Consecutive edits of one field are one step. A tab stays a Tab, `--inject --role` is honored, and `form-fill` is one step. `--rename` is one parameter. `--literal` fails on an unknown name. `--context` is a `#` comment. `selftest record` checks an iframe click and type. Unattended recipes and the human-participation script are `docs/collaborative-self-test.md`. They are exported with guidance. They are not an `@all` feature.
- [ ] `pingMs` from `export-guidance --warm` is the warm controller (target at most 1 s). A fresh JVM wall clock for one verb is classload, not that ping. Live Edge skips when `microsoft-edge` is not on PATH. Live AT-SPI skips when the session bus is down (`no AT-SPI bus`). Do not start a fake bus.
- [ ] A browser protocol verb goes through `BrowserProtocols.serve` so `--via` and the fallback order hold, says `via` in its reply, returns `error: unsupported:` with a `fix:` when no backend can serve it, and adds a row to the support table in `docs/browser-protocols.md`. Optional add-ons download only from `optional-install <name> --confirm` with a pinned SHA-512; tests never download.
- [ ] Preserve Java 21 compatibility.
- [ ] Preserve established public behavior unless a breaking change was requested.
- [ ] Avoid unrelated refactoring.
- [ ] Put disposable scripts and intermediate artifacts under `.agent-work/`.
- [ ] Keep reusable maintained tooling under `scripts/`.

## Verify behavior

- [ ] Add or update focused framework tests.
- [ ] Add or update Maven consumer scenarios for consumer-visible behavior.
- [ ] Update service-call definitions, configuration, data, local endpoints, or pages when needed.
- [ ] Cover meaningful edge and compatibility cases.
- [ ] When an agent launches Pickleball tests with known execution settings, use `pkb_runvars` as the authoritative input unless the test intentionally exercises normal JVM/profile precedence.
- [ ] Never supply `pkb_run_profile` as test input; it is derived output.
- [ ] For Workbench/protocol/worker changes, preserve the JDK-only shared protocol, core-free controller artifact/process, separate consumer worker, consumer-authoritative classpath, and opaque nested payload.
- [ ] Never restore a root/`tools.dscode:pickleball`/behavioral-control dependency to Workbench to fix compilation.
