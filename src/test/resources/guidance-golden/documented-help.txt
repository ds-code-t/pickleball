# help
Pickleball Workbench. help <command> prints usage. help <flag> prints that flag.
exit 0 ok, 1 failed, 2 usage. --json is one JSON object and no preamble.
decide: discover, then plan, then run. plan lists the scenarios. run is confirm, or isolate then execute-step.
Timing is .pickleball/runs/<id>/launch-timing.txt. Stderr timing only when PKB_WORKBENCH_TIMING=1 or -Dpkb_workbench_timing=true.
Do not pass pkb_run_profile. Do not open the GUI to test yourself. isolate is the headless session.
run: discover confirm plan hint discover-hint resolve-runvars
workspace: workspace-show workspace-edit workspace-seed
session: isolate session-start execute-step status events stop kill open-scenario example play from-here pause insert-step update-step diagnostic-run save refresh session-sync worker-start worker-restart worker-stop open-window close-window show-run
coordination: short-log note inbox finish presence post history gc-runs gc-versions use-version export-guidance
descriptors: session list | session info <sessionId> [--json] | session hold <sessionId> | session release <sessionId>
page: inspect-page find-element
retrieval: query runs | query get | query query | query search | query props | query errors | query tail
controller: sync worker-check live-check ui mcp session
all: close-window confirm diagnostic-run discover discover-hint events example execute-step export-guidance find-element finish from-here gc-runs gc-versions help hint history inbox insert-step inspect-page isolate kill live-check mcp note open-scenario open-window pause plan play post presence query refresh resolve-runvars save session session-hold session-info session-list session-release session-start session-sync short-log show-run status stop sync ui update-step use-version worker-check worker-restart worker-start worker-stop workspace-edit workspace-seed workspace-show
