# help act
Usage: act --target=<selector> [--kind=click|type|hover|press|select|attach] [--query=<text>] [--ref=<ref>] [--pick=<n|name>] [--purpose=<token>] [--value=<text>] [--condition=title=<text>|text=<text>|url=<text>|ref=<id>:selected] [--snap=diff|auto] [--timeout=<ms>]
With --pick and several hits the reply lists candidates and picked (index, name, why). --pick chooses one hit in the same snapshot, so the ref cannot go stale. A success includes checked and settleMs. Hover on a visible element is applied and dispatched. A click is applied when the page or that element's text or state changes. A covering mask that does not clear fails the click. --timeout is that wait in milliseconds, including a spinner or loading class. visible is whether the element is shown, the same value explain reports. Replies include frame. A short id (s1.h18) names that element and is not expanded to its accessible name.

# help answer-wait
Usage: answer-wait --id=<question> [--timeout=<ms>] [--choices=a,b]
Reads the choice for a question ask or ask-and-wait --async already showed. Same fields as ask-and-wait: id, value, choice, applied. Missing --id exits 2. Timeout exits 1 with error timeout and closes the card. The wait does not hold the command lane.

# help ask
Usage: ask --say=<question> [--choices=Yes,No] [--handle=<target>] [--id=<question>] [--sensitive=true] [--min-show=<ms>] [--run-id=<id>]
--min-show keeps an unanswered card on screen at least that long. --choices is a comma list or a JSON array. Each choice is its own button.

# help ask-and-wait
Usage: ask-and-wait --say=<question> [--choices=a,b] [--id=<id>] [--timeout=<ms>] [--async]
Returns only the clicked choice. --choices is a comma list or a JSON array, one button each. The card shows Answer sent: <choice> for about 1.5 seconds. An answer already stored is returned even if the worker call is tight. --async returns id immediately. answer-wait --id reads the choice. A bare timeout is milliseconds. A trailing s is seconds.

# help doctor
Usage: doctor
Reports chrome, session, health, headed, pid, bridge, worker, lease, leaseLeft, orphans, frame, placed, and waits. chrome=present only while the recorded Chrome pid is alive. lease is open when leaseLeft is 0. live-stop clears the session. No session still exits 0. waits is how many blocking waits are off the command lane. A wait in progress stays health=ok.

# help events
Usage: events [--hooks] [--json] [--cursor=<token>] [--run-id=<id>] [--follow] [--until=<type|text=...>] [--timeout=<seconds>] [--type=<name>] [--echo] [--from=any] [--format=lines|json] [--fields=<a,b>] [--where=<k=v>] [--limit=<n>] [--budget=<bytes>] [--group=type|role] [--priority=on]
--follow tails .pickleball/agent-events.jsonl from the end of the file unless --cursor is set, so earlier lines are not returned. --until=human is a chat message, an answer, or an agent-UI click, not a keystroke. It exits on the first match in this process. It does not hop and it does not leave a child process. No Workbench session is required. --timeout default 30, max 120. 0 checks once. Own source=agent lines are hidden unless --echo or --from=any.

# help record
Usage: record --start [--session=<id>] | --stop | --status | --pause | --resume | --script | --editor | --edit --index=<n> --text=<phrase> | --move --from=<n> --to=<n> [--depth=<n>] | --nest --index=<n> | --outdent --index=<n> | --add [--index=<n>] [--text=<phrase>] [--depth=<n>] | --delete --index=<n> | --popout --panel=editor|chat | --popin --panel=editor|chat | --save --name=<name> | --load --name=<name> | --list | --export --name=<name> --format=feature [--out=<file>] | --run --name=<name> [--param=<name=value>] | --inject --kind=<click|input|select|key|hover|drag|check> [--query=<label>] [--value=<text>] [--role=<role>] | --rename --from=<param> --to=<param> | --literal=<param> | --reject --index=<n> | --accept --index=<n> | --context --text=<phrase>

# help snap
Usage: snap [--target=browser:auto|browser:<id>|browser:cdp=<url>|desktop:<pid>|desktop:app~<name>|ref:<doc>:<handle>] [--session=<id>] [--within=<id>] [--depth=<n>] [--group=role|type] [--priority=on] [--format=lines|json] [--fields=<a,b>] [--where=<role=button>] [--limit=<n>] [--budget=<bytes>] [--include=values,highlights,cards,guide,placements,chat] [--exposure=human|full] [--since=<snapCursor>]
Rows carry value (passwords redacted), checked, purpose, badge, highlight, guide, card, and msg when present; --include narrows them. --since prints only rows added or changed since that snap and lists removed rows. --within is a ref, short id, backend id, or element id. --session is the start or isolate session id. A document, shadow root, html, body, and head do not consume a depth level.
