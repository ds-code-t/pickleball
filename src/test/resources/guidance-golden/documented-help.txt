# help act
Usage: act --target=<selector> [--kind=click|type|hover|press|select|scroll|attach] [--query=<text>] [--ref=<ref>] [--pick=<n|name>] [--purpose=<token>] [--value=<text>] [--condition=title=<text>|text=<text>|url=<text>|ref=<id>:selected] [--snap=diff|auto] [--timeout=<ms>] [--dx=<px>] [--dy=<px>] [--budget-ms=<ms>] [--aria-ref=<eN> (refs from aria-snap --mode=ai, Playwright)]
Without a query or ref the error is: act requires --query or --ref. With --pick and several hits the reply lists candidates and picked (index, name, why). --pick chooses one hit in the same snapshot, so the ref cannot go stale. A success includes checked and settleMs. Hover on a visible element is applied and dispatched. A click is applied when the page or that element's text or state changes. A covering mask that does not clear fails the click. --timeout is that wait in milliseconds, including a spinner or loading class. visible is whether the element is shown, the same value explain reports. Replies include frame. A short id (s1.h18) names that element and is not expanded to its accessible name. --human-override=<reason> is accepted on act (owner only, logged) and is not a verb flag. type reports via (cdp-insertText, cdp-keys, or input-chain), value, and verified; applied follows that read-back, including a selected option and an upload offer. An ambiguous reply lists each candidate with the reason it lost. --pick=<role> chooses the one hit with that role. --budget-ms is the same millisecond cap as find (best hits so far, budgetExceeded:true). Desktop type uses ValuePattern, then TextPattern plus SendInput, then SendInput. Live desktop input is refused unless the target window is foreground and its title matches (case-insensitive equality, or either title contains the other). The reply includes window. A fixture is not live and is not refused. act --kind=type keeps a document or edit when one matches, including over a nested button with the same label. act --kind=scroll maps to the engine scroll verb. With --query or --ref the node is scrolled into view; when --dx or --dy is set the engine then wheels by those pixels (omitted deltas are 0, into-view only). Without a query or ref the page scrolls by --dx/--dy; when both are omitted, dy is one viewport height. The reply reports dx, dy, into_view, scrollX, and scrollY, and scrollLeft/scrollTop when the target is an element. Desktop act --kind=scroll is not supported and returns an error with a fix, not a missing-kind error. attach is refused while the session is human-locked.
Tier: human.

# help answer-wait
Usage: answer-wait --id=<question> [--timeout=<ms>] [--choices=a,b]
Reads the choice for a question ask or ask-and-wait --async already showed. Same fields as ask-and-wait: id, value, choice, applied. Missing --id exits 2. Timeout exits 1 with error timeout and closes the card. The wait does not hold the command lane.
Tier: control.

# help ask
Usage: ask --say=<question>|@file [--choices=Yes,No] [--handle=<target>] [--id=<question>] [--sensitive=true] [--min-show=<ms>] [--run-id=<id>] [--type=text|choice|confirm] [--prompt=<question>|@file] [--options=<a,b>]
--min-show keeps an unanswered card on screen at least that long. --choices is a comma list or a JSON array. Each choice is its own button. A text card (no --choices) shows a text field named pkb-answer and a button labeled Send. Send, or Enter in the field, submits when the trimmed text is not blank. An empty field does not submit. The answer event is type=answer. --type writes a card with no live page. A choice answer must be one of --options. @file is a path relative to the project, or an absolute path. Use it to pass spaces and quotes on Windows. A missing file is error: and fix:.
Tier: control.

# help ask-and-wait
Usage: ask-and-wait --say=<question> [--choices=a,b] [--id=<id>] [--timeout=<ms>] [--async]
Returns only the clicked choice. --choices is a comma list or a JSON array, one button each. The card shows Answer sent: <choice> for about 1.5 seconds. An answer already stored is returned even if the worker call is tight. --async returns id immediately. answer-wait --id reads the choice. A bare timeout is milliseconds. A trailing s is seconds.
Tier: control.

# help doctor
Usage: doctor
Reports chrome, session, health, headed, pid, bridge, worker, lease, leaseLeft, orphans, frame, placed, and waits. chrome=present only while the recorded Chrome pid is alive. lease is open when leaseLeft is 0. live-stop clears the session. # help find
Usage: find --target=<selector> [--query=<text>] [--format=lines|json] [--fields=<a,b>] [--where=<k=v>] [--limit=<n>] [--budget=<bytes>] [--budget-ms=<ms>] [--group=type|role] [--priority=on] [--purpose=<token>] [--exposure=human|full] [--include=<groups>] [--role=<role> [--name=<name>] [--description=<text>] [--via=auto|bidi|playwright|cdp]]
--role finds by accessibility role and exact name (BiDi accessibility locator, Playwright getByRole, CDP Accessibility.queryAXTree) in every frame unless --frame=top or --frame=<id> (default --frame=all); hits carry source=role, and queries without --role rank as before. An exact accessible name beats a substring: when one hit's name equals the query, substring hits are dropped. --purpose (or purpose=<token> in the query) keeps controls whose data-pkb-purpose has that token. Hits are returned once, as items. A long page ref is not embedded. --fields keeps only the named keys and rejects an unknown name (error: unknown field). When the query engine has no selector, the error is: find requires --query, and it does not name --text, --pipeline, or --selector. Hidden inputs are not textboxes and are omitted. Human exposure keeps a collapsed control with visible=false. An icon inside a link, including a glued prefix, resolves to that link. When nothing matches exactly, the query's words (- and _ read as spaces) match a run of whole words in a name, label, or text: Upload and Upload-File find Upload File; upload --query matches the same way. During scroll-search, stderr prints progress every 2 seconds. When --budget-ms elapses, the reply keeps the best candidates so far and sets budgetExceeded:true. A missing --budget-ms adds no budget field. --budget stays a byte cap.
Tier: human.

# help frame
Usage: frame --target=<selector> [--list] [--reset] [--enter=<id|name>]
Lists frames, returns later steps to the top document, or enters a frame. --reset clears the entered frame and the page driver. The page engine is Chrome DevTools. --engine=selenium is not supported. --enter scopes later find, act, snap, and inspect to that frame, and enters an iframe with that id, name, or title when the driver can see it. Replies include frame. frame --list rows include id, name, url, and sameOrigin (scheme, host, and port; different ports are cross-origin; the top frame is same-origin). A list with no --enter and without --reset is served by the start host even while an isolate worker is alive. --enter and --reset stay on the current target.
Tier: control.

# help record
Usage: record --start [--session=<id>] | --stop | --status | --pause | --resume | --script | --editor | --edit --index=<n> --text=<phrase> | --move --from=<n> --to=<n> [--depth=<n>] | --nest --index=<n> | --outdent --index=<n> | --add [--index=<n>] [--text=<phrase>] [--depth=<n>] | --delete --index=<n> | --popout --panel=editor|chat | --popin --panel=editor|chat | --save --name=<name> | --load --name=<name> | --list | --export --name=<name> --format=feature [--out=<file>] | --run --name=<name> [--param=<name=value>] | --inject --kind=<click|input|select|key|hover|drag|check> [--query=<label>] [--value=<text>] [--role=<role>] | --rename --from=<param> --to=<param> | --literal=<param> | --reject --index=<n> | --accept --index=<n> | --context --text=<phrase>
Records DOM and desktop interactions. # help snap
Usage: snap [--target=browser:auto|browser:<id>|browser:cdp=<url>|desktop:<pid>|desktop:app~<name>|desktop:app=<name>|ref:<doc>:<handle>] [--session=<id>] [--within=<id>] [--depth=<n>] [--group=role|type] [--priority=on] [--format=lines|json] [--fields=<a,b>] [--where=<role=button>] [--limit=<n>] [--budget=<bytes>] [--include=values,highlights,cards,guide,placements,chat] [--exposure=human|full] [--since=<snapCursor>] [--aria (Playwright aria snapshot; see aria-snap)]
Rows carry value (passwords redacted), checked, purpose, badge, highlight, guide, card, and msg when present; --include narrows them. --since prints only rows added or changed since that snap and lists removed rows. --within is a ref, short id, backend id, or element id. --session is the start or isolate session id. A document, shadow root, html, body, and head do not consume a depth level.

# help start
Usage: start --url=<page> | --url-key=<URL.key> --browser=<chrome|edge|chrome-headless> [--headed] [--human] [--hold=<seconds|forever>] [--panel] [--size=1600x1000] [--env=KEY=VALUE]
Opens the browser, navigates, and waits until GET /health is ok. fixture: names a built-in page. --panel opens the page panel. live-start is start. The reply includes the agent envelope. Its classpath is this JVM's java.class.path when that path contains LiveBrowserHost, otherwise the versioned or .pickleball/workbench/classpath.cache when that file does, otherwise the classes that loaded this program. # help validate
Usage: validate [--tags=<expr>] [--name=<regex>] [--run-id=<id>] [--max-steps=<n>] [--all] [--noop]
Reports undefined steps, ambiguous glue, and unresolved RUN SCENARIO targets. Outline rows are expanded. Core steps count as defined. A long suite prints progress and stops at a step cap unless --max-steps or --all is set, and reports how many scenarios were skipped. Plain validate lists empty consumer step definitions (noop:true) and exits 1 when any are found. --noop is accepted. --noop with --tags still filters the feature scan and lists those noops. A non-empty body is not listed. Runs nothing. A flag this command does not use, including --quiet, is rejected with error: and fix:.
Tier: control.

# help wait-any
Usage: wait-any [--answer=<question>] [--chat=human|agent|any] [--watch=<short id>:click] [--timeout=<ms>]
Returns whichever condition comes first and names it in fired (answer, chat, or watch). At least one condition is required. Events already stored are ignored. --chat does not treat source=system as a message. A click for another id does not fire --watch. An equal at prefers answer, then chat, then watch. Timeout exits 1 with error timeout. A bare timeout is milliseconds. A trailing s or ms wins. The wait does not hold the command lane.
Tier: control.

# help watch
Usage: watch --target=<selector> [--ref=<ref>] [--until=mutation|change|visible|hidden|text=<text>|click] [--kinds=<kinds>] [--duration=<ms, up to 120000>] [--selector=<css>] [--debounce=<ms>] [--attributes=a,b] [--contains=<text>] [--own]

A replaced iframe document and a changed selected tab count even when that document's counter starts at zero.
