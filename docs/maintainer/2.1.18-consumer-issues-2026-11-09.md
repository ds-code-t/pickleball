### 1. Equality checks keep a trailing line break
- Change: "…submit.\n" is equal to "…submit." → equal on 2.1.16, not equal on 2.1.18.
- Observed: EOR_Common_Behavior — EOR Select Customer, row "VT: No Cust Selected": `ensure Error Banner is equal to "Please select one customer for each individual and submit."` passes on 2.1.16, fails on 2.1.18 (Pega banner text ends in `\n`).
- Exposure: ~835 element-text equality checks (495 Field, 260 Cell, 17 Dropdown Selection, 6 Error Banner, …). IF: conditions on such text silently take the other branch.
- Reproduce: local_tests/PB218_Probe.feature, scenario W1 (no browser).
- Fix: Pickleball trims trailing whitespace in equality, or change affected checks to `contains` / `starts with`.

### 2. Workbench re-runs scenarios after ~10 minutes
- Change: 2.1.18 launches in a warm JVM. At ~10 min, launch-timing.txt logs `stage=fallback … fresh-jvm` and starts a second Maven JVM that re-runs the selection while the first is still running.
- Observed: rows executed twice — 23/102 (full run), 17/27 (confirm), 7/7 (ELSE run). Effects:
  - passed rows re-run and fail (ECV row);
  - 4 of 5 browser-death errors `Error communicating with the remote browser`, `UnreachableBrowserException`) occur on the second execution;
  - the two runs collide on shared QA data, and the run record keeps the last attempt.
- Not affected: normal ▷ mvn test / CI.
- Workaround (verified): `PKB_WORKBENCH_SPEED=sequential` (or `-Dpkb.workbench.speed=sequential`). Report to Pickleball.
