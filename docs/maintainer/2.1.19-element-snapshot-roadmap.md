# 2.1.19 ElementSnapshot Unification

**Goal**: One immutable `ElementSnapshot` for both DOM paths. Fix bugginess through simplicity and one shared code path. Unclear APIs, output, or docs count as a bug. Docs and tests ship with every change. Never weaken or delete an existing test to get green.

**Agreed design** (owner bot + Heavy). Build covers every phase below. Nothing in this list is deferred.

## One record

`ElementSnapshot` (next to `ElementWrapper`):

| Field | Meaning |
|---|---|
| `nodeId` | Composite frame + backend node id. Null on the Selenium path. Stable until the node is re-rendered, then a new id. |
| `tag` | Lowercase tag name. |
| `text` | Historical `textContent`: value attribute for `input`/`textarea`, selected option text for `select`, otherwise `innerText`. |
| `value` | DOM value property, or the value attribute when the property is empty. |
| `selectedValue` | Concatenated value (attribute, else text) of direct children with the `selected` attribute. Null when there are none. Empty string when those children exist and the value is empty. |
| `attributes` | Unmodifiable map of every attribute. |
| `bounds` | Composite border box. Null on the Selenium path. |
| `siblingIndex` | Previous element siblings. Real in both modes. Never a hard-coded 0. |
| `sameTagIndex` | Previous siblings with the same tag. Real in both modes. |
| `stableSelector` | Derived once: `#id` when it is a unique CSS id, else `data-testid` / `data-test` / `data-user-id` / `name` / `title` / `aria-label`, else a short unique CSS path. |

`ElementWrapper` holds one record. Every snapshot read goes through the record. `getAttributeSnapshot()` remains only as a deprecated JSON view rebuilt from the record (`tagName`, `textContent`, `childValue`, `attributes`, `siblingIndex`, `sameTagIndex`). The element return value is cached on the wrapper. The snapshot JSON is not mutated to store it.

Public getters that stay: `getAttributeSnapshot`, `getElementReturnValue`, `getSnapshotAttribute`, `snapshotAttributeEqualsIgnoreCase`, `snapshotContainsAnyAttribute`, `getSnapshotValue`, `getTagName`, `getIndex`, `getSameTagIndex`. `snapshot()` is the record.

## One script, two producers

`ElementSnapshotScript.FUNCTION` is the only reader of tag, text, value, selected child, attributes, positions, and the stable selector.

- **Selenium** (`SeleniumSnapshotProducer`): the live `WebElement` is `arguments[0]`. `nodeId` and `bounds` stay null.
- **Composite** (`CompositeSnapshotProducer`): dom-composite 2.4.0 has no element eval, and `CompositeWebElement` is not a WebDriver node, so it cannot be `arguments[0]`. The same function runs through the driver's `JavascriptExecutor` after the script locates that one node from id / data-testid / data-test / data-user-id / name / text / the composite css or xpath, walking same-origin frames. `nodeId` and `bounds` come from the composite hit. If no candidate matches exactly one node, construction fails with the selector list and the mode. Positions are never filled in as 0.

## One selector, one refresh

`xpath1`, `xpath2`, and the overlap re-find are removed in phase 3. Any selector logic that is still required lives in the shared script's selector derivation.

`refreshSnapshot()` is the only recovery path. It runs on `StaleElementReferenceException`, on dom-composite `StaleException`, or when the caller asks. It does not run on a read.

1. Wait with the existing budget (`safeWaitForPageReady` / `safeWaitForElementReady`, 60s).
2. Find that one element by `stableSelector`. Composite mode uses the composite finder when it is primary. Selenium mode uses the driver.
3. Replace the wrapper's element and snapshot. Clear the return-value cache.
4. If the selector matches nothing, or more than one node, fail. The message names the mode, the selector, the node id, and what was tried. No silent miss.

A node id is stable only until re-render. There is no liveness query yet (upstream ask). Refresh does not keep a whole-page snapshot.

## Performance

Snapshot once at construction. Refresh only on stale or an explicit `refreshSnapshot()` / `takeSnapshot()`.

- Selenium cost: one element script.
- Composite cost: one element script that also locates the node. Not a page snapshot, not a second composite `snapshot` of the document.

Trace log on create and refresh: `event`, `mode`, `selector`, `nodeId`, `durationMs`. The old `System.out.println` of the snapshot is gone. `DEBUGelementsnapshot` still traces the JSON view.

## Phases

Push each phase to `2.1.19` only. Never commit, push, or merge to `master`. No force-push. Targeted tests between phases. Full regression only after phase 4.

### Phase 1 — record, Selenium producer, stable selector

`ElementSnapshot`, the shared script, `SeleniumSnapshotProducer`, wrapper field, getters, return-value cache. Composite hits already go through the shared script so positions are real before the class is split out. `xpath1` / `xpath2` stay until phase 3 so recovery does not change in the same commit.

Tests: Selenium producer (positions, selected child, attributes, selector) and wrapper construction / getters. No full suite.

### Phase 2 — composite producer and parity

`CompositeSnapshotProducer` owns the composite entry. Parity test on `src/test/resources/element-snapshot/fixture.html`: Selenium and composite producers return equal fields except `nodeId` and `bounds`. The test locates a binary only inside this repo. A missing vendored binary skips the live-binary case with that reason. It does not search `PATH`, `~/.m2`, or a sibling checkout. In-process parity (the producer + the shared script on the fixture) always runs.

### Phase 3 — one refresh path

`refreshSnapshot()`. `refindElement` and `executeWithStaleRetry` use it. Delete `xpath1`, `xpath2`, and the overlap re-find.

Tests: forced stale in both modes (replace the node, refresh, fields match; missing node fails with the clear error). Consumer scenarios in `maven-consumer-project` for `pkb_composite` on and off.

### Phase 4 — docs, upstream asks, full regression

Javadoc on `ElementWrapper` / `ElementSnapshot`. Staleness section and a short AI-agent note in this file: one snapshot, read `snapshot()`, do not parse two XPaths, do not expect positions of 0. Upstream list for the DOM Selector bot, non-blocking:

- subtree snapshot rooted at one node
- `selectedValue`, `siblingIndex`, and `sameTagIndex` on the node description
- a node liveness query

Then full regression: `./gradlew test` on root, `pickleball-workbench`, `pickleball-control-protocol`, `pickleball-control-api` (JDK 21); consumer `@all` headless; `python scripts/consumer_sim.py --publish`; `python scripts/verify_agent_contract.py`; GitHub Actions `validate`, `windows`, and `gate` green on `2.1.19`.

## Logging checklist

- CLI-first trace line for create and refresh (`mode`, `selector`, `nodeId`, `durationMs`).
- Failure text starts with `error:` and includes `fix:`, the mode, and the selector that was tried.
- No `System.out` of the snapshot. No silent stale miss.

## Success

One snapshot concept. Both producers return equal real fields (parity test). No hard-coded positions. One refresh path. Snapshot once. Callers and public getters still behave. Docs, this roadmap, and `docs/agent/repository-index.md` updated. Full regression green.
