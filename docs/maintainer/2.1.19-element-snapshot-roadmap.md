# 2.1.19 ElementSnapshot Unification Roadmap

**Goal**: Rework ElementWrapper so its internal element snapshot is a single ElementSnapshot record produced by either the dom-composite path or the Selenium fallback (`pkb_composite=off`). Aligns with owner philosophy: fix bugginess through simplicity and one shared code path; AI-agent confusion counts as a bug; docs and tests with every change.

**Context**: 2.1.19 integrates dom-composite as primary DOM path. ElementWrapper currently builds an ObjectNode attributeSnapshot (tag, text/value, selected-child, all attributes via JS, sibling/same-tag position) at construction and after stale re-find. Composite path (takeCompositeSnapshot) copies tag/text/attrs and hard-codes positions to 0. Stale recovery uses two XPaths + elementMatch paths with waits. ~16 files consume via getWrappedElements/ElementMatch.

dom-composite `snapshot` stores nodes in session with stable key = frame + backend node id (stable while element lives). CompositeWebElement holds node id, attrs, bounds. No subtree snapshot, no liveness query yet.

**Recommendation**: Do it. One ElementSnapshot record (nodeId, tag, text, attrs, bounds, selectedValue, siblingIndex, sameTagIndex, stableSelector) with two producers. ElementWrapper holds the record instead of raw JSON + two XPaths. Stale refresh = element-scoped re-snapshot via stable selector (composite) or existing re-find (Selenium). No whole-page cache (invalidation risk). Positions computed in Pickleball until upstream adds them. Upstream asks documented but non-blocking.

## Phases

### Phase 1: ElementSnapshot record + Selenium producer
- Functionality: Introduce immutable (or refreshable) ElementSnapshot record/POJO with the fields above. Extract Selenium producer from existing takeSnapshot JS logic (tag, text, attrs, positions via sibling walk). ElementWrapper holds ElementSnapshot instead of ObjectNode; retain xpath1/xpath2 and current recovery temporarily. Getters for return value etc. adapted.
- Docs: Update ElementWrapper javadoc and any maintainer notes on snapshot fields and dual-path intent.
- Targeted tests: Unit tests for Selenium producer (positions, selected child, attrs) and ElementWrapper construction/refresh. No full suite.

### Phase 2: Composite producer
- Functionality: Composite producer from CompositeWebElement (nodeId, tag, text, attrs, bounds, selected). Compute positions in Pickleball (JS fallback via adapter or approximate; document if 0 for now). Integrate into ElementWrapper; takeCompositeSnapshot becomes the producer. Stable selector from recommended or attrs.
- Docs: Document composite producer and position computation note.
- Targeted tests: Composite-mode snapshot tests (pkb_composite=on). Verify fields match Selenium where possible.

### Phase 3: Unified stale recovery
- Functionality: Shared refreshSnapshot() path. Primary: element-scoped composite re-snapshot via stable selector (or node key if available). Fallback: existing Selenium XPath re-find. Update refindElement and executeWithStaleRetry. Document staleness semantics (nodeId stable until re-render; refresh on StaleElementReferenceException).
- Docs: Staleness semantics section; AI-agent notes on one snapshot concept.
- Targeted tests: Stale recovery tests for both modes (force stale, verify re-find/re-snapshot and field consistency).

### Phase 4: Upstream asks + full regression
- Functionality: None (document only). Upstream asks for dom-composite (owned by DOM Selector bot): subtree snapshot with root arg; selected value + position fields in node description; node liveness check query.
- Docs: Upstream request list with rationale.
- Full regression: `./gradlew test` across modules; consumer `@all` headless; `scripts/consumer_sim.py --publish`; `scripts/verify_agent_contract.py`. CLI-first and logging checklist (trace logs for snapshot/refresh, no silent failures).

**Estimates**: 300-500 LOC total. Phases independent enough for incremental PRs on 2.1.19 (never push to master).

**Success criteria**: Single snapshot concept; both paths produce equivalent ElementSnapshot; stale recovery works; no regressions; clearer for AI agents and maintainers.
