# Pickleball 3.0.0 Workbench Full-Edit + DOM Engine Core Design

**Branch:** `3.0.0` only. Start SHA: `6a1bf40d`. Updated tip: `00e51db`.

**Version:** stays `3.0.0`.

**Locked direction (2026-11-12, final for this round):** Single consistent CLI-first edit model for four Workbench surfaces, Java DOM engine packaged as core of the pickleball jar, and live native desktop access (Windows UIA, macOS AX, Linux AT-SPI) with a single consistent query/verb/walk model shared with the browser DOM. ## 6. Live native desktop access and consistent browser/desktop model (mandatory)

**Current:** `dev.domengine.desktop.DesktopTree` keeps the fixture backend and also attaches live. Windows uses UI Automation, macOS uses Accessibility, and Linux uses AT-SPI. `desktop attach --fixture` replays a recorded tree. `desktop attach --live` reads the platform tree. Live `click` and `type` call that platform or fail; they do not report success for a recorded tree. `desktop snapshot` writes one composite snapshot (screenshot, a11y-xml source, structure, paths, viewport map, and a pre-map). A fixture snapshot needs `--screenshot`. A live snapshot captures the window when `--screenshot` is omitted.

**Design:**
- Implement live native desktop access on the machine where the engine is running:
  - Windows: UI Automation (UIA)
  - macOS: Accessibility (AX)
  - Linux: AT-SPI
- Keep the fixture backend for tests and offline use. Live attach must work without a fixture against real desktop windows.
- Live click, type, and the other desktop verbs must actually act on the real UI, not only return ok on a recorded tree.
- CLI-first: every live desktop capability is on the CLI; GUI/MCP only forward. Logging checklist applies.
- Targeted tests for the live path where the OS allows, plus fixture tests so CI on a headless runner still proves the API. Do not weaken existing tests.
- Package this as part of the pickleball jar (same as the rest of the Java engine).

**Consistency rule (mandatory):**
- One query language, one verb set, and one walk/attach/resolve model for the browser DOM and for live native desktop UI on Windows (UIA), macOS (AX), and Linux (AT-SPI).
- Functionality, syntax, and logic should match as closely as the platforms allow. A step or CLI invocation that finds or acts on a browser element should look and behave the same way when the target is a desktop window or control, except where a real platform difference makes that impossible — and those exceptions must be named and justified in the design, not left implicit.
- Do not invent a second parallel API or a different selector dialect for desktop.
- Keep the fixture backend for tests. Live paths and the browser path share the same CLI surface and the same core logic.

Named platform exceptions (to be expanded in implementation if more arise):
- Accessibility tree shapes differ (role names, hierarchy depth, bounds units). Map to the shared model; document unmappable attributes.
- Input injection (click/type) may require elevated permissions or focus on some platforms; fail clearly rather than silently no-op.
- Shadow/pierce and frame contexts are browser-only; desktop has no equivalent and must not invent one.
- Image/OCR template matching may differ in precision; share the same CLI verb and document the backend difference.

Landed exceptions:
- Accessibility roles are mapped onto the shared query roles (`button`, `textbox`, `window`, and the others in `AtSpi.roleName` and `NativeDesktop.mapRole`). An AT-SPI role number that has no shared name stays `unknown`. The original number is `atspi-role`. UIA `ControlType.Text` maps to `label` because that control is static text, not an editable textbox. AX roles drop the `AX` prefix and then use the same map. There is no second selector dialect.
- A live walk stops at 12 levels or 500 nodes so attach cannot hang. The root then carries `walk-truncated=true`. The fixture path has no cap.
- Bounds are the platform's screen pixels (AT-SPI extents, UIA `BoundingRectangle`, AX position and size). A later coordinate click uses the bounds from the last attach or walk, so a control that moved can miss. The call still fails if the platform action and the input tool are both unavailable.
- Live click prefers AT-SPI `DoAction`, UIA `InvokePattern`, or AX `AXPress`. The coordinate fallback is `xdotool` on Linux and `SetCursorPos` plus `mouse_event` on Windows. Live type prefers AT-SPI `SetTextContents`, UIA `ValuePattern`, or AX `value`, then focus plus keystrokes. No session bus, a denied accessibility permission, or a missing tool throws. The command does not return `ok`.
- `frame`, `shadow`, and `pierce` are rejected on every desktop query, resolve, click, and type. Browser query still honors them. Desktop does not invent a shadow or frame tree.
- `image` and `ocr` are the same pipeline stage on both surfaces. OCR in this build fails with the same `ocr is not available` error on a browser file and on a desktop tree. Precision still depends on the captured bounds versus the browser viewport.
- `desktop close` ends the engine session. It does not close the user's window. Browser session close still stops a browser this engine launched.
- `desktop list` lists engine sessions, the same way `session list` lists browser sessions. It is not a second window catalog. Top-level windows are children of `attach --live`.
- AT-SPI `FRAME` maps to `window`. A desktop frame is a top-level window, not a browser frame.

## Live AT-SPI Fix-back 1

`desktop attach --live` on Linux calls the accessibility bus with `dbus-send --session` and `DBUS_SESSION_BUS_ADDRESS` set to that bus. `--address=` is not used. Role text comes from `GetRoleName` (`frame`, `button`, `desktop frame`, `menu`, `menu bar`, `menu item`, `page tab`, `panel`, `terminal`, `application`). The numeric `GetRole` value is `atspi-role` and is the fallback only when the name is empty. That fallback matches at-spi2-core 2.56. Button is 43, not 42 and not radio. Frame is 23, not 22. Panel is 39, not a textbox. A frame whose name contains the `--name` filter is a window and is selected. `role=button` matches a GetRoleName `button` node. No bus still throws `AT-SPI unavailable` and does not return `ok`.

## Backward-compatibility guarantees

- Existing Gherkin syntax unchanged.
- Cucumber step annotations stay single string literals.
- Dalton `db_edited` / extract / conflict behavior preserved.
- Existing Workbench collaboration features left alone unless a small non-breaking hook is required.
- Dalton-off remains file-only except new optional CLI writes.
- Selenium fallback (`pkb_composite=off`) works.
- Fixture desktop backend continues to work for tests/CI.
- No separate published `dom-engine` artifact.
- Engine API remains general-purpose (`dev.domengine`).

## Breaking-change list

(Empty.) All changes are additive. No reinterpretation of existing syntax, annotations, Dalton semantics, Selenium fallback, or fixture path.

## CLI-first and logging checklist

Every new capability reachable from the CLI. Workbench, MCP, and Gradle only forward. No business logic or SQLite/core calls in Workbench. Toggleable, per-entity, date-stamped, size-capped logging.

Checklist at end of every phase:

- [ ] Workbench action forwards to CLI
- [ ] MCP tool forwards to CLI
- [ ] Gradle task (if any) forwards to CLI
- [ ] Logging is toggleable, per-entity, date-stamped, and size-capped
- [ ] Existing tests still pass; no regressions in file-only / Dalton-off / Selenium fallback / fixture desktop
- [ ] For engine packaging: verification test fails if `dev.domengine` classes or sources missing from jar / sources jar
- [ ] For live desktop: fixture tests pass on headless CI; live tests run where OS allows and fail clearly otherwise
