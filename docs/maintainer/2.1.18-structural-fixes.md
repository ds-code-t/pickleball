## Phases

### Phase 1: Secrets redaction
- **Functionality**: Introduce shared `OutputFormatter` / `SecretRedactor` (e.g. in pickleball-workbench or shared). Apply to workspace-edit (warning), workspace-show, launch echo, all CLI/MCP outputs. Redact secret values; show stored `${protected:key}` as written. Never print plain secrets. Relevant: WorkbenchAgentCommands, Workspace, any print paths.
- **Docs**: Update consumer-agent-guide.md, workbench-agent-detail.md, release-notes.md. Sync packaged guidance (scripts/sync_consumer_guidance.py).
- **Tests**: FIRST write failing test reproducing consumer command that previously printed secret (e.g. workspace-show with secret key). Assert secret value absent, reference present. Then fix. No weaken.
- **CLI-first**: All workspace/show/edit/launch commands reachable via CLI, clear exit codes (0/1/2), ASCII-safe output.
- **Logging**: Actionable messages, no secrets, specific fix: hint (e.g. "secret redacted; use workspace-show for reference").
- **Exit**: All tests green; secret never appears in any captured output or log in the test suite or harness.

Assert stdout, exit codes, record.json contents, timings budget. Must run on Linux (existing CI) and new windows-latest GitHub Actions job using PowerShell and mvnw.cmd. Place scripts under scripts/ or maven-consumer-project.
- **Docs**: Document harness run in maintainer docs and release notes.
- **Tests**: Harness is the e2e test; failing assertions on bad output/exit. Add to CI.
- **CLI-first**: Entire session is CLI verbs.
- **Logging**: No secrets, actionable.
- **Exit**: Harness passes on Linux and the new Windows job.
