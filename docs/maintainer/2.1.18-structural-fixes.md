## Phases (EVERY PHASE MANDATORY)

### Phase 1 — Secrets redaction (N4)
**Functionality:** Introduce or extend a shared OutputFormatter / SecretRedactor. workspace-edit, workspace-show, launch echo, and all CLI/MCP output go through it. Never print secret values. Show the stored reference text as written (e.g. `${protected:key}`). Redact in logs too.
**Docs:** Update consumer-agent-guide.md, workbench-agent-detail.md, release-notes.md. Sync packaged guidance.
**Tests:** Write failing consumer-command test first (e.g. workspace-show or edit that would previously print a secret; assert value absent from stdout/stderr). Then fix. No weakening assertions.
**CLI-first checklist:** All workspace-* and launch commands reachable via CLI; clear exit codes; ASCII-safe output; secrets redacted.
**Logging checklist:** Actionable messages, no secrets, specific fix: hint (e.g. "secrets are redacted; stored reference shown").
**Exit criteria:** No secret value appears in any test output or log; redaction test green; docs/index/sync/contract pass.

### Phase 2 — Consumer-simulation E2E harness
**Functionality:** Build and install the artifact into maven-consumer-project. Script a full agent session through the real CLI: discover (uncompiled + compiled), isolate, execute-step (b64 and absolute --text-file on Windows), events, query errors/tail, rerun same run-id, confirm, finish. Assert stdout, exit codes, record.json, timings. Must run on Linux (existing CI) and new windows-latest GitHub Actions job using PowerShell and mvnw.cmd.
**Docs:** Document how to run the harness. Release notes.
**Tests:** The harness is the primary test. Failing assertions first if needed. Dan will test Windows later; CI must pass.
**CLI-first checklist:** Every capability in the session is CLI; documented; clear exit codes; ASCII.
**Logging checklist:** Actionable, no secrets, fix: hints.
**Exit criteria:** Linux harness green; Windows job green; timings within budget where claimed.

### Phase 3 — Golden tests
**Functionality:** Extract every documented command from guides, release notes, packaged guidance. Run them and compare to saved expected output (golden files).
**Docs:** Goldens live beside docs or in test resources. Update on intentional changes.
**Tests:** Goldens themselves. Fail if doc promises what code doesn't do.
**CLI-first / Logging:** Covered.
**Exit criteria:** All goldens pass; no doc drift.

### Phase 4 — Merge duplicate paths
**Functionality:** One argument parser so `--x=v` and `--x v` behave the same (fixes B10 space/absolute). One launcher for all entry points (openers, wrapper, fast path call it; unknown verb = exit 2, never GUI — fixes N11). One seed/warning function shared by hint and seed (compile-then-seed, fixes N1/B17, N8, N12). One event stream for anchor and execute-step (fixes S5). One output formatter with secret redaction and ASCII-safe output (fixes N5).
**Docs:** Update all affected. Sync.
**Tests:** Failing consumer-command tests first for each (e.g. absolute Windows --text-file, unknown verb, uncompiled seed, events after execute-step). Then implement.
**CLI-first / Logging:** One path, clear exits, ASCII, no secrets.
**Exit criteria:** No duplicate paths remain for these; all related tests green; harness proves them.

### Phase 5 — Unified run-lifecycle model
**Functionality:** One folder per attempt. Rerun reports only its own results (fixes N2). Run's own saved configuration snapshot wins over ambient config (fixes N3). Update why and stoppedAt on transitions (N9). Write snapshot even on launch failure.
**Docs:** Document the model.
**Tests:** Failing tests for rerun counts, confirm precedence, why update. Proven by harness.
**CLI-first / Logging:** Clear.
**Exit criteria:** Lifecycle tests and harness green; no stale data across reruns.

### Phase 6 — Process rules and release gate + O8
**Functionality:** Every fix starts from a failing test that reproduces the consumer's exact command. Never warn instead of fixing (seed-before-compile already in Phase 4). Release gate: blocked unless Linux harness, Windows job, golden tests and full suite all pass. Implement O8: pass/fail counts (and failed scenario names if cheap) in the summary line.
**Docs:** Process in AGENTS.md or maintainer. Release notes.
**Tests:** The gate itself; O8 assertion in harness/golden.
**CLI-first / Logging:** Summary is CLI output.
**Exit criteria:** Gate active; O8 present; before-all regression test runs through real Cucumber @BeforeAll hook (not direct method call).

### Phase 7 — Remaining valid items
**Functionality:** Finish B9 (failure fields on real path), B10 leftovers, B13/B14, S2 if measurable, status idle semantics, query tail, N6/N7/N13, B18 exit code under mvnw, remaining docs. All proven by harness/goldens.
**Docs / Tests / Checklists / Exit:** Same pattern. All green.
