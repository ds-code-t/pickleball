## CLI-first and logging checklist

- Every surface (MCP, open/ scripts, mvnw exec:java, java -cp, java -jar) is a thin forwarder to one launcher/command core.
- Agent-facing errors use the `error:` / `fix:` form. No Maven BUILD FAILURE stack for usage errors.
- Read `.pickleball/agent-log` before, after, and during long sessions. Keep terminal logging minimal.
- Use own run id. When a Workbench window is open, only one agent drives it; others stay headless.

## Phase 1: Hook source tracking for every key written by PKB_props.put in hooks

**Functionality:**
- Remove the `isRunVariableKey` filter from `PickleballRunner.noteHookWrite` and from the loop in `valueSources()`.
- Record every non-blank key written while a hook runs (globalTestProperties / globalTestDefaults).
- In `WorkspaceSeed.writeSources`, stop writing a literal `"default"` for keys not in the runner classification. Use the runner's `valueSources()` when present; fall back to `inferSource` (or equivalent) instead of hard-coding `"default"`.
- Every key written by a runner hook shows `source=hook` and is marked ` computed` in `workspace-show` text and `--json`, including non-`pkb_` keys, description, and secrets.
- Existing classification for properties, default, and cli/override remains correct. No change to normal `mvn test`.

**Docs:**
- Update `docs/release-notes.md` (2.1.18 section) with the source-tracking change.
- Update `docs/consumer-agent-guide.md` (within 5120 UTF-8 LF byte limit) and `docs/workbench-agent-detail.md` if needed.
- Update any workspace-show / source model documentation.
- Run guidance sync, index refresh, and agent contract verification.

**Tests:**
- Unit/consumer-sim test: a hook that does `PKB_props.put` for a plain key (e.g. `description`), a `pkb_` key, and a secret key next to `glue(...)`. All labeled `source=hook` / ` computed` in workspace-show text and `--json`.
- Existing source-model tests continue to pass with equal or stronger assertions. No weakened tests.

## Phase 2: Windows exit codes — document stock Apache mvn.cmd collapse and add stock-wrapper CI test

**Functionality:**
- No code change to exit-code logic (already correct on patched wrappers, java -cp/-jar, Linux mvnw).
- Document clearly that stock Apache `mvn.cmd` (any version, including 3.2.0 / 3.3.x) collapses any non-zero JVM exit to 1. Only the project's patched `mvnw.cmd` returns the real code (2 for usage errors).
- Windows scripts that need the exact code must match the `error:` line or use `java -cp`.

**Docs:**
- Update `docs/release-notes.md` and AGENT-GUIDE with the stock-vs-patched distinction and the recommendation.
- Update any exit-code tables.

**Tests:**
- Add a Windows CI test (in the existing agent-contract or consumer harness workflow) that runs a stock Maven Wrapper `mvnw.cmd` in a temp copy.
- Assert: non-zero exit, presence of the `error:` line and `fix:` hint in the failure output, and no Maven BUILD FAILURE stack.
- Do NOT assert exit code 2 (upstream forces 1).
- Existing patched-wrapper and java -cp tests continue to assert the real code 2.

## Phase 3: pkb_datapath and pkb_configpath accept comma-separated lists

**Functionality:**
- `pkb_datapath` and `pkb_configpath` accept comma-separated lists of paths, same as `pkb_features`, `pkb_componentpath`, `pkb_callpath`, and `pkb_glue`.
- Existing single-path values keep working unchanged (opt-in; a single path with no comma is unchanged).
- A comma always splits paths and never becomes part of a folder name.
- One shared splitter for all path settings (eliminate the current three `split(",")` copies).
- Define and implement list semantics: e.g. data paths: first match wins; config paths: merged in order. Document the exact semantics.

**Docs:**
- Update configuration docs, release notes, and AGENT-GUIDE.
- Phase 5 will add the summary table; this phase updates the individual path descriptions.

**Tests:**
- Single-path values continue to resolve exactly as before.
- Comma lists resolve correctly according to the documented semantics (first-match for data, merge for config).
- Edge cases: blank entries, trailing commas, paths containing spaces (if supported).
- Shared splitter is covered by the path tests. No duplicated split logic remains.

## Phase 4: Short RUN type aliases

**Functionality:**
- RUN step text (uppercase, case-sensitive as now) and `RunType` table cells (uppercased) accept the short aliases: `COMPONENT` / `COMPONENTS`, `CALL` / `CALLS`, `SERVICE` / `SERVICES`.
- Mapping: `COMPONENT`/`COMPONENTS` → `COMPONENT SCENARIO(S)`; `CALL`/`CALLS`/`SERVICE`/`SERVICES` → `SERVICE CALL(S)`.
- Singular forms error when more than one scenario matches; plural forms allow several (same as the full words).
- Full words keep working unchanged. Backward compatible.
- One shared mapping/lookup path; no per-alias special cases beyond the mapping table.

**Docs:**
- Update step documentation, release notes, and AGENT-GUIDE with the aliases and singular/plural rules.

**Tests:**
- RUN steps and RunType table cells with each alias succeed for the correct number of matches.
- Singular alias on multiple matches produces a clear `error:` / `fix:`.
- Full words continue to work. Case rules preserved.
- Consumer scenarios or internal checks cover both step text and table cells.
