## Root Cause Analysis

**#1 Help classpath**: `PickleballWorkbenchLauncher.main` treats `help` as an agent-core command and dispatches to `WorkbenchAgentCommands.run`. That class has a static `ObjectMapper` (Jackson). On a thin `java -jar` classpath (controller-only payload), class initialization throws `NoClassDefFoundError`. `WorkbenchCliHelp` is pure JDK and already owns the catalog. Cycle risk: `WorkbenchCliHelp.knownFlag` references `WorkbenchAgentCommands.MAJOR_FLAGS`.

**#2 Exit codes**: `exitProcess` / `keepExitCode` already does `System.exit` then `Runtime.halt` to defeat Maven exec:java rewrite. Some usage paths (split flags, certain parse failures) may still exit 1, or the Linux `mvnw` path may not preserve the status the same way Windows `mvnw.cmd` now does. All usage-error paths must hit `exitProcess(2)` and be proven through both launch styles.

**#3 / #4 Failure display**: `FailureRecord.fromThrowable` / `fromWorker` already skips wrapper messages such as `Step: '...' failed` and chooses the deepest non-wrapper cause. The `query errors` (and events) renderer still emits a step row that carries the wrapper message and a second failure row that carries the real cause. Merge: the step row must receive the `FailureRecord` message (and stackHead); suppress the duplicate empty/wrapper failure row so there is exactly one substantive row per failure.

**#5 Secret fix text**: `SecretRedactor.HINT` is the hardcoded string "secret redacted; the plain value is not printed. Read it from project properties, not from this command." Runner-set secrets (not present in any project property file) need the source named as the runner hook.

**#8 Computed marker**: `WorkspaceSeed.computedKeys` only marks keys that exist in project property files *and* differ from the file value. Hook-computed values (user, machine, Java vendor, time, …) that are not in any property file are unmarked. Extend marking (or add a source annotation) so users can see which keys need a reseed.

**#10 Quote stripping**: Maven `mvnw` / exec plugin strips inner double quotes from `--text`. Already partially documented; strengthen with a runtime warning that points at `--text-b64` / `--text-file` when the problem is detectable (or always when `--text` is used through a wrapper).

**#13 Guide size**: `docs/consumer-agent-guide.md` is 5116 bytes (LF, 78 lines). Previous contract check treated that as under 5120. Consumer measured 5806 bytes (likely CRLF export, a different packaged file, or extra content). Reconcile: choose one measurement (prefer LF of the source), update the contract check limit and comments, update release notes, and ensure the exported `AGENT-GUIDE.md` matches. Trim if necessary to stay under the agreed limit.

**#6 / #7 / #9**: Unification claimed these were fixed by `FailureRecord`, explicit idle status, and events outcome appending. They were untested in the retest. Add real tests (unit and/or consumer-sim) that assert non-null `message`/`stackHead` on execute-step failure JSON (including undefined steps), `elapsed-step-ms=idle` when idle, and `PASSED`/`FAILED` + `id=` on events lines. Fix any residual that the new tests expose.

## Phased Roadmap

### Phase 1: Help path isolation (#1)
- **Functionality**: In `PickleballWorkbenchLauncher.main`, detect the `help` command (and `--help`/`-h` aliases) early, before any load of `WorkbenchAgentCommands`. Dispatch directly to `WorkbenchCliHelp.catalog()` / `forTopic()` and exit 0 or 2. Break the `MAJOR_FLAGS` dependency so `WorkbenchCliHelp` does not force-load `WorkbenchAgentCommands` (move the flag list to a shared pure-JDK constants class or duplicate the minimal list in Help). Ensure `java -jar ... help` succeeds on a classpath that has no Jackson.
- **Docs**: Release notes and help text note that `help` is always available on the thin controller jar.
- **Tests**: Unit test that loading/executing help does not reference Jackson; integration-style assertion that the help path exits 0 without the NoClassDefFoundError.
- **Acceptance**: `java -jar ... help` exits 0 with the catalog; no Jackson required.

### Phase 2: Consistent usage exit 2 (#2)
- **Functionality**: Audit every usage-error path (command-line parse failures, unknown verb, split/`--tags` errors, missing required flags). All must call `exitProcess(2)`. Confirm the `System.exit` + `Runtime.halt` pair defeats Maven exec:java rewrite on both Linux and Windows. Ensure the Linux `mvnw` wrapper also returns the real JVM status for usage errors (Windows `mvnw.cmd` already does).
- **Docs**: Explicit exit-code table in release notes / agent guide: `java -jar`, `java -cp`, `mvnw exec:java`, `mvnw.cmd` all return 2 for usage errors.
- **Tests**: Consumer-sim or unit tests that launch via the documented `mvnw exec:java` style (and the Windows equivalent) for a split `--tags` and an unknown verb; assert exit code 2. Equal or stronger assertions.
- **Acceptance**: Usage errors exit 2 from every documented launch style on Linux and Windows.

### Phase 3: One row per failure with root cause (#3, #4)
- **Functionality**: In the `DiagnosticQuery` errors (and related events) rendering path, attach the `FailureRecord` message and stackHead to the step row. Suppress the separate empty or wrapper failure row so there is exactly one substantive row per failure. An undefined step shows the real "Failed to find PickleStepDefinitionMatch …" (or equivalent) on the step row.
- **Docs**: Document the single-row failure shape and that the step row carries the root cause.
- **Tests**: Assert that `query errors` for an undefined step produces exactly one row whose message is the root cause; no duplicate step+failure pair. Cover a defined-step failure as well.
- **Acceptance**: One row per failure; root-cause message visible on the step row.

### Phase 4: Actionable secret fix and computed markers (#5, #8)
- **Functionality**: Make the secret `fix:` text source-aware. When the secret is not present in any project property file, name the runner hook as the source; otherwise name the property file. Extend `WorkspaceSeed.computedKeys` (or add a sibling source tracker) so hook-computed values (user, machine, Java vendor, time, and other runner-supplied keys) are marked even when absent from property files. Show a `computed` marker or an explicit source on `workspace-show`.
- **Docs**: Update `workspace-show` examples and the agent guide to describe the source-aware fix and the computed marker.
- **Tests**: A runner-set secret prints a fix text that names the runner hook (not "project properties"). A hook-computed key that is not in a property file is marked computed / shows its source.
- **Acceptance**: Secret fix text is accurate; hook-computed keys are visibly marked.

### Phase 5: Quote stripping warning (#10)

- **Tests**: Simulate a stripped `--text` (or the warning condition) and assert the warning appears and names the alternatives.

## CLI-first and logging checklist

- `help` is a thin path that never loads heavy classes (Jackson, AgentCommands statics) on the controller jar.
- Every entry point (`java -jar`, `java -cp`, `mvnw exec:java`, `mvnw.cmd`, open scripts) is a thin forwarder that preserves the one exit-code policy (usage errors always exit 2).
- Outputs remain structured and concise: one `FailureRecord` shape, one row per failure, root-cause message on the step row, source-aware `fix:` texts, visible computed/source marks.
- Logging is actionable, contains no secrets, and never gives circular guidance.
- Agent-facing text is discoverable and non-confusing.
- No new verbs or features.
