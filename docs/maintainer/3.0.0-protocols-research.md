# 3.0.0 browser protocols research (trimmed)

Retrieved 2026-11-24. Primary sources are linked inline in each section. This is the maintainer copy of the research behind [the protocols roadmap](../roadmaps/3.0.0-protocols-roadmap.md); it covers Playwright, Selenium, WebDriver BiDi, Firefox and the Chrome DevTools Protocol beyond what D12–D14 added.

It does not repeat what `collabfix-launch/build-locked-followons.md` already gives the Build: D12 (Playwright default dependency, no browser downloads), D13 (attach to any running Chromium: channel, extension, CDP endpoint, Selenium CDP, discover, relaunch) and D14 (Playwright feature verbs: page/context, route/fulfill, HAR if no new dep, waits, tracing, video, screenshots, downloads/uploads, dialogs, emulation, tabs/frames, keyboard/mouse, raw `cdp`). This research covers what sits beyond or under those phases. The main gap: D14 is Playwright-only. It has no cross-protocol engine layer, no unified event stream, and no monitoring that also works on Selenium, BiDi or Firefox sessions.

Not present on 3.0.0: no `Runtime.exceptionThrown` row (page JS errors are not projected), no request/response bodies, no WebSocket/EventSource/WebTransport frames, no `Fetch`/BiDi intercept (mocking), no `Audits` issues, no `Security`/certificate events, no download/permission/geolocation control, no BiDi network/log/browsingContext events, no Selenium BiDi high-level handlers, no Performance/Tracing, no WebAuthn, no service-worker/storage inspection, no HAR, and no unified cross-protocol event schema persisted into the run's logs or store. Selenium's own CDP layer (`selenium-devtools-v1xx`) is on the classpath through selenium-java but is not used.

## 2. Primary-source findings (verified 2026-11-24)

### 2.1 Playwright (Java), Apache-2.0
Source: https://playwright.dev/java/docs/release-notes (latest **1.65**: Chromium 158, Firefox 159, WebKit 27.2, tested with Chrome 157 / Edge 156).
- 1.65: `Locator.normalize()` stringifies to Java code; `Page.getByRef()` maps refs from `Page.ariaSnapshot()` "ai" mode to locators; `CDPSession.send()` timeout option. Breaking: actions wait for non-inert, RFC 6265 cookie matching, proxy credentials are no longer sent to sites.
- 1.64: `Page.webmcp()`/`Frame.webmcp()` (experimental WebMCP page tools, needs `--enable-features=WebMCP`); screencast fps and CSS styling for action decorations.
- 1.63: `frameLocator()` without a selector searches all frames; `Locator.visible()`; aria and screen snapshots inside traces (`setAriaSnapshots`, `setScreenSnapshots`); OPFS in storage state; `onDialogClosed`.
- 1.62: WebP screenshots, `scroll: none`, `Locator.waitForFunction()`, `APIResponse.timing()`; headless clipboard isolated.
- 1.61: **WebAuthn `BrowserContext.credentials()` virtual authenticator (all browsers)**; **`Page.localStorage()`/`sessionStorage()` WebStorage API**; `connectOverCDP(artifactsDir)`; HAR and traces now include **WebSocket**.
- 1.60: **`Tracing.startHar()/stopHar()`**; **`Locator.drop()`** (external file/data drop); `ariaSnapshot(boxes)`; `Browser.onContext`; context-level mirrors of page events (download, frame*, pageClose...); **`connectOverCDP(noDefaults)`**, which leaves a user's daily browser undisturbed (no download/focus/media overrides); `WebError.location()`; `Locator.highlight(style)`, `Page.hideHighlight()`.
- 1.59: **`Page.screencast()`** (record, real-time frames, action annotations, overlays); `Page.ariaSnapshot()`, `depth`/`mode`; `Page.pickLocator()`; **`BrowserContext.setStorageState()`** (no new context); `Page.consoleMessages(filter)`/`pageErrors(filter)`/`clear*`; `ConsoleMessage.timestamp()`; `Request.existingResponse()`; `Response.httpVersion()`; `Tracing.start(live)`; **`Browser.bind()`**, which exposes a browser to playwright-cli and `@playwright/mcp`.
- 1.58: `connectOverCDP(isLocal)`. 1.57: Chrome for Testing builds; `page.accessibility()` removed; `Worker.onConsole`. 1.56: `Page.consoleMessages()`, `pageErrors()`, `requests()`. 1.54: partitioned cookies (`partitionKey`). 1.51: IndexedDB in storageState. 1.49: `matchesAriaSnapshot`. 1.48: **`routeWebSocket()`**, `requestGC()`. 1.45: **Clock API** (`install`, `pauseAt`, `fastForward`, `setFixedTime`, `runFor`). 1.37: `newCDPSession`/`newBrowserCDPSession`. HAR record/`routeFromHAR` have been available since about 1.23.
- Firefox/WebKit attach: Playwright drives its own patched Firefox and WebKit. There is no generic attach to a stock Firefox. Playwright's WebDriver BiDi support is described by Mozilla as "still a work in progress" (fxdx.dev, 2025-06). **Unverified:** whether a stable BiDi channel exists in 1.65.

### 2.2 Selenium 4.x (Java), Apache-2.0
Sources: https://github.com/SeleniumHQ/selenium/blob/trunk/java/CHANGELOG, https://www.selenium.dev/documentation/release_notes/, https://www.selenium.dev/documentation/webdriver/bidi/.
- Latest **4.54.0 (2026-11-23)**; 4.53 (2026-11-17). Each release supports only **three CDP versions** (4.54: v156–v158). This is why Selenium's CDP API is brittle and the project says "do not start new work on it" (Network guide).
- BiDi is enabled with `options.setCapability("webSocketUrl", true)`. All Java BiDi classes have been `@Beta` since 4.46. Low-level modules live in `org.openqa.selenium.bidi.module`: `Network` (`addIntercept`, `onBeforeRequestSent`, `onResponseStarted/Completed`, `onAuthRequired`, `onFetchError`, `continueRequest/Response`, `provideResponse`, `failRequest`, `continueWithAuth`, `setCacheBehavior`; since 4.18), `LogInspector`, `BrowsingContext`/`BrowsingContextInspector`, `Script`, `Input`, `Storage`, `Browser`, `Permission`. High-level: `((RemoteWebDriver) driver).script().addConsoleMessageHandler/addJavaScriptErrorHandler` (also DOM mutation handlers and `pin`), and `driver.network()` request/auth handlers.
- 4.53: Java BiDi code generator; accessibility snapshot atom. The Python and JS bindings return an a11y snapshot; Java "will follow later".
- pickleball pins `selenium-java` `[4.44,5.0)`, so every API above is reachable without a new dependency.

### 2.3 W3C WebDriver BiDi
Source: https://www.w3.org/TR/webdriver-bidi/ (**Working Draft, 13 November 2026**) and the editor's draft https://w3c.github.io/webdriver-bidi/. The modules in the current draft, extracted from the spec:
- `browser`: close, create/get/removeUserContext, getClientWindows, setClientWindowState, **setDownloadBehavior**
- `browsingContext`: activate, captureScreenshot, close, create, getTree, **handleUserPrompt**, **locateNodes** (css/xpath/innerText/**accessibility**/context locators), navigate, print, reload, setBypassCSP, **setViewport**, **startScreencast/stopScreencast**, traverseHistory. Events: contextCreated/Destroyed, domContentLoaded, load, **downloadWillBegin/downloadEnd**, fragmentNavigated, historyUpdated, navigationStarted/Committed/Aborted/Failed, userPromptOpened/Closed
- `emulation`: setForcedColorsModeThemeOverride, **setGeolocationOverride**, **setLocaleOverride**, setMediaFeaturesOverride, **setNetworkConditions**, setScreenOrientationOverride, setScreenSettingsOverride, setScriptingEnabled, setScrollbarTypeOverride, setTextLayoutModeOverride, **setTimezoneOverride**, setTouchOverride, **setUserAgentOverride**, setViewportMetaOverride
- `input`: performActions, releaseActions, **setFiles**, event **fileDialogOpened**
- `log`: entryAdded (console and JS errors with stack traces)
- `network`: **addDataCollector/getData/disownData/removeDataCollector** (request and response bodies), addIntercept/removeIntercept, continueRequest/Response/WithAuth, failRequest, provideResponse, setCacheBehavior, **setExtraHeaders**. Events: beforeRequestSent, responseStarted, responseCompleted, fetchError, authRequired
- `script`: addPreloadScript, callFunction, evaluate, getRealms, disown, removePreloadScript. Events: message (channels), realmCreated/Destroyed
- `session`: new/end/status/subscribe/unsubscribe (by id or attributes); `storage`: getCookies/setCookie/deleteCookies (partition-aware); `webExtension`: install/uninstall
- Extension modules defined in other specs (permissions `permissions.setPermission`, Web Bluetooth emulation) exist. **Not verified** per browser.

Browser support: Chrome/Edge 126+ and Firefox 117+ (web-features "limited availability"); Safari is not supported in stable. Safari Technology Preview has experimental BiDi behind `safari:experimentalWebSocketUrl` with no network, log or user-context support (Selenium PR #17729, 2026-07). Chrome implements BiDi through **chromium-bidi** (Apache-2.0, a BiDi-to-CDP mapper inside ChromeDriver, npm 160.0.8181-0). Its "BiDi+" extensions are `goog:cdp.sendCommand`, `goog:cdp.getSession`, `goog:cdp.resolveRealm` and `goog:browsingContext.getAccessibilityTree`, so **raw CDP is reachable from a BiDi session on Chrome**. **Not verified:** a per-command Chrome-vs-Firefox matrix (check https://wpt.fyi/results/webdriver/tests/bidi at build time; treat any command as optional with capability probing).

### 2.4 Firefox
- **CDP removed in Firefox 141** (fxdx.dev "CDP Retirement in Firefox" 2025-06-02; WebDriver Newsletter 141, 2025-07-22). BiDi is the only remote protocol (Firefox 140 ESR still has CDP via `remote.active-protocols`). The Remote Agent starts with `--remote-debugging-port`, which serves BiDi at `ws://host:port/session`. pickleball must never try CDP on Firefox.
- Puppeteer: BiDi default for Firefox since v23 (2024-08); Firefox-over-CDP removed in v24 (2025-01). For Chrome, Puppeteer still defaults to CDP and supports `protocol: 'webDriverBiDi'`.

### 2.5 Chrome DevTools Protocol
Sources: https://chromedevtools.github.io/devtools-protocol/ and `ChromeDevTools/devtools-protocol` json (0.0.1752859, BSD-3-Clause).
- **Policy change:** the CDP home page now says "Direct use of CDP by third-party applications is unsupported". Supported products are Chrome, DevTools, Chrome DevTools for agents, Lighthouse, Puppeteer and ChromeDriver. Tip-of-tree "can break at any time". This argues for BiDi first and CDP behind a capability probe, with experimental domains wrapped and degrading gracefully.
- Domains useful for pickleball, from the protocol json:
  - **Network**: webSocketCreated/FrameSent/FrameReceived/Closed, eventSourceMessageReceived, webTransport*, getResponseBody, searchInResponseBody, setBlockedURLs, setExtraHTTPHeaders, emulateNetworkConditionsByRule, overrideNetworkState, setCacheDisabled, getCertificate
  - **Fetch**: requestPaused, authRequired, fulfill/continue/fail, getResponseBody, takeResponseBodyAsStream
  - **Log**: entryAdded, including violations and interventions
  - **Runtime**: consoleAPICalled, **exceptionThrown**
  - **Audits**: issueAdded, covering mixed content, CORS, CSP, cookie, deprecation, low-text-contrast and form issues; also checkFormsIssues
  - **Security**: visibleSecurityStateChanged, certificateError, setIgnoreCertificateErrors
  - **Performance**: getMetrics; **PerformanceTimeline**: timelineEventAdded (LCP, layout shift); **Tracing**: start/end, plus the trace-event stream
  - **Emulation**: CPU throttling, sensors, idle, vision deficiency, timezone/locale/geolocation, virtual time, pressure
  - **Browser**: setPermission/resetPermissions, setDownloadBehavior, downloadWillBegin/Progress
  - **Page**: fileChooserOpened, javascriptDialogOpening/Closed, lifecycleEvent, frame*, screencast, printToPDF, windowOpen, backForwardCacheNotUsed
  - **Target**: setAutoAttach (workers, OOPIFs, service workers), targetCreated/Destroyed/Crashed
  - **ServiceWorker**, **Storage** (cookies, quota, IndexedDB/CacheStorage tracking, clearDataForOrigin), **DOMStorage**, **IndexedDB**, **CacheStorage**
  - **WebAuthn** (virtual authenticators), **FedCm**, **Preload** (speculation rules), **Autofill**, **DeviceAccess**, **BluetoothEmulation**, **Input**
  - **Debugger** (logpoints via setBreakpointByUrl with a condition), HeapProfiler, Profiler, **WebMCP**
- **Chrome 136+**: `--remote-debugging-port/pipe` is ignored on the **default** user-data-dir (developer.chrome.com/blog/remote-debugging-port, 2025-03-17; Chrome Enterprise notes). Chrome for Testing and Chromium are unaffected. **Chrome 144+**: `chrome://inspect/#remote-debugging` lets a user allow remote debugging of the running instance (Chrome DevTools MCP advanced-usage, `--autoConnect`). D13 already uses this; doctor and docs must state the 136 rule.
- Security: a CDP endpoint is full browser takeover, and attackers use CDP to steal cookies (SpecterOps 2026-08-13). pickleball must keep endpoints on localhost, never log cookies or bodies with secrets, and redact.

### 2.6 Other cutting-edge pieces
- **Chrome DevTools for agents / `chrome-devtools-mcp`** (Apache-2.0, npm 1.13.0, needs Node LTS, built on Puppeteer). Tools cover: input (incl. upload, dialog, click_at), pages, emulate, **performance trace with insights**, network list/get, **console with source-mapped stacks**, **set_logpoints**, **Lighthouse audit**, screencast, **heap snapshot analysis**, **mock_network**, extensions, WebMCP tools, PWA, WebAuthn. Connects via `--autoConnect` (Chrome 144+), `--browser-url` or `--wsEndpoint`. The perf tools may call the Google CrUX API unless `--no-performance-crux` is set, which is a privacy flag. It is useful as an opt-in **bridge**, not as a dependency; most of its value can be built natively over CDP.
- **Playwright MCP / playwright-cli** (Apache-2.0, Node): `Browser.bind()` (1.59) lets pickleball expose its own browser to these tools so that the user's other agents can drive the same session.
- **WebMCP** (experimental Chrome feature): pages register tools. Available through Playwright 1.64 `page.webmcp()` and CDP `WebMCP` domain.
- **axe-core** (MPL-2.0) for accessibility audits. Playwright removed `page.accessibility()` and points to Axe. It is a single JS file that could be injected. **MPL-2.0 is weak copyleft and needs a flag**, so make it opt-in and do not bundle it.
- **Lighthouse** (Apache-2.0, Node). Only via opt-in (`npx lighthouse` or chrome-devtools-mcp).

## 3. Gap list

The fallback order for every engine API is **Playwright (if this session is Playwright-attached) → BiDi (Firefox always; Chromium when a BiDi socket exists) → CDP (Chromium only) → Selenium classic → clear `error: unsupported on <browser>/<protocol>` + `fix:`**. The exception is monitoring on Firefox, which is BiDi only. Every verb is CLI first with an MCP forwarder, tier-tagged (D4 human/control), toggleable per-entity logging, and coverage-gate registered.

## 4. New dependencies / downloads (beyond Playwright)

- **Required: none.** Everything in A1–A20 and M1–M16 uses Selenium (already pinned), Playwright (D12) and pickleball's own JDK WebSocket CDP/BiDi clients.
- **Opt-in only (Dan t1122u: allowed if free and open source and flagged):**
  - axe-core, MPL-2.0. It is weak copyleft: keep it as an unmodified separate file, never shade it, and note it in THIRD-PARTY-NOTICES. Downloaded by an explicit `optional install axe` from npm/unpkg with SHA-512 integrity pinning.
  - Lighthouse, Apache-2.0. npm download, run with the Node inside Playwright's driver-bundle.
  - chrome-devtools-mcp, Apache-2.0. npm download, same Node.
  - Any npm package needs registry access. Flag the external-download implication in doctor.
- Nothing downloads at build, test or default runtime.
