## Result

Phase 0 used the existing stages. This Linux box did not run a Windows isolate, so the ~40s split is still `worker-spawn` → `jvm-main` → `classpath-scan` → `worker-ready` with no new durations.

Phase 1 makes `live/classes` one relative symlink to `base/classes` when `createSymbolicLink` works. Windows tries that, then `mklink /J`, then the per-file link-or-copy path. `copy-live` on 5259 files was 32 ms (wall 576 ms). A save under the link calls `detachContainingLiveClasses` and copies the tree before writing.

Phase 2 reads class-file headers in a preferred test-output directory (`target/test-classes`, `live/classes`, and the other preferred roots) and loads only the one concrete runner. Glue packages come from those paths. Jars stay on `ReflectionSupport`. 713 compiled classes scanned in 167 ms. The controller does not set `PKB_WORKBENCH_LIVE_READY`; an unset variable does not wait.

Phase 3 is the directory link above. It is the per-file Windows cut. No further shared-path change without a Windows isolate that is still over 60s.

Phase 4 records these numbers. Full Gradle, `consumer_sim`, `verify_agent_contract`, and Windows CI were not run.
