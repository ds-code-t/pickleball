## New issues

| # | Area | Problem | Suggested fix |
|---|------|---------|---------------|
| N1 | Seed order | When test classes are not yet compiled, discover seeds the workspace before Maven compiles. The seed falls back to `DefaultDynamicSuite`, so glue, configpath and other runner defaults are blank, and the run proceeds with the wrong configuration (the warning tells the user to reseed). `hint` gives the same blank result with no warning. | Compile test classes before seeding, or reseed automatically once compiled when the seed fell back. Have `hint` print the same warning. |
| N2 | Rerun packs | A rerun on the same run id adds to the existing diagnostic pack. 4 scenarios gave `summary scenarios=8 steps=36`, and `query errors` on the now-PASSED run returns the earlier attempt’s failures. | Give each attempt its own subfolder, or clear the pack on relaunch. Have query and the summary read the latest attempt by default. |
| N3 | Confirm filters | `confirm --run-id=<id> --name=X` merged in `pkb_tags` from the same agent’s discover of a different run, because the agent’s saved filters take priority over the run’s own. A failed discover does not update the run’s own snapshot. | When `--run-id` is given, use that run’s snapshot first. Write the snapshot even when the launch fails. |
| N4 | Secret display | Values classed as secret leak or mislead in several places: (a) the `workspace-edit` warning prints the old plain-text value; (b) `workspace-show` prints the plain-text value kept by B1; (c) the launch echo shows `$(protected:<key>)` in place of the reference actually stored, which hides the reference that failed. | Redact secret values in every display. Show the stored reference text as written. |
| N5 | Output encoding | `query` and `events` output includes `–` (U+2026), which a default Windows console shows as `♦`. | Use ASCII `...`, or force UTF-8 stdout in the launcher. |
| N6 | `--fields` | An unknown field name returns items as `{}` with exit 0. | Exit 2 and list the valid fields. |
| N7 | `query search` | `where` names an unrelated older run. `scanCapped:true` gives no hint how to widen or narrow the scan. | Set `where` to the source of the hits, and add `--run-id` scoping or a cap flag to the `fix` text. |
| N8 | `workspace-seed` | Each “literal secret in configs copy” warning prints twice, and so does the `pkb_<key> was set by the runner and is not in project properties` warning from B1. | Print each warning once. |
| N9 | Run record | A rerun keeps the first `why`, and the stop line repeats it. `finish` writes a stop line but leaves `stoppedAt` unchanged. | Update `why` on relaunch. Have `finish` update `stoppedAt`. |
| N10 | Fast path docs | The guide says `java -cp @classpath.cache` without giving the file’s location (`.pickleball/v/<version>/workbench/classpath.cache`). In PowerShell, `@` must be quoted (`"@path"`). | Print the full command after discover, and add a PowerShell example. |
| N11 | `.pickleball/open/` openers | Passing a non-one-shot verb to `pickleball-workbench.cmd` (seen with `discover --tags=…` and `session list`) silently opens the Workbench GUI (`pickleball-2.1.18.jar ui`) and blocks, instead of running the command or failing. An agent that follows the release note (“openers take the same path when you pass a one-shot verb”) cannot tell which verbs count. | Run `discover`, `confirm` and `session` through the launcher, or exit 2 with `error: / fix:` naming the supported verbs. Never open the GUI unless asked to. |
| N12 | `hint` | With compiled tests, `hint` showed the runner-set secret key with no `WARNING:` line, though the release notes say `hint` and `workspace-seed` both warn. Only the seed printed it. | Print the same warning from `hint`. |
| N13 | `workspace-show` | `computed` is appended to almost every key (for example `pkb_plugins`, `pkb_reportretention`, `pkb_features`), because few keys appear in property files. The keys that really change between runs (`user`, `machine`, `time`) do not stand out. | Mark only values a runner hook computed at seed time, or show the source (`hook`, `properties`, `default`) instead of one flag. |
