# 3.0.0-agent-fast design

**Status:** planning. Written 2026-11-18 against branch 3.0.0-agent-fast at e3ad4229. Implementation stays on this branch. The orchestrator merges to 3.0.0 after verification.

**Goal:** fix every confirmed bug from the 2026-11-18 consumer field report and make Workbench and all Pickleball dynamic functionality fast, responsive and cheap for AI agents in consumer projects. Starting anything is slow, every step feels sluggish, and injecting the prebuilt HTML components and collaborating with the human through them is worst of all.

## Locked decisions (orchestrator, 2026-11-18)

- No-op consumer glue: flag `noop:true` in step replies and warn in the run report by default; an opt-in setting may turn it into a failure. Never silently SUCCESS without the flag.
- Extend `start` to really launch/attach a live browser (fixing B3) rather than adding a sibling verb; `live-start` may exist only as a documented alias if it costs nothing.
- Fix CLI-to-live-worker forwarding (B2/P3) first; a controller `call` verb (P2) follows on the same path, no second transport.
- Pause lease: hold the live scenario while any client (MCP or CLI controller) is attached via heartbeat; document the lease and its timeout.
- Agent verbs use the snapshot-backed engine when available, with the documented fallback chain; scenario default behavior stays unchanged unless a change is proven safe by tests.
- `navigate to:` accepts `file:`, `data:` and `about:blank` in addition to http(s).
- Phase 1 performance targets in the evaluation are accepted as the starting targets.
- Desktop: the same target-agnostic API ships in this roadmap, backed by the existing desktop engine verbs; no separate desktop surface.
- Do not add Playwright, Chrome DevTools MCP, or any Node dependency; borrow designs only (ref-based compact snapshot, actionability checks, include-snapshot-on-action).

## Target-agnostic API

One higher-level API for browser/DOM and desktop targets. MCP, CLI and Workbench forward to the existing verb dispatcher (`domengine` / `AgentSurfaceRouter` / control bridge). No new layers. Extend existing verbs; do not invent a parallel catalog.

Target selector (one string):

```
target = browser:<session-id>[/tab:<id|title~|url~>][/frame:<path|name>]
       | browser:cdp=<ws/http url> | browser:auto
       | desktop:<pid|app~name>[/window:<title~>]
       | ref:<docVersion:handle>
```

Verbs (extend the existing set):

| Verb | Key params | Notes |
|------|------------|-------|
| attach | target, --auto | CDP join, BiDi, Selenium debuggerAddress, desktop attach --live |
| snap | mode=compact\|find\|diff\|full, within, budget | Compact ref view over existing composite snapshot producer |
| find | query, strict, rank, scrollSearch | pre-map → CDP/BiDi → Selenium → desktop |
| act | kind, query\|ref\|xy, value, snap=diff | Actionability check then fallback chain |
| wait | condition, timeout | watcher awaitPromise → events → poll |
| watch | kinds, scope, duration | push events from watcher |
| eval | expr, world=pkb\|main | isolated or main |
| ui | op list (existing ui-apply), anchor | placements, panel, ask, chat |
| explain | query\|ref | actionability report |
| capture | screenshot, clip, --out | no base64 in default reply |

Existing agent verbs (`panel-open`, `label`, `chat-send`, etc.) are forwarded to the live worker when a session exists.

## Tier table

| Tier | Role | Examples |
|------|------|----------|
| ENGINE | Universal, stable, reliable; used by any scenario; automatic fallback | B1 guard in pkb-runtime.js, lease/quit on restart, continuous OOPIF auto-attach in existing CDP client, push channel fix (binding with executionContextName), event-driven waits via existing MutationObserver + awaitPromise, frame restore always, closed-shadow via DOM.resolveNode, actionability in act path, snapshot producer |
| AGENT | Finer or experimental; one-call functions for agents, especially human collaboration and DOM probing | compact reply formats, one-call wrappers (act/find-and-act, wait-for, form-fill, ask-and-wait, confirm, status, pin, toast, checklist), doctor, selftest ui --cpu, --hold, experimental switches, session-scoped chat cursor |

## Fallback chains

Automatic, logged once per run and reason. Existing chains, not new ones:

1. **Locate**: pre-map hit → live query (CDP DOM pierce / BiDi locateNodes) → AX-name match → Selenium findElement (current frame then switch) → desktop UIA/AX/AT-SPI.
2. **Act**: CDP Input.dispatch* (after actionability) → BiDi input.performActions → Selenium Actions → JS synthetic click in isolated world (marked synthetic) → desktop OS input.
3. **Wait**: watcher awaitPromise → protocol events (Network/Page/BiDi) → bounded LeanWaits poll.
4. **Inject**: CDP isolated-world preload + binding → BiDi sandbox + channel → Selenium executeScript (re-inject on navigation, logged).
5. **Snapshot**: CDP producer → BiDi → Selenium page-source → desktop producer. Skipped fields go in warnings[].

## Push-channel and watcher design

- Fix the existing binding: `Runtime.addBinding` with `executionContextName:"pkb-surface"`. Have pkb-runtime.js and the watcher call it. `ui-poll` keeps its long-poll API but wakes instantly from the pushed queue. `drainIsolated` remains the fallback.
- Extend the existing isolated-world runtime (`pkb-runtime.js`) with a lightweight watcher (docVersion, lastMutationTs, dirty-subtree, coalesced per rAF). Engine waits with one `Runtime.evaluate{awaitPromise}` / BiDi `script.callFunction{awaitPromise}` that resolves on condition instead of FluentWait polling.
- Coverage: MutationObserver, network inflight (CDP/BiDi + injected counters), busy/load-mask (`aria-busy`, progressbar, elementsFromPoint overlay, inert), navigation hooks, Resize/IntersectionObserver, capture-phase user-action events (ref + role/name), top-layer/dialog.
- No new module. Everything stays inside the existing runtime and CDP client.

## Frame and shadow strategy

- Same-origin / nested: `contentDocument` + `DOM.getDocument{pierce}` + DOMSnapshot. Snapshot carries `frame_path`.
- Cross-origin OOPIF: continuous `Target.setAutoAttach{autoAttach:true, flatten:true, waitForDebuggerOnStart:true, filter:[{type:"iframe"}]}` inside the existing CDP client. On `Target.attachedToTarget` apply preload/binding/watcher, then `Runtime.runIfWaitingForDebugger`. FrameId→sessionId map. Match by frameId, not URL.
- Dynamic frames: auto-attach + `Page.frameAttached`. Watcher bumps version.
- about:blank / srcdoc: on `executionContextCreated` with no pkb world, `Page.createIsolatedWorld` + evaluate runtime.
- Selenium fallback: `switchTo().frame` last resort.
- Open shadow: pierce. Closed: `DOM.resolveNode` in pkb world gives a handle. Optional AGENT `--patch-attach-shadow` (off by default, detectable). Listeners use composedPath. Frame and shadow_path in every reply. Inspect walks the same contexts steps do, or reports that it does not.

## Snapshot integration

Compact ref-based view (`- button "Save" [ref=e12]`) over the existing composite snapshot producer. Refs are `docVersion:handle`. Every `act` / `wait` can return `snap=diff`. Same call for browser and desktop. Auto-snapshot before/after macros where practical. No second snapshot system. Full tree never goes into the model context by default.

## Compact reply formats

Default replies are compact (≤2 KiB for inspect/page/step). Full artifacts stay on disk. `screenshot --out=<file>` (no inline base64). Timing fields on every reply. `noop:true` on empty glue. `visible` / `hidden` / `lost` / `overlaps` on placements. `frame` (or desktop window) on every reply. `browser_lost` / session-ended events.

## Prebuilt components and one-call functions

Chosen (thin wrappers over existing verbs; no new catalog):

- Components (AGENT, ui-apply ops or thin): confirm (highlight + Yes/No), status (persistent waiting), pin (comment thread), toast (transient), checklist (multi-step overlay). Desktop uses native/popup backend.
- One-call functions: live-start (extend start), act (find + act + wait), form-fill, wait-for, ask-and-wait / confirm, snapshot / snapshot-diff, doctor, selftest ui --cpu.

## What is deliberately NOT done

- No Playwright, Chrome DevTools MCP, or Node dependency. Borrow designs only.
- No new layers or parallel catalogs. Extend existing dispatcher, runtime, CDP client, snapshot producer.
- No second snapshot system or full page replay/restore.
- No main-world shadow patch by default.
- No making `pkb_composite=on` the default.
- No minimap, cheatsheet, split-compare, or other backlog items unless a phase lands them early.
- No forced mutation or artificial scoring (philosophy from other work, not applicable here).

All phases in the roadmap are mandatory and must be completed in full. Nothing is optional or deferred.
