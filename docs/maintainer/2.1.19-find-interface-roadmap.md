## Phase 2: Dual mode (human-viewable default vs lower-level opt-in per query) with mandatory human-limitation labels
**Functionality:**
- Mode parameter on the same query path (not a parallel API, not session-sticky). Human-viewable / human-interactive is the default for interact (click, type, "what is on screen"): displayed, intersects the visual viewport, non-zero size, topmost/interactable. MUST exclude nodes that are isDisplayed but outside the current visual viewport. Humans do not see outside the viewport.
- Lower-level view/interact: source, hidden, invisible, off-viewport, zero-size, aria-hidden, clipped, occluded, pointer-events:none, and similar. Same path, relaxed filter. Opt-in PER QUERY.
- Human-limitation labels mandatory on every lower-level result AND action. Both machine-readable reason codes and a short sentence. Codes include human_could_not_see / human_could_not_click / human_could_not_follow plus reasons such as off_visual_viewport, display_none, visibility_hidden, opacity_zero, aria_hidden, zero_size, clipped, occluded, pointer_events_none, source_only. Example: "acted on node X; a person could not have seen or clicked it because it is scrolled out of the visual viewport and has opacity:0." Extra power must never be confused with a human-replicable path.
- Interact defaults to human-visible mode. Agent must opt in per action to act on a non-human-visible target, and that action still carries the labels.
- Inspect/find in human mode returns only human-visible nodes. Inspect/find in lower-level mode may return the extra layer, and every node is labeled. Page source remains a separately labeled read (offline --html or an explicit source dump).
- Occlusion / clipping / corner interactability: consume mapping-geometry Phase 3 hit_grid / hit_at / topmost when those capabilities exist; until then, capability-gate a coarser fallback (intersects visual viewport and not display:none / visibility:hidden). Do not block this roadmap on mapping Phase 3 being finished.
- Through the same shared path. Engine stays general-purpose.

**Docs:** Update this roadmap. Document the mode parameter, default, labels, and codes in dynamic-control-api.md, workbench docs, and agent guidance.

**Tests:**
- Unit / parity: human mode excludes off-viewport isDisplayed nodes; lower-level includes them with labels. Opt-in is per query.
- Consumer-shaped repro: agent query in human mode misses scrolled-out node; same query in lower-level mode returns it with off_visual_viewport + opacity_zero labels and sentence.
- Action on lower-level target carries labels; human default rejects or requires explicit opt-in.
- Measured: no session sticky state.

**CLI-first checklist:** Mode flag and labels reachable from composite CLI.

**Logging checklist:** Log mode used, labels applied, and reason codes. Toggleable.

**Regression risk:** Medium (visibility filter changes for controller path). Gherkin isDisplayed / displayed contracts locked by parity tests. Existing Gherkin behavior unchanged. Launch modes covered.

## Phase 3: Visual relative location (left-of / right-of / above / below / near) via Geometry view
**Functionality:**
- Visual relative location is pure visual distance using the Geometry view — not document or tree order. Consume all five Geometry spaces through that one view: use visual-viewport-relative when asking what a person sees; nearest-scrollport-relative when the reference lives inside a scroller; document_css_px as the global space; layout-viewport-relative and frame-document-relative as already planned. Ties use existing paint order / top-layer / hit_grid / topmost sampling. Overflow uses nearest-scrollport. Closed-shadow and cross-origin fail closed as today.
- If current engine near=/below= still has tree-order residue, make visual distance the contract for these exposed relative stages. Do not invent a parallel geometry system; if mapping-geometry has not landed yet, capability-gate and fall back without fake quads.
- Exposed on the shared query object path (near=, below=, left-of, right-of, above, etc. as engine stages or expressions). Gherkin after/before stay document order.
- Engine: general-purpose visual distance stages or helpers if needed (working branch + PR). Update domc-asks.md.

**Docs:** Update this roadmap. Document visual vs document-order distinction. Note Geometry dependency and capability gate.

**Tests:**

- Consumer-shaped repro: two elements side-by-side; visual near/right-of selects the visual neighbor, not the document-order one.

## Phase 4: Ranked candidates with explain, image reconcile, and fast surfing batch
**Functionality:**
- For agent / Workbench / direct queries, return ranked candidates with explain / why-matched (engine scores and --explain). Existing Gherkin Ambiguous / first / nth / nesting / within behavior stays locked by tests.
- Image reconcile priority: bind to a DOM / CompositeNode first when the match can promote (engine --promote-visual). If no node can be bound (desktop/screenshot-only, or closed-shadow / cross-origin fail-closed), keep a labeled visual-only hit. Never pretend a visual hit is a DOM node.
- Fast surfing, in scope: one query + mode + optional limit that returns a rich labeled batch (text, geometry when available, visibility labels) and stable node handles for follow-up reads/acts without re-walking the tree. Out of scope for this roadmap: a batch action primitive ("click these N links and report which succeeded"). Each act stays a single labeled call through the human-visible default.
- Through the same shared path. Engine general-purpose (scores, --explain, --promote-visual, --count-only already exist; extend as needed on working branch + PR).

**Docs:** Update this roadmap. Document ranked explain, image promote vs visual-only, and fast surfing batch with handles.

**Tests:**
- Unit / parity: ranked results include scores and --explain; image promote binds node when possible, else labeled visual-only.
- Consumer-shaped repro: image= match promotes to node; desktop-only stays visual-only with label. Fast surfing batch returns labeled handles usable for a follow-up single act.
- Gherkin ambiguous/nth locked.

**CLI-first checklist:** --explain, promote-visual, and batch/limit reachable from CLI.

**Logging checklist:** Log scores, explain reasons, promote outcome, and handle issuance.

**Regression risk:** Low. Additive. Existing Gherkin selection locked by tests.
