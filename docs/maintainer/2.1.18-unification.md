## Current Duplicated Paths (call graph level, file:class)

### 1. Diagnostic Attempt Store
Writers:
- tools.dscode.common.reporting.diagnostic.DiagnosticReporter (defaults runsRoot to reports/diagnostic-runs/<runId>/; writes events.jsonl, summary.json, run-index.json, packs)
- tools.dscode.launcher.WorkbenchRunReports (publishes workbench/summary.json, console/; currentRunScenarioDirs prefers private .pickleball/runs/<id>/diagnostic then falls back to reports/diagnostic-runs/<id>)
- tools.dscode.launcher.WorkbenchAgentCommands / AgentCoordination / LastDiscoverSnapshot (snapshots, catalog)

Readers:
- WorkbenchRunReports (summary counts, status)
- DiagnosticQuery (in pickleball-control-protocol or launcher; query, events, errors, tail, search)
- DiagnosticCli (rebuild, compare)
- WorkbenchSessionCommands (events)

Dual paths: shared reports/diagnostic-runs/<run-id>/ (accumulates across attempts) vs private .pickleball/runs/<id>/diagnostic + attempts/<n>/diagnostic (intended isolation not used by all readers). B1 evidence: piles onto reports/, counts accumulate, query sees old rows on PASSED run.

Target: One current-attempt store at .pickleball/runs/<run-id>/diagnostic. On relaunch, atomic archive of previous diagnostic/ to attempts/<n>/diagnostic. All writers and readers open only the current attempt. Delete or redirect shared reports/diagnostic-runs path for Workbench flows.

### 2. Failure Record
Sources:
- Worker event recorder (ControlBridgeEventRecorder or equivalent; records step/failure events)
- Execute-step worker path (WorkbenchSessionCommands / nested worker)

Transformers (lossy):
- DiagnosticQuery (fills/nulls phrase/message/stackHead, inserts empty failure rows, drops real cause)
- WorkbenchSessionCommands (execute-step JSON fields null or partial)
- WorkbenchRunReports (summary extraction from messages)

Target: One structured Failure record (phrase, message, cause chain, stackHead, step text) written once at the source. All consumers read it unchanged. No per-surface munging, no empty duplicates, real cause preserved for defined and undefined steps.

### 3. Launcher / Argument Parser / Exit Codes
Core:
- tools.dscode.launcher.PickleballWorkbenchLauncher.main (parses via WorkbenchCommandLine, dispatches agent/session or forks controller)
- tools.dscode.launcher.WorkbenchCommandLine (parse, isAgentCoreCommand, isSessionClientCommand)

Thin / residual:
- WorkbenchOneShotLaunch (classpath.cache fast path)
- .pickleball/open/*.sh/.cmd/.ps1 (unknown verb previously silent GUI; now claimed fixed)
- MCP tools
- mvnw exec:java / gradle wrappers (exit code remapping observed in B9)

Target: One launcher/command dispatcher and one argument parser. All entry points are thin forwarders. Consistent exit codes from every entry point (usage errors always exit 2).

### 4. Structured Outputs / Renderer
Multiple free-text formatters:
- WorkbenchRunReports.compact (comma-joined failedScenarios, string status)
- OutputFormatter (ASCII, redaction; mentioned in notes)
- Query/events pages, fix: texts (circular or non-actionable)

Target: Structured outputs (JSON arrays for lists such as failedScenarios, explicit idle/running status, non-circular actionable fix text) produced by one renderer.

### 5. Seed-to-Launch Path
Paths:
- WorkspaceSeed / WorkbenchAgentCommands.workspace-seed / hint
- LastDiscoverSnapshot (retained profile)
- DiagnosticCli.resolve-runvars / discover-hint
- PKB_props / globalTestProperties()/globalTestDefaults() hooks

Target: One seed-to-launch path. Run-var resolution runs once (including run-var files and globalTestProperties()/globalTestDefaults() hooks). The captured copy, possibly edited, is the final config with no hooks reapplying. Shared warning function for uncompiled/fallback. No form that the warning says will fail is ever written.

## Target Architecture (one list per concern)

- **Diagnostic Store**: Single current attempt at `.pickleball/runs/<run-id>/diagnostic`. Atomic move of previous to `attempts/<n>/diagnostic` on relaunch. Writer and every reader use only current. Shared reports/diagnostic-runs path unused by Workbench.
- **Failure**: Single immutable Failure object written at event source. Readers (execute-step JSON, events, query, summary) consume it unchanged.
- **Launcher**: PickleballWorkbenchLauncher is the sole dispatcher. WorkbenchCommandLine is the sole parser. Openers, MCP, wrappers, java -cp are thin forwarders that preserve exit codes.
- **Outputs**: One renderer produces structured JSON (arrays, explicit status) and non-circular fix text. ASCII-safe, redacted.
- **Seed**: One resolution function. Captured copy is final. Hint and seed share the same path and warning.

## What Gets Deleted/Merged

- Dual-path logic in WorkbenchRunReports.currentRunScenarioDirs and DiagnosticQuery loaders.
- Per-surface failure munging in DiagnosticQuery, SessionCommands, RunReports.
- Residual exit-code special cases in wrappers and openers.
- Free-text list formatters (comma-join, string status) in favor of one structured renderer.
- Duplicate seed/warning functions (hint vs seed).
- Any residual GUI-fallback for unknown verbs.
