# Pickleball 2.1.18 report-6 roadmap

Branch: **2.1.18** @ `a4b87f29`. Features 18–23 out of scope. Never touch master.

## Dan's philosophy (mandatory)
Every recent fix broke something else. Fixes must be surgical or holistic: fix by simplicity and **ONE shared code path**, not by adding parallel special cases. Two paths that should behave the same (direct/warm vs wrapper/sequential vs `java -cp` vs `isolate`) must share the code that decides the behavior. AI-agent confusion (misleading output, contradicting docs) is a bug.

## Testing rule (time-efficient, mandatory)
- Between phases run ONLY the new reproducing tests and directly targeted tests. Parity tests are written but run only as targeted tests.
- Do NOT run the full regression until all implementation is pushed.
- After the last implementation push, Build must **STOP and report the head commit** before running the final full regression, so Dan can test locally in parallel. Build runs the final full regression (JDK 21 `./gradlew --rerun-tasks` all modules, `scripts/consumer_sim.py --publish`, `scripts/verify_agent_contract.py`) only when told to continue.
- Before every push run `python3 scripts/sync_consumer_guidance.py` (regenerates `docs/agent/repository-index.md` and `index.txt`; a stale index fails the Windows CI job).
- Push and pull-request CI is Windows only. Linux is verified locally on the maintainer box with JDK 21. macOS testing is tech debt (`docs/maintainer/tech-debt.md`).
- No failing, skipped or weakened tests. Docs are updated with every behavior change.

## Root-cause analysis (verified in code @ a4b87f29)

### A. Direct/warm vs wrapper output contract (bugs 2, 3, 17; touches 14)
**Root cause:** Separate output paths. Direct/warm has its own code instead of the shared run-report filter.
- `WorkbenchSpeed.java` `tryDirect`/`warmRun` (~208-214): prints the whole captured worker stream raw to `out` (no `# pkb-console` filter; marker is `WorkbenchConsoleTap.java:23`), so bug 2. Prints `error: warm launch exited N` + `fix: rerun with -Dpkb_workbench_speed=sequential` for ANY nonzero exit, including ordinary test failures (bug 3).
- Wrapper: `WorkbenchAgentCommands.java` (~1785-1805) passes `quiet ? null : out` to `WorkbenchRunReports.publish`, so `--quiet` drops the `summary` line (bug 17). `WorkbenchRunReports.java` (~100-117) builds the summary.
**Fix direction:** One output function (filter console markers, emit summary always, quiet drops all else) used by both direct and wrapper. Distinguish launch failure (no run record/summary) from test failure (summary FAILED) in one place.
**Regression risk:** All discover/confirm/isolate/direct/sequential/`java -cp` paths. Callers: launch entry points, timing, session. Locking tests: new parity tests required; existing `WorkbenchRunReportsTest`, `Workbench*Test`.

### B. Resolve cache hit vs miss divergence (bug 1)
**Root cause:** Cache hit and miss take different paths for runner secrets and warnings.
- `WorkspaceSeed.java` (~63-73): on `Workspace.cacheHit` calls `Workspace.restoreCache` and returns, skipping `writeCaptured` logic (~94-132: runner-secret keep ~122-123 and warnings ~126-130, rule at ~301-320). Miss path stores at ~89.
- `Workspace.java` (`cacheKey`/`storeCache`/`restoreCache` ~573-625): plain copy, no format/build version in the key, so old-build entries holding `${protected:<key>}` are reused.
**Fix direction:** Seed hit and miss go through one post-step (keep runner secrets + warnings); add a cache format/build version to `cacheKey` so older entries are invalidated.
**Regression risk:** All workspace-seed/discover/confirm/isolate on cache hit. Callers: seed, launch, resolve. Locking tests: `WorkspaceSeedTest.runnerComputedSecretWithoutAPropertySourceStaysALiteralAndWarns` (and related); new hit/miss parity.

### C. Warm JVM / session lifecycle state (bugs 6, 7)
**Root cause:** Warm JVM does not exit when its state file disappears; status reports running before any step.
- `WorkbenchWarmMain.java` (~92-110) `exitDue`/`watch`: idle exit depends on `busy`/`lastUsedNanos`; parent pid refreshed from the file (~106-107), so an orphan whose state was deleted is never found. `WorkbenchSpeed.java` (~226-228) `stopStale` and `WorkbenchApplication.java` (~399-402) `releaseWarm` rely on `WarmProcess.release(state)`, so `stop` can't kill by PID when the file is gone.
- Bug 7: `WorkbenchSessionCommands.java` (~1404-1410) `formatReport` trusts `Timing.stepRunning` (~1447-1454); the source (session `/health` state) reports running before the first step. Fix at the source: running only when a command is in flight.
**Fix direction:** Warm JVM enforces its own idle timeout and exits when its state file disappears. Make `stop` kill by PID even when the state file is missing. Status idle whenever no command is in flight.
**Regression risk:** Warm process lifecycle, stop, isolate restart, session status. Locking tests: `VersionSwitchTest`, warm process tests; new orphan/idle/status tests.

### D. Step text / parser input (bugs 5, 8)
**Root cause:** Quote-strip heuristic too narrow; phrase operations assume non-null elements.
- Bug 8: `WorkbenchSessionCommands.java` (~1911-1927) `quoteStripWarning` heuristic only matches `the|a|an X button|link|field...`; `*, save E.` passes silently. Fix: under exec:java/mvnw always suggest `--text-b64` when text has no quotes (one rule).
- Bug 5: NPE from a null `ElementMatch` in phrase operations, e.g. `ActionOperations.java` (~96-127 SAVE; `:127` `valueElement.getValues()`), `PhraseData.java` (~498-503), `AssertionOperations.java` (~143+). Fix: validate required elements once where the phrase is built and throw a syntax error naming the missing part.
**Fix direction:** One validation at phrase construction; one quote-strip rule.
**Regression risk:** All step execution (execute-step, isolate, direct). Locking tests: existing step/phrase tests; new for NPE->syntax error and quote warning.

### E. validate (bug 4)
**Root cause:** Validate uses its own incomplete matcher instead of the runner's.
- `WorkbenchValidate.java` (~100-123) matches raw step text with regex against a `glue` list (`countGlue`), with no Outline `<placeholder>` expansion, no Pickleball core/dynamic step matchers, and no progress or cap on a whole-suite run.
**Fix direction:** Reuse the same glue/step-matching code the runner uses (one matcher), expand Outline rows, add progress and a cap/page.
**Regression risk:** validate command, feature index selection. Locking tests: new for false positives (Outline, core steps) and whole-suite progress/cap; existing feature index tests.

### F. Diagnostic query (bug 9)
**Root cause:** Capped flag computed on whole-project scan even for scoped `--run-id`.
- `DiagnosticQuery.java` (~1036-1046) `logs()` sets `capped = lines.size() > SCAN_LINES` on the whole project `agent-log` even for a scoped `--run-id`; also `appendWorkerLogs` (~1063) and output (~225-229).
**Fix direction:** Set capped only when the scoped scan hit the limit.
**Regression risk:** query search, diagnostics. Locking tests: new scoped scanCapped test; existing DiagnosticQuery tests.

### G. Failure records (usability 14, 15, 16)
**Root cause:** FailureRecord and reports embed too much or too little structured data.
- 14: `WorkbenchSessionActions.java` (~593-601) puts the full `stackTrace` in `failure.cause`; copied again at `WorkbenchSessionCommands.java` (~1166-1179).
- 16: `stackHead` from `FailureRecord.java` (~20,66-112) and `DiagnosticQuery.java` (~837-892) takes the first line (exception message). Fix once in `FailureRecord`: first frame outside Pickleball/Cucumber; `cause` = top `Caused by:` line; full chain to a file / `--verbose`.
- 15: `WorkbenchRunReports.java` (~100-117) `failedScenarios` is names only; add `path:line` and example row.
**Fix direction:** One place in FailureRecord for stackHead/cause; reports add path/line/example.
**Regression risk:** execute-step failure JSON, summary, diagnostics. Locking tests: existing FailureRecord/execute-step tests; strengthen for new shape.

### H. Docs (bug 10)
**Root cause:** Contradicting statements on `mvnw.cmd` exit codes.
- Release notes lines 12 and 27 vs line 6 and `workbench-agent-detail.md` on `mvnw.cmd` exit codes. Make all say stock `mvnw.cmd` returns 1; scripts use `java -cp` or match `error:`; drop "patched mvnw.cmd" wording.
**Fix direction:** Align all docs. Docs only.
**Regression risk:** None (docs). Locking: agent contract verification.

### I. Version tree (bug 11, unconfirmed)
**Root cause:** Possible external deletion; current version must never be swept.
- Only deletion path found is `AgentCoordination.java` (~952+) `sweepVersions` (doc says not called from export). Current version must never be swept; missing `.last-used` treated as now. Check callers and `.last-used` handling.
**Fix direction:** Launch-time detection of missing `v/<current>/` that prints `run export-guidance`, and record the deleting command if possible.
**Regression risk:** version switch, export, gc. Locking tests: `VersionSwitchTest`.

### Speed 12, 13
**Root cause:** First isolate does not reuse discover classpath cache; stage-overlap log is after compile; compile may run twice.
- First `isolate` stage `starting / Maven resolve or feature index` and the `stage-overlap index+compile` timing log (`WorkbenchLaunchTiming`). Reuse the discover classpath cache (`ClasspathCache`, `WorkbenchSpeed.java` ~168-181) for first isolate, split the stage in timing, log index start/end, raise cold-start default timeout, compile once.
**Fix direction:** Reuse cache, better timing, single compile.
**Regression risk:** isolate cold start, timing, launch. Locking tests: existing speed/timing tests; new for cache reuse and timing.

## Phased roadmap
Every phase: write the reproducing test FIRST (must fail before the fix) + cross-path parity test (same input through direct/warm vs sequential vs `java -cp` vs isolate where the bug applies, asserting identical stdout contract / exit / summary / warnings). Then implement the one shared path. Update docs. Run only new + targeted tests. Sync index before push.

### Phase 1: Shared output contract (A: bugs 2, 3, 17)
- Repro tests: direct path echoes `# pkb-console` lines; test failure prints `error: warm launch exited` + fix; `--quiet` drops summary.
- Parity: same run via direct/warm, sequential, `java -cp`, isolate — identical filtered stdout, summary always present (even under quiet), no error/fix on ordinary FAILED.
- Targeted: `WorkbenchRunReportsTest`, relevant launcher tests.
- Docs: workbench-agent-detail.md, release notes on stdout/quiet/summary/exit.

### Phase 2: Cache hit/miss parity + version (B: bug 1)
- Repro test: second seed / cache hit loses runner-secret value and warning; old-build cache entry reused.
- Parity: hit vs miss produce identical kept secrets + warnings.
- Targeted: `WorkspaceSeedTest`.
- Docs: any cache/seed docs.

### Phase 3: Warm JVM lifecycle + status (C: bugs 6, 7)
- Repro tests: orphan warm JVM survives after state file delete / stop; status=running before first step.
- Parity: stop/idle behavior identical across paths.
- Targeted: VersionSwitchTest, warm process tests, session status tests.
- Docs: warm JVM / stop / status.

### Phase 4: Phrase validation + quote warning (D: bugs 5, 8)
- Repro tests: `save E.` (quotes stripped) throws NPE instead of syntax error naming missing element; `*, save E.` under mvnw silent (no text-b64 suggestion).
- Parity: same step text via execute-step / isolate / direct produces identical syntax error or warning.
- Targeted: step/phrase/ActionOperations tests.
- Docs: execute-step --text / --text-b64.

### Phase 5: validate matching (E: bug 4)
- Repro tests: false positive undefined on Outline `<placeholder>` and core steps; whole-suite hangs with no progress.
- Parity: validate matches what the runner accepts.
- Targeted: feature index / validate tests.
- Docs: validate help / behavior.

### Phase 6: Diagnostic capped + FailureRecord shape + failedScenarios (F+G: bugs 9, 14, 15, 16)
- Repro tests: scoped query always scanCapped:true; failure.cause has full stack; stackHead is exception message; failedScenarios names only (no path:line / example).
- Parity: failure JSON / summary / query identical across paths.
- Targeted: FailureRecord, DiagnosticQuery, execute-step, RunReports tests.
- Docs: failure JSON, summary, query.

### Phase 7: Docs alignment + version tree detection (H+I: bugs 10, 11)
- Repro: docs contradict on mvnw.cmd exit; missing `v/<current>/` silent.
- Targeted: agent contract, VersionSwitchTest.
- Docs: release notes, workbench-agent-detail.md, export-guidance.

### Phase 8: Speed (12, 13)
- Repro: first isolate cold start near timeout; stage-overlap log after compile; possible double compile.
- Targeted: timing / ClasspathCache / launch tests.
- Docs: speed / timing notes.

After Phase 8 push: **STOP and report the head commit**. Full regression only when told to continue.
