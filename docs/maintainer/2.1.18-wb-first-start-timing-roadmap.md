## Phases

### Phase 0 — Instrument the ~40s gap (no behavior change)

Add shared progress stages so the post-digest time is visible. Record link vs copy counts on copy-live.

- Extend the existing copy-live stage (or add a companion line) to report `links=N copies=M` (count hardlink successes vs fallback copies), plus files/bytes/ms if cheap.
- Add stages emitted via the existing `progress stage=...` path that SessionHealthWait observes from logs (session.log and/or worker stderr):
  - `worker-spawn` (parent process, immediately after `ProcessBuilder.start` in the session launch path)
  - `jvm-main` (worker process, earliest practical point in main)
  - `classpath-scan` (or `glue-scan`; worker, around classpath/glue initialization before server bind)
  - `worker-ready` (when `/health` first succeeds, or equivalent)
- All new stages must be emitted to the same streams SessionHealthWait already tails using the existing progress stage format.
- Keep all prior stages. Targeted tests only. No functional change. Consumer-shaped Windows timing repro that prints the new stages and counts.

### Phase 1 — Parallelize the link path (simplest shared optimization)

`linkTree` / the link branch of `transferTree` is currently a serial for-loop of `linkOrCopy`; the copy path is already parallel (`copyFiles` with an ExecutorService). Make the link branch use the same thread-pool pattern as `copyFiles`, still calling `linkOrCopy` per file (`Files.createLink` preferred, copy fallback on Unsupported/Security/IOException). Preserve Windows correctness and all isolation/cache invariants.

Guided by Phase 0 numbers. If this brings fresh-cache first isolate worker-ready under 60s on Windows-shaped cold start, stop further optimization. Targeted tests + consumer_sim / Windows cold-start repro.

### Phase 2 — Additional guided optimizations if still over target

Only if Phase 1 does not meet the target. Simplest shared-path changes that preserve invariants:

- Delay or skip full live materialize until first rebuild (if safe given base/live isolation and second-start classpath-cache).
- Other reductions in per-file Windows cost that do not break the fallback copy.
- Do not shift work into discover. Do not weaken isolation or cache. Targeted tests.

### Phase 3 — Docs, scoreboard, STOP

Update `docs/pickleball-workbench.md`, release notes, CLI help if needed, and this roadmap with measured numbers.

Fill scoreboard with Windows consumer-shaped numbers.

Note the `validate --all` hold / needs controlled rerun.

**STOP after the implementation push and report the head SHA.** Full Gradle / consumer_sim / verify_agent_contract / Windows CI only when Dan says continue.
