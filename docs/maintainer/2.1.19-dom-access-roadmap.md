# Pickleball 2.1.19 DOM Access Full Review and Roadmap

**Goal (Dan, 2026-11-03):** EVERY Pickleball DOM access point, including read-only mapping, counting, identification and filtering of elements, must go through dom-composite / the DOM selector, efficiently (batched, one round trip where possible, no per-element WebDriver chatter). Fix through simplicity and one shared path, not per-call-site tweaks.

**Context:** 2.1.19 made dom-composite (vendored Java bindings 2.4.0) the single entry point for Pickleball DOM and desktop interaction. ElementSnapshot rework (head 8ebae4ff) made ElementWrapper read elements through one snapshot. Composite phases and snapshot phases are marked complete in their roadmaps, but residual raw WebDriver reads remain for counting, filtering, identification, and some scans/waits.

**HARD RULES:** never commit, push or merge to master; no force-push; no failing or weakened tests; docs updated with every change; simplicity and one shared code path; AI-agent confusion from Workbench/MCP syntax counts as a bug; CLI-first and toggleable per-entity logging checklist in every roadmap. TESTING RULE (Dan 2026-11-02): between phases run only the tests tied to the changed functionality, and hold full regression (full JDK 21 suite, consumer_sim, agent contract, CI) until all implementation is done, then run it once. Push after each phase. Keep the agent index synced (`python scripts/sync_consumer_guidance.py`) so CI validate stays green. Update this roadmap scoreboard with SHAs.
