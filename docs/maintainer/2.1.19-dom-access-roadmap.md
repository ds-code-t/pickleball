# Pickleball 2.1.19 DOM Access Full Review and Roadmap

**Goal (Dan, 2026-11-03):** EVERY Pickleball DOM access point, including read-only mapping, counting, identification and filtering of elements, must go through dom-composite / the DOM selector, efficiently (batched, one round trip where possible, no per-element WebDriver chatter). Fix through simplicity and one shared path, not per-call-site tweaks.

**Context:** 2.1.19 made dom-composite (vendored Java bindings 2.4.0) the single entry point for Pickleball DOM and desktop interaction. ElementSnapshot rework (head 8ebae4ff) made ElementWrapper read elements through one snapshot. Phases 1–4 closed the leftover counting, filtering, identification, scan, wait, and interaction reads. The scoreboard below is the status. There is no remaining (c) gap.

TESTING RULE (Dan 2026-11-02): between phases run only the tests tied to the changed functionality, and hold full regression (full JDK 21 suite, consumer_sim, agent contract, CI) until all implementation is done, then run it once. ## Logging checklist

Trace-level and off unless asked. `pkb_composite_log=batch` or `pkb_composite_log=all` records one line per batched describe:

`TRACE batch mode=<composite|selenium-batch|selenium-legacy> selector=<by> nodes=<count> durationMs=<n>`

No per-element line. The log stays in the composite log file (`pkb_composite_log_dir`, otherwise the temp composite log). It must not change the result of the query.

## Upstream request (non-blocking)

dom-composite 2.4.0 `query` already returns tag, text, states, attributes, and bounds, and Pickleball reads those fields with no second round trip. 2.4.0 still has no element-scoped eval and no describe-by-node-id. Snapshot refresh re-finds the node through WebDriver. Request, when the DOM Selector bot next cuts a binary:

1. `describe` for many stored node ids in one call: tag, text, displayed, enabled, selected, attributes, bounds.
2. Element-scoped eval so the snapshot script does not need a WebDriver round trip.

Pickleball does not block on either. The adapter batch is the path until those verbs exist.
