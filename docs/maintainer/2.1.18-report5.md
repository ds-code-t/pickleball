## Root Cause Analysis

**#1 Exit codes**: Code already calls `exitProcess(2)` for parse failures (including split `--tags`) and unknown verbs. `exitProcess` does `System.exit` then `Runtime.halt` to defeat the Maven exec:java rewrite. Project `mvnw.cmd` preserves ERRORLEVEL. `scripts/consumer_sim.py` already has stages that expect exit 2 for an unknown verb and a split `--tags` through the wrapper (using `mvnw.cmd` on Windows). Yet the consumer retest of `111dea5` on Windows PowerShell still sees exit 1 through the documented `mvnw ... exec:java` launch. True cause is that the harness command does not match the exact documented launch the consumer used, or the Windows CI job does not exercise/assert that path the same way, or the in-process exec:java path still maps to Maven's BUILD FAILURE exit 1 on that exact invocation. Fix must make the exact documented command (from the agent guide: `./mvnw -q org.codehaus.mojo:exec-maven-plugin:3.5.0:java "-Dexec.mainClass=tools.dscode.launcher.PickleballWorkbenchLauncher" "-Dexec.classpathScope=test" "-Dexec.args=..."` and the Windows `mvnw.cmd` equivalent) exit 2, proven by a test that runs that command on Linux and on the Windows CI job.

**#2 Value sources**: `workspace-show` currently marks some keys ` computed` via `WorkspaceSeed.computedKeys` (runner-set secrets and some hook keys when absent from property files). Other hook-computed values (for example a description that holds user, machine, locale, and Java vendor) are not marked. Users cannot tell which keys need a reseed. Need one shared value-source model: every value reports its source (`hook`, `properties`, `default`, `cli/override`). Hook-computed values are marked. Not a special case for secrets.

**#3 Timing stages**: `launch-timing.txt` records `index` then jumps to `maven-start`. The gap (compile, seed fork, etc.) is invisible. Add notes for those stages so the gap is visible. Overlapping the index with compilation is tech debt, not this round.

**#11-14**: Report4 phase 6 claimed these were re-verified with tests (non-null message/stackHead, idle status, PASSED/FAILED on events, quote warning). Confirm the tests exist and cover the observed problems; add any missing assertion. No new work if covered.
