# Composite snapshot coverage on origin/3.0.0 (`960bad6b`)

Inspected 2026-11-13, America/Phoenix. Repo unchanged.

**Verdict:** Chrome, Chromium, Edge, and Firefox write one composite snapshot (screenshot, HTML, structure, XPaths, distinct geometry spaces, and a pre-map). Firefox uses BiDi, or a logged Selenium fallback when no socket is published. The desktop row below is the earlier accessibility walk; the desktop producer itself is documented in `docs/snapshot.md`.

**Docs:** They describe a unified *query/verb/walk model* as implemented, not a unified composite snapshot. AGENTS.md:435: "Browser DOM and desktop UI share one query language, one verb set, and one walk/attach/resolve model; named platform exceptions are justified in the design." In Pickleball, "composite snapshot" is a per-element `ElementSnapshot`, not a page-level map (`AGENTS.md:126`; `CompositeSnapshotProducer.java:29-39`).

## Gaps

- Chrome, Chromium, and Edge `snapshot` is the combined artifact. Firefox uses the same builder through BiDi or the Selenium fallback. `LiveTree.enrich` remains the per-node path used by actions, not by the snapshot.
- `stableSelector` on the per-element snapshot is CSS, not the page XPath.
- `docs/maintainer/3.0.0-java-dom-design.md:37` names a `SnapshotSource` class that does not exist. The CDP producer now computes distinct live spaces. `3.0.0-workbench-edit-design.md:50` still says DesktopTree is fixture-only.
