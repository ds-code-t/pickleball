# Composite snapshot coverage on origin/3.0.0 (`960bad6b`)

Inspected 2026-11-13, America/Phoenix. Repo unchanged.

**Verdict:** Not fully implemented, or universal. No single artifact combines a screenshot, page source, structure, XPaths, and viewport/screen mapping. Pieces exist separately, mostly on Chromium. Desktop is an accessibility-tree walk with screen-pixel bounds.

**Docs:** They describe a unified *query/verb/walk model* as implemented, not a unified composite snapshot. AGENTS.md:435: "Browser DOM and desktop UI share one query language, one verb set, and one walk/attach/resolve model; named platform exceptions are justified in the design." In Pickleball, "composite snapshot" is a per-element `ElementSnapshot`, not a page-level map (`AGENTS.md:126`; `CompositeSnapshotProducer.java:29-39`).

## Gaps

- No combined screenshot + source + structure + XPath + viewport map on any platform.
- Live `snapshot`/`query` skip `LiveTree.enrich`, so trees usually have no boxes. `enrich` runs only from `PageActions` (click/drag) with scroll `0,0` (`PageActions.java:32`). `Query.geometry` copies the same box into four of five named spaces (`Query.java:349-356`).
- No composite page-source verb (`ElementOperations.java:351-353`). `stableSelector` is CSS, not XPath. Firefox cannot join the Java engine. Desktop has no screenshot; `image` needs a caller `--viewport` file (`Engines.java:82-83`).
- `docs/maintainer/3.0.0-java-dom-design.md:37` names a `SnapshotSource` class that does not exist. AGENTS.md describes five real geometry spaces; the Java engine does not compute distinct live spaces. `3.0.0-workbench-edit-design.md:50` still says DesktopTree is fixture-only.
