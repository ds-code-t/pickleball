**Pickleball 3.0.0 Java DOM Composite Engine Design**

**Subsystem:** Java DOM Engine (replaces Rust composite)  
**Status:** Design locked 2026-11-12; implementation on branch `3.0.0`.

### Purpose
Replace ALL Rust in the DOM composite engine (and anywhere else in pickleball) with Java. Retain every Rust-implemented capability: query, selectors, geometry, observe, actions, CLI, MCP server, conformance suite, CDP talk to Chrome. Integrate more tightly with Dalton-centered pickleball 3.0.0. The engine interface stays general-purpose, not tied to Pickleball.

Open engine PRs #2 and #3 on ds-code-t/dom-composite must NOT be merged. They may be superseded by this Java rewrite. Do not touch them.

### Where the Java engine lives
- Primary: new Gradle module `dom-engine` inside the pickleball repository (`dom-engine/`). Core package `dev.domengine` (or `tools.dscode.domengine`). No dependency on pickleball, Dalton, Cucumber, or Selenium. General-purpose.
- Pickleball integration: thin adapter in `src/main/java/tools/dscode/` (replaces or wraps `DomCompositeAdapter` / `CompositeBinaryLocator`). Can use the engine in-process for speed or launch the Java CLI process for isolation, matching today's binary model.
- Alternative considered: rewrite inside ds-code-t/dom-composite on a non-primary branch. Rejected for the initial implementation because tighter Dalton integration and single-repo development are preferred. Extraction to a separate repo remains possible later.
- Vendored `dev.domcomposite.Client` stays until the switchover; then locator points at the Java engine.

### How it talks to Chrome (CDP)
- Java CDP client (WebSocket) implementing the same LiveTree behavior: `DOM.getDocument` with pierce, `Page.getFrameTree`, computed style, border boxes in top-document CSS pixels, accessible name.
- Session attach/create, detach without killing the browser (when attached).
- Same command surface as today's `composite serve --stdio`.

### How pickleball locates and runs it
- `CompositeBinaryLocator` evolves to `CompositeEngineLocator` (or updated `CompositeBinaryLocator`).
- Order: `pkb_composite_bin` (now path to Java CLI jar or script), `COMPOSITE_BIN`, classpath-embedded Java entry point, or in-process service.
- Default becomes the in-process or launched Java engine. `pkb_composite=off` still falls back to Selenium element path.
- CLI-first: `domengine` (or keep `composite`) CLI is the surface. Workbench, MCP, Gradle only forward.

**As built:** The class stayed `CompositeBinaryLocator`. Explicit `pkb_composite_bin` (property, then `pkb_runvars`, then env `COMPOSITE_BIN`, then env `pkb_composite_bin`) wins, then the Java engine launcher unless `pkb_composite_engine=rust`, then Rust homes, classpath natives, and the Maven classifier. It is a launched CLI, not an in-process service. See `docs/direct-control-handoff.md`.

### Integration with Dalton
- Sessions and logs can be recorded in Dalton when `pkb_dalton=true` (optional, not required).
- Entity references in selectors or payloads if useful (future).
- Engine remains usable without Dalton. Tighter coupling is through the adapter, not the core.

### Capabilities preserved (must match current Rust)
- ContextSource walker (light, shadow, iframe).
- LiveTree CDP adapter + SnapshotSource + DesktopTree (accessibility via Java/AT or fixture fallback; native desktop verbs where possible).
- Pipeline selectors: css, xpath, text, role, frame, shadow, near, below, desc, a11y, image (template/OCR optional).
- Geometry, observe, actions: click, type, scroll, submit, key, dblclick, contextclick, drag, eval, screenshot, etc.
- CLI, MCP server (`domengine-mcp` or equivalent), conformance suite.
- Logging: toggleable, per-entity, date-stamped, size-capped (reuse 1 MiB / 10 MB patterns). `COMPOSITE_LOG*` equivalent.

### Central core / 10MB file cap / Log dashboard
- **Central core**: the `dom-engine` module is the central core. Pickleball, Workbench, and future consumers share it.
- **10MB file cap**: already implemented for `.pickleball/history.log` (trim from front). Apply the same cap pattern to engine logs and any new log files. Do not reimplement.
- **Log dashboard**: if missing, add a Workbench tab or CLI `log show` / `log tail` that surfaces the capped, date-stamped engine and history logs. CLI-first; GUI only forwards. Inspect current Workbench for existing log views before adding.

### Non-goals
- No change to existing Gherkin syntax or step annotations.
- Do not remove Cucumber-core aspects.
- Do not weaken or delete existing tests.
- Version stays 3.0.0. No force-push, no release, never master / 2.2.0 / 2.1.19.
- Do not truncate AGENTS.md or other docs.

See `docs/roadmaps/3.0.0-java-dom-roadmap.md` for the phased plan.

## Live AT-SPI Fix-back 1

Linux AT-SPI calls do not use `dbus-send --address=`. That invocation does not complete D-Bus Hello on the accessibility bus. `AtSpi.call` sets `DBUS_SESSION_BUS_ADDRESS` to the address returned by `org.a11y.Bus.GetAddress` and uses `--session`. `busAddress()` is unchanged: `--session` against the session bus. Name is still `Properties.Get`. Role is `GetRoleName` first, then `GetRole`. The shared map is `NativeDesktop.mapRole`. The number is stored as `atspi-role`. The numeric fallback matches `AtspiRole` in at-spi2-core 2.56, not the older ATK numbers. `FOCUS_TRAVERSABLE` (21) is why frame is 23 and button is 43. `EXTENDED` after window is why application is 75. A blank GetRoleName is the only time that table is used, so a wrong number cannot turn a named button into a radio.
