# Pickleball 2.1.19 Context / Count / Position Roadmap

**Goal (Dan):** Fix correctness bugs in composite context and position selection, cut round trips for count/every/nth, and integrate more tightly with Dom Composite. Existing Gherkin/step syntax and behavior must not change. Dom-composite may be changed (breaking changes allowed; no other app uses it) but must stay a decoupled general-purpose engine with no knowledge of pickleball.

**Baseline:** SHA `9234fb5e` on branch `2.1.19`. Previous DOM efficiency round completed. Composite is primary via `ElementOperations` / `DomCompositeAdapter` when binary present (`pkb_composite=auto`).

**HARD RULES:** never commit, push or merge to master; no force-push; no failing or weakened tests; docs updated with every change; simplicity and ONE shared code path. Group by verified shared root cause. AI-agent confusion from syntax/controls counts as a bug. CLI-first and toggleable per-entity logging checklist in every phase. Between phases run ONLY targeted tests tied to the changed code. The final full regression (Gradle `:test :pickleball-control-protocol:test :pickleball-control-api:test :pickleball-workbench:test --rerun-tasks`, `consumer_sim`, `verify_agent_contract.py`, Windows CI) runs ONCE at the very end of all phases. After the last implementation push, Build must STOP and report the head commit, and run the final regression only when told to continue. CI runs the Windows job only. Keep agent index synced. Consumer-shaped repros for bugs 1–4 that fail before the fix and pass after; Windows/PowerShell and multi-run-id patterns where relevant. Parity tests (Selenium vs composite, across launch modes) asserting identical contracts. Measured round-trip or timing before/after for each efficiency change.

**Verified candidates (code at 9234fb5e):**

CORRECTNESS BUGS (composite on):
1. Context without id/name: `CompositeWebElement.scope()` + `xpathAnchor()` returns null → `findElements` empty. Selenium would search relative to the context element.
2. XPath starting with `(` is returned unchanged by `scope()` (also guards for `//`, `(//`, `(/`) → searches whole page, not the context. `combineAnd` can produce parenthesized expressions.
3. Nesting filter silently skipped when any hit lacks id/name (same root cause as 1). `NestedByLocator.tryCompositeNestBatch` returns null if any `anchor()` is null; Selenium would still filter. Other fallbacks may also skip or return unfiltered.
4. `AllContextsScan.limit` ignores `#N` and every `#N` → "the 3rd X" returns the first match on the all-contexts path. Only handles `"last"`; otherwise first (if no selectionType) or all. Wraps every hit before limiting.

EFFICIENCY:
5. Position selection is duplicated in `NestedByLocator.findWithRetry`, `ContextWrapper.selectByPosition`, `AllContextsScan.limit`, and ordinal slice in `DomCompositeAdapter.hits` / `SelectorTranslator.ordinal`. One shared `PositionSelection.apply` required.
6. All-contexts wraps and snapshots every hit before limit keeps one → N-1 wasted evals. Wrap only chosen hits.
7. count / every costs 1 query + N snapshot evals. Prefer lazy snapshots from hit data (tag, text, attrs, displayed, bounds); eval only when `selectedValue`/`siblingIndex`/`stableSelector` is read. Or batch eval many node-ids.
8. Dom Composite lacks `query --within <node-id>` (search under a node). Once added, `scope()` uses it instead of the id/name XPath anchor → fixes bugs 1–3.
9. Dom Composite nesting filter (`--nesting deepest|outermost` or `>> leaf`) would remove the nesting round trip and the broken fallback.
10. After nesting lives in the engine, send `--nth` / `--count-only` so position can be applied by the engine (order must stay: displayed → nesting → regex → position).
11. eval accepting several node ids: every costs 1 query + 1 eval.

**Architecture:** All changes go through the single shared path (`ElementOperations` → `DomCompositeAdapter` / `ElementReads` / new `PositionSelection`). Composite remains decoupled. Pickleball gates on capabilities and keeps fallbacks when the binary does not list them. Coordinate Dom Composite API additions as general-purpose (update `prompts/domc-asks.md` if present, or create). Parity tests assert identical contracts.

**Every phase is mandatory and must be completed in full. Nothing is optional or deferred.**

## Phase A (pickleball only): shared PositionSelection + wrap-only-chosen + lazy snapshots + consumer repros for bugs 1–4
**Functionality:**
- Introduce one shared `PositionSelection.apply(List, ElementMatch)` used by NestedByLocator, ContextWrapper, AllContextsScan, and any ordinal slice. Handles last, numeric index (1-based), every N, selectionType. Fixes bug 4.
- In AllContextsScan (and similar): collect raw hits first, apply limit/position, then wrap/snapshot only the chosen hits. Fixes wasted N-1 evals (item 6).
- Lazy ElementSnapshot from hit data where possible (tag/text/attrs/displayed/bounds from query response). Eval only on demand for selectedValue/siblingIndex/stableSelector (item 7 partial).
- Consumer-shaped repros (failing tests or scenarios) for bugs 1–4 that demonstrate empty find on context-without-id, whole-page search on parenthesized XPath, skipped nesting, and wrong ordinal on all-contexts. Must fail before fix, pass after.
- No Dom Composite changes yet. Fallbacks preserved.

**Docs:** Update this roadmap. Note in dynamic-steps or agent feature-map that position selection is now shared and all-contexts honors #N. Document the repros.

**Tests:**
- New unit tests for PositionSelection covering last, 3rd, every 2, empty, out-of-range.
- Parity: Selenium vs composite for position on normal and all-contexts paths.
- Consumer repros for bugs 1–4 (targeted Gherkin or Java checks). Measured: all-contexts N hits now wraps only 1.
- Existing NestedByLocator / ContextWrapper / AllContextsScan tests remain green.

**Logging checklist:** Trace-level position apply; toggleable via `pkb_composite_log` or entity.

**Regression risk:** Low-medium. Position is used in many element finds. Existing tests lock 1st/last/every behavior on Selenium path. Parity covers composite. Launch modes covered.

## Phase B: upstream --within, --nesting, multi-node eval through Dom Composite; switch scope()/nesting over with capability gates

Add `--nesting deepest|outermost` (or equivalent) applied after displayed, before regex/position. Add multi-node `eval` accepting several node ids in one call.
- Update `prompts/domc-asks.md` (create if missing) with the general-purpose API requests. No pickleball knowledge in the engine.

- In NestedByLocator: when capability lists nesting, send the flag; drop the broken tryCompositeNestBatch and JS fallback for that path. Order preserved.
- Multi-node eval for count/every snapshots when capability present.
- Capability gates everywhere; Selenium fallback when composite off or capability missing.
