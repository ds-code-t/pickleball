# Pickleball 2.1.19 Context / Count / Position Roadmap

**Goal (Dan):** Fix correctness bugs in composite context and position selection, cut round trips for count/every/nth, and integrate more tightly with Dom Composite. Existing Gherkin/step syntax and behavior must not change. Dom-composite may be changed (breaking changes allowed; no other app uses it) but must stay a decoupled general-purpose engine with no knowledge of pickleball.

**Baseline:** SHA `9234fb5e` on branch `2.1.19`. Previous DOM efficiency roadmap completed. Composite is primary via ElementOperations / DomCompositeAdapter when binary present (`pkb_composite=auto`).

**HARD RULES:** never commit, push or merge to master; no force-push; no failing or weakened tests; docs updated with every change; simplicity and ONE shared code path. Group by verified shared root cause. Analyze regression risk per change: other callers, launch modes, existing tests that lock the behavior. Add parity tests (Selenium vs composite, across launch modes) asserting identical contracts. Include measured round-trip or timing before/after for each efficiency change. Consumer-shaped repros for bugs 1–4 that fail before the fix and pass after; Windows/PowerShell and multi-run-id patterns where relevant. Every phase is mandatory and must be completed in full; nothing is optional or deferred. Between phases run ONLY targeted tests tied to the changed code. The final full regression (Gradle `:test :pickleball-control-protocol:test :pickleball-control-api:test :pickleball-workbench:test --rerun-tasks`, `consumer_sim`, `verify_agent_contract.py`, Windows CI) runs ONCE at the very end of all phases. **Verified candidates (code at 9234fb5e):**

CORRECTNESS BUGS (composite on):
1. Context without id/name: `CompositeWebElement.scope()` / `xpathAnchor()` returns null → find empty. (xpathAnchor only uses id or name+tag.)
2. XPath starting with `(` is returned unchanged by `scope()` (also `//`, `(//`, `(/`) → searches whole page, not the context. `combineAnd` can produce these.
3. Nesting filter silently skipped when any hit lacks id/name (same root cause as 1; `NestedByLocator.tryCompositeNestBatch` returns null if any anchor null; Selenium would filter).
4. `AllContextsScan.limit` ignores `#N` and every `#N` → "the 3rd X" returns the first match on the all-contexts path. (only handles `last` or first/all; no elementIndex/sampleEvery).

EFFICIENCY:
5. Position selection is duplicated in `NestedByLocator.findWithRetry`, `ContextWrapper.selectByPosition`, `AllContextsScan.limit`, and a separate ordinal slice in `DomCompositeAdapter.hits` — one shared `PositionSelection.apply` is required.
6. All-contexts wraps and snapshots every hit before limit keeps one → N-1 wasted evals. Wrap only chosen hits.
7. count / every costs 1 query + N snapshot evals. Prefer lazy snapshots from hit data (tag, text, attrs, displayed, bounds); eval only when selectedValue/siblingIndex/stableSelector is read. Or batch eval many node-ids.
8. Dom Composite lacks query `--within <node-id>` (search under a node). Once added, `scope()` uses it instead of the id/name XPath anchor → fixes bugs 1–3.
9. Dom Composite nesting filter (`--nesting deepest|outermost` or `>> leaf`) would remove the nesting round trip and the broken fallback.
10. After nesting lives in the engine, send `--nth` / `--count-only` so position can be applied by the engine (order must stay: displayed → nesting → regex → position).
11. eval accepting several node ids: every costs 1 query + 1 eval.

**Architecture:** All changes go through the single shared path (`ElementOperations` → `DomCompositeAdapter` / `ElementReads` / shared PositionSelection). Composite remains decoupled. Fallback to Selenium only when composite is off or capability missing. Parity tests (Selenium vs composite, and across launch modes) assert identical contracts. Measured round-trip or timing before/after for each efficiency change. Consumer-shaped repros for bugs 1–4.

**Every phase is mandatory and must be completed in full. Nothing is optional or deferred.**

## Phase A (pickleball only): shared PositionSelection, wrap-only-chosen-hits, lazy snapshots; consumer repros for bugs 1–4
**Functionality:**
- Introduce one shared `PositionSelection.apply(List, ElementMatch)` used by NestedByLocator, ContextWrapper, AllContextsScan, and (where applicable) adapter. Handles last, #N (elementIndex), every #N (sampleEvery), selectionType. Fixes bug 4.
- In AllContextsScan: apply limit/position before wrapping/snapshotting chosen hits only. Fixes wasted N-1 evals (item 6).
- Lazy ElementSnapshot from hit data where possible (tag/text/attrs/displayed/bounds from query); full eval only on selectedValue/siblingIndex/stableSelector read. Reduces count/every cost (item 7).
- Consumer-shaped repros (failing before, passing after) for bugs 1–4: context without id/name, parenthesized XPath from combineAnd, nesting skip on mixed anchors, all-contexts "the 3rd X". Include Windows/PowerShell multi-run-id patterns.
- Capability-gated fallbacks preserved.

**Docs:** Update this roadmap. Note in dynamic-steps or agent feature-map that position is one shared path; all-contexts position honored. AGENTS.md public contracts if needed (behavior unchanged).

**Tests:**
- Parity: Selenium vs composite for position (#N, last, every), context scoping, nesting, all-contexts nth.
- Measured round-trips: all-contexts N hits before (N wraps) vs after (1 wrap); count/every before (N evals) vs after (lazy or batch).
- Targeted consumer scenarios and internal checks for the repro cases.
- Existing tests that lock position/context remain green.

**Logging checklist:** Trace/info for position apply and lazy snapshot miss; toggleable via `pkb_composite_log`.

**Regression risk:** Medium. Other callers of find/position/all-contexts. Launch modes covered by parity. Existing tests lock results; new repros prove the bugs.

## Phase B: upstream --within, --nesting, multi-node eval through Dom Composite; switch scope()/nesting over with capability gates

- In pickleball: gate on capabilities. When `--within` listed, `CompositeWebElement.scope()` / find uses it instead of id/name XPath anchor → fixes bugs 1–3. Nesting uses engine filter when listed, else existing path. Multi-eval for every when listed.

**Docs:** Update this roadmap, AGENTS.md contracts (capability gates), domc-asks, feature-map.

**Logging checklist:** Info for capability use (within/nesting/eval) vs fallback; toggleable.

**Regression risk:** Medium. Other callers of scope/nest/eval. Launch modes and existing tests lock semantics. Fallbacks preserve old behavior.
