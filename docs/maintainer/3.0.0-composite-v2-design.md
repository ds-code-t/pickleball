# Composite snapshot v2 design

**Status:** Approved. Implementation follows `docs/roadmaps/3.0.0-composite-v2-roadmap.md` on `3.0.0-composite-v2`.
**Base:** `origin/3.0.0` at `c337ea27`. v1 schema is `dom-engine/src/main/resources/dev/domengine/snapshot/composite-snapshot.schema.json` (`$id` `urn:pickleball:composite-snapshot:1`).

Early 3.x accepts v1 and v2. A later cut-over may drop v1. This document does not drop it.

## v2 schema outline

File: `dom-engine/src/main/resources/dev/domengine/snapshot/composite-snapshot-v2.schema.json`.

| | v1 (unchanged) | v2 |
|---|---|---|
| `$id` | `urn:pickleball:composite-snapshot:1` | `urn:pickleball:composite-snapshot:2` |
| `schema` | `pickleball.composite-snapshot` | `pickleball.composite-snapshot` |
| `version` | `1` | `2` |

`schema` stays the family name. Version and `$id` select the document. Draft 2020-12. `additionalProperties` false, same as v1.

v2 required fields are the v1 required set plus `canonical`. v1 field shapes stay valid inside v2 so a v1 reader that ignores unknown fields can still see `nodes[]`, `premap`, and `source`. The v2 schema itself rejects a document that omits `canonical`.

`canonical` is the only authored tree. `nodes[]` and `premap` are projections and must be reproducible from `canonical` plus viewport, screenshot, and platform.

```text
canonical
  kind            "html" (browser) or "html-ish" (desktop)
  frames[]
    id, parent_id, url, frame_path, offset {x, y}
    html          raw or synthesized document for that frame
    shadow        "preserved" when the html inlines shadow roots
  side            desktop only; omitted on browser
    a11y_xml      original a11y-xml text
    native_path_attr   "data-pkb-native-path"
```

Browser `source.kind` stays `html`. The joined frame text may remain for v1 readers. The canonical per-frame `html` is authoritative. Desktop `source.kind` stays `a11y-xml` and `source.text` equals `canonical.side.a11y_xml`.

Optional on each `nodes[]` entry, v2 only: `identity` (the replay chain). v1 nodes omit it. Absence of `identity` does not fail v1 validation.

### Dual acceptance

| Direction | Rule |
|---|---|
| Parse | `version` 1 validates against the v1 schema. `version` 2 validates against the v2 schema. Any other version fails. |
| Missing version | Treat as v1 when `schema` is `pickleball.composite-snapshot` and `canonical` is absent. A document with `canonical` and no version fails. |
| Produce | New browser and desktop snapshots emit version 2. Offline `premap --file` emits version 2. |
| Project | Every v2 document also carries `nodes[]` and `premap` built by the existing builder, so a consumer that only reads those fields still works. |
| Round-trip | `CompositeSnapshot.fromJson` reads both. `toJson` writes the version it parsed, or 2 when the builder produced the snapshot. |

No second snapshot type. JSON and JSONata projections are on demand over this document. They are not stored.

## Browser canonical HTML

One `canonical.frames[]` entry per frame document, including the main frame and each iframe. `frame_path` is the index-qualified XPath chain of iframe elements, joined by ` >> `, matching v1 `frames[]`.

`html` is serialized from the captured DOM tree, not from the browser's own `outerHTML`. Chrome, Chromium, and Edge capture that tree with the CDP DOM domain. Firefox and the facade capture it with `page-walk.js`, one walk per browsing context. `CanonicalHtml` writes the markup from that tree. `DOM.getOuterHTML` and the walk's `outerHTML` field stay on `source.text` only. They are not `canonical.frames[].html`.

The captured tree is one pierced tree: closed shadow roots are included, and a cross-origin frame is its own document instead of the parent's `outerHTML`. Attribute order is the order on the captured node. The serializer does not ask the page for markup and does not change the live document.

The serializer writes:

- Element start tag, attributes, children, end tag, in document order.
- A shadow root is a child of its host: `<template data-pkb-shadow="open">...</template>` or `closed`. The template is engine markup, not page content. Query evaluation treats that template's children as the shadow tree and does not match the template element itself.
- An iframe element stays in the parent document with `data-pkb-frame="<frame id>"`. Its document is the child frame's `html`, not `srcdoc` and not the iframe's innerHTML.
- The main frame id is `main`. A child id is the CDP frame id when the capture has one, otherwise `f` plus the backend node id.

Text, comments, and `<` / `&` in text nodes are escaped. Attribute values are escaped. The serializer does not reformat or drop unknown attributes. `data-pkb-shadow` and `data-pkb-frame` are the only attributes the serializer adds.

## Desktop HTML-ish synthesis

Input is the projected accessibility tree the UIA, AX, and AT-SPI producers already return (`NativeDesktop.mapRole` roles, screen box, accessible name, states, `platform-role`, and `uia-runtime-id` / `ax-path` / `atspi-path`). Synthesis does not recapture and does not call FlaUI.

`canonical.kind` is `html-ish`. One frame, id `desktop`, parent empty, `html` a single document: `<html><body>...</body></html>`. The desktop root element is the body’s first element child when the capture root is `desktop`; otherwise the capture root is that child.

### Role to tag

Use the projected role from `mapRole`. Unknown roles become `<div role="...">` with that role string. Do not invent a second role map.

| Projected role | Element | Attributes added by the mapping |
|---|---|---|
| `button` | `button` | |
| `textbox` | `input` | `type="text"` |
| `label` | `label` | accessible name as text content |
| `checkbox` | `input` | `type="checkbox"` |
| `radio` | `input` | `type="radio"` |
| `combobox` | `input` | `role="combobox"` |
| `window` | `section` | `role="window"` |
| `application` | `div` | `role="application"` |
| `dialog` | `dialog` | `open` when the node is displayed |
| `img` | `img` | |
| `link` | `a` | |
| `heading` | `h2` | `role="heading"` `aria-level="2"` |
| `list` | `ul` | |
| `listitem` | `li` | |
| `menu` | `div` | `role="menu"` |
| `menuitem` | `div` | `role="menuitem"` |
| `tab` | `div` | `role="tab"` |
| `desktop` | `div` | `role="desktop"` |
| anything else | `div` | `role` set to the projected role when it is not `unknown` |

`button`, `a`, `label`, `li`, `h2`, and `menuitem` put the accessible name in the text content when the node has no separate value. `input`, `img`, and `combobox` put it on `aria-label` and do not duplicate it as text.

### Attribute mapping

| Source | HTML |
|---|---|
| UIA AutomationId, when the capture stored it | `id` when the value is an HTML id token (ASCII letter then letters, digits, `-`, `_`, `:`). Always also `data-uia-automation-id`. |
| Accessible name | text content or `aria-label` as above. When both text and a different name exist, text is the content and the name is `aria-label`. |
| UIA ClassName, when stored | `class` and `data-uia-class` |
| Help text, when stored | `title` |
| `platform-role` | `data-platform-role` |
| Value | `value` |
| checked | `checked` on checkbox and radio; otherwise `aria-checked="true"` |
| expanded | `aria-expanded="true"`; collapsed or missing on an expandable control is `aria-expanded="false"` |
| disabled | `disabled` and `aria-disabled="true"` |
| focused | `data-pkb-focused="true"` |
| offscreen or hidden | `data-pkb-offscreen="true"` |
| native path | `data-pkb-native-path` with the `uia-runtime-id`, `ax-path`, or `atspi-path` |
| backend | `data-pkb-backend` `uia`, `ax`, or `atspi` |

Existing capture attributes that are not in this table are copied as `data-pkb-attr-<name>` with the name lower-cased. Secrets are not a desktop capture field. Do not add one.

### Geometry

Write `data-x`, `data-y`, `data-w`, `data-h` from the node screen box, in pixels. The builder fills `boxes.screen_px` from those values and leaves `document_css_px` null, which is the current desktop rule. Do not copy the screen box into the CSS spaces. `image_px` stays the screen box minus the window origin, times `image_scale`.

### Side data

- `canonical.side.a11y_xml` is the original `<node role name x y w h>` serialization the desktop producer already writes. Synthesis does not replace that string.
- `canonical.side.native_path_attr` is `data-pkb-native-path`.
- v1 `source.kind` remains `a11y-xml` and `source.text` is that same XML.
- v1 `nodes[].path` remains the native path when the capture wrote one, otherwise the numeric id.

## nodes[] and premap as projections

`CompositeSnapshotBuilder` keeps one pipeline.

1. If the input is a v2 canonical tree, parse `canonical.frames[].html` into the existing `DomNode` tree. Shadow templates become `shadowRoots`. `data-pkb-frame` links an iframe element to the child frame. Desktop `data-x`/`data-y`/`data-w`/`data-h` become the screen box.
2. If the input is a live `DomNode` tree, serialize it to canonical HTML or HTML-ish first, then project from that serialization so the stored HTML and the flat list cannot drift.
3. Run `XPathIndex.assign`, section detection, box caps, label affinity, and `PreMapBuilder` on that tree. Write `frames[]`, `nodes[]`, and `premap` from the result.

v1 documents have no canonical tree. Their `nodes[]` and `premap` stay the builder output they have today. Query results that already pass stay the same, because the projection uses the same index and pre-map code.

A projection is pure: the same canonical HTML, viewport, screenshot bytes, and platform produce the same `nodes[]` and `premap`, aside from `id` and `captured_at`, which are capture metadata.

Indexes are not a second source of truth. They are the fast path over the projection.

## Human and full-access masks

Two views. Computed lazily on first query for that root object and document version, and kept in a 32-entry cache keyed by the root object. A blank document version stamps element count and node id and geometry, so an in-place edit is recomputed. Not stored as a second tree. Applied to the candidate set before DSL, XPath, and CSS evaluation. An index hit is intersected with the mask. The mask never removes nodes from `nodes[]` or from the canonical tree.

Default view for a real-use query is `human`. `full-access` is explicit (`--exposure full` or `exposure=full-access`). The existing `exposure=human` value stays the human view.

### Seen

A node is seen when all of these hold:

- `in_viewport` is true (the visual box, or `screen_px` on desktop, intersects the viewport with area greater than zero).
- The node is displayed (no `hidden` state, not `display:none`, not `visibility:hidden`, opacity not zero).
- When paint order was captured, no later opaque node fully contains this node's box. When paint order is absent, do not invent occlusion. Displayed plus in-viewport counts as seen.

### Reachable, side-effect free

Reachable is only a computation over stored state and geometry. The engine must not scroll, click, expand, or otherwise change the page or desktop while deciding the mask.

Active accessible context:

- The snapshot root window or document.
- Not a background window (`offscreen` on a `window` that is not the foreground root).
- Not a closed menu with no size.
- Not a subtree under `aria-hidden="true"` or `inert`, except the disclosure path described below.

Scroll-reachable when all of these hold:

- The node is in the active context and is not `hidden` for a reason other than being outside the current scroll offset.
- A stored box exists.
- An ancestor scrollport (or the document viewport) has content size larger than its client size on an axis, and the node's box lies inside that content box, so a scroll offset change would bring it into the viewport.
- No control state has to change. Scroll only.

Expand-reachable when all of these hold:

- An ancestor is a collapsed expandable the human could open: `aria-expanded="false"`, a closed `details`, or a collapsed state, and that ancestor is enabled and is itself seen or scroll-reachable.
- The node is in that ancestor's stored region, or it is in the tree and its only `hidden` cause is that collapsed ancestor.
- A box or a stored region exists. A collapsed control does not grow a predicted box. No region and no box means not reachable.

Human keeps a node that is seen or reachable. Full-access keeps every node.

### Input

Human mode filters perception and query. Mouse and keyboard actions do not consult the mask. An action whose target is outside the human view still runs. That is not a failure.

## Replay identity

Recorded on each v2 `nodes[]` entry as `identity.chain`, an array tried in order. Each step is omitted when its source value is missing. Replay stops at the first hit and reports `matched` (`stable`, `native-path`, `fingerprint`, `xpath`, or `none`), the locator string, and the zero-based chain index.

Since D6, `act --identity` replays a recorded chain and `act --refind=chain` re-finds a stale ref through the chain kept when the ref was minted (`TargetVerb.CHAINS`, bounded at 4096 keys); the default for a replaced node is still `stale_ref`. Other paths do not read the chain: `DomCompositeAdapter.queryEngine`, `act`, `find`, and `click` take a selector or a live node id. A stale node id throws. `ElementWrapper.refreshSnapshot` looks up `stableSelector` and does not read a chain. `PageActions` `--node-id` is a backend node id; `--refind` repeats the selector. `RecordControl` replay runs the recorded Gherkin routine and stores a name, query, or ref, not a v2 node. `DomCompositeAdapter.replayIdentity` forwards to `IdentityChain.replay` and logs `INFO identity replay matched=<kind>` only when a chain is present. `query --identity` prints a replay without acting; `act --identity` acts on it.

### 1. Stable attributes

First unique hit at record time, in this order. A value that matched more than one node at record time is skipped.

1. HTML `id`, or the desktop `id` copied from AutomationId.
2. `data-testid`.
3. AutomationId when it was not copied to `id` (`data-uia-automation-id`).
4. `role` plus accessible name plus section (`section_path`). Locator form `role=<role>[name="<name>"][section="<section_path>"]`.

### 2. Native path

Desktop only, and only when the path is `uia-runtime-id`, `ax-path`, or `atspi-path`. A bare numeric id is not this step. Browser `backend_node_id` is not durable across loads and is not a chain step.

### 3. Fingerprint

Locator `dhash=<n>;text=<text>;rel=<x>,<y>,<w>,<h>`.

- `dhash` is the existing 64-bit crop hash when a screenshot crop exists. Omit the part when it does not.
- `text` is the accessible name, else the node text, trimmed.
- `rel` is the box divided by the viewport width and height, four numbers rounded to two decimals. Desktop uses the screen box and the window size.

A match needs every recorded part. dHash within 10 bits (the existing `TemplateMatch.prefilter` distance). Text equal after trim. Each relative component within 0.05. Missing dHash matches on text plus relative bounds.

### 4. Positional XPath

The index-qualified `xpath`, plus `shadow_path` and `frame_path`. `XPathIndex.resolve` is the resolver. Last resort.

## OCR hook, cache, and gating

`OcrHook` runs only for an element that is an image, an SVG, or an icon: tag `img`, tag `svg`, role `img`, or role `image`. No other tag.

Cache key is the SHA-256 hex of the cropped image bytes. One process cache. Human and full-access share it. A hit returns the stored text and does not call the runtime again.

Gating happens before the cache lookup's miss path and before any runtime call:

- Human view: the element must be in the human mask. An image outside that mask is not recognized and is not a cache miss that calls the runtime.
- Full-access: any image, SVG, or icon in the tree may be recognized.
- A full-access call may fill the cache. A later human call for the same hash uses that entry when the element is in the human mask.

Runtime resolution, in order: `pkb_ocr_runtime`, then env `PKB_OCR_RUNTIME`. The value is a filesystem path to an already installed runtime. No download, no classpath addition, no FFM. When the value is unset, blank, or not an existing file, the result is:

```text
ok: false
error: OCR runtime not installed
code: ocr_runtime_missing
```

The intended runtime is the Microsoft-signed ONNX Runtime with a light model. It is flagged in the roadmap and the release notes. This branch does not add it.

Query flag `ocr-views` is `human`, `full`, or both. A blank value, or a value with no tokens, means both. Tokens are case-insensitive and ignore surrounding whitespace. A token that is neither is exit 1, code `invalid`, message `invalid ocr-views: <token>`. Several bad tokens are joined with a comma. The check runs before the query installs the viewport or the view mask. A listed view that is not the active one returns zero hits and does not read the runtime.

## Query evaluation

The Control Engine DSL (`>>`, `AND`, `OR`, `NOT`, relations, `look`) stays as it is. Masks apply first, then stages.

`xpath=` and `css=` prefer the index when the expression is one the index can answer (absolute index-qualified XPath, or a simple compound CSS selector). Anything else evaluates on the canonical tree:

- XPath 1.0 through the JDK `javax.xml.xpath` API on an XML DOM built from the canonical tree. No new XML library. Numeric index predicates work. An invalid expression is an error, not zero hits.
- CSS through the in-repo matcher, extended over that same tree for combinators and attribute selectors the index refuses. No new CSS library.

Live `document.evaluate` on a joined browser remains the page check it is today. Offline and desktop evaluation use the canonical tree. JDK 21. No FFM.

## Out of scope

- Actually scrolling or expanding to probe reachability.
- Bundling ONNX Runtime or FlaUI.WebDriver.
- Removing v1.
- A JSONata store. Projection stays on demand.
- Changing Gherkin or Cucumber step annotation shape.
