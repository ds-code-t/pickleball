## Shared mechanism

One long-lived worker / controller with:
- Cached resolved classpath (hash of pom.xml + lockable inputs). Skip full Maven when unchanged. Prefer Maven daemon (mvnd) if available; else persistent resolve or pure cache-skip.
- Warm JVM reuse across commands. Invalidate/restart only on classpath or watched source/config change (content hash or mtime+size).
- Stage scheduler for concurrent independent stages. Overlap feature index with compile; overlap seed with compile.
- Failure fallback to today's sequential fresh-JVM path on any cache miss, hash mismatch, daemon error, or parallel failure.
- Identical Windows/Linux behaviour; use project wrappers only.
- One shared process where possible; remove second controller JVM if isolation invariants allow.

## Phase 1: Persistent classpath cache + warm JVM worker reuse

**Functionality:** Cache resolved classpath; skip full Maven when pom and lockable inputs are unchanged. Reuse a live worker JVM across commands with safe invalidation on classpath or source change.

**Docs:** release notes, AGENT-GUIDE, workbench agent detail, this roadmap.

**Target:** warm discover < 3 s; Maven stage < 1 s on cache hit.

## Phase 2: Parallel stages + overlaps

**Functionality:** Stage scheduler runs independent sync/seed/resolve/index stages concurrently. Build the feature index while compiling. Overlap the seed step with compile.

**Docs:** timing output documentation, release notes.

**Tests:** harness order assertions, correctness of parallel results, no race on shared state.

**Target:** uncompiled `launch-timing.txt` shows `stage=overlap` with `index+compile`; the 60 s index-to-maven gap shrinks because those stages run together. Seed overlaps compile on a classpath-cache hit.
