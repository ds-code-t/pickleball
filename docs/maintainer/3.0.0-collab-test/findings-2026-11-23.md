## Feature / API / MCP ideas
- Non-blocking answer wait (async ask returning a token + cheap poll) or a separate worker lane so waits never block human verbs.
- `upload` / act --kind=attach on start host; human-mode "request upload" affordance.
- Read-only human chat read: last N messages with author, Delivered/Read status.
- snap --since=<token> / wait-for-new-control; working chat cursor.
- `navigate --url=`.
- snap/find: --exposure, field values, highlight state, card titles, guide state.
- Reliable applied detection (or applied=unknown instead of false).
- Stable find by purpose/role regardless of dynamic label text (unread counts).

## Attributes / tagging for DOM control & filtering
- data-pkb-purpose on all panel controls (chat tab, pop-out, guide tab, send, retry, card options).
- Stable ids/labels independent of badge text; separate badge element (data-pkb-badge).
- data-pkb-highlight / data-pkb-guide-step on highlighted/guided targets, surfaced in snap.
- data-pkb-card-id + title + state (open/answered/timed-out) on cards.
- Message elements with data-pkb-msg-id/author/status for dedupe and read.

## Docs / instructions
- Warn that blocking waits stall the session; recommend non-blocking pattern.
- Document chat-send vs chat-turn semantics.
- Human-mode guide: polling cadence for short-lived cards, how to read agent messages, no upload path.
- Document applied=false semantics.
