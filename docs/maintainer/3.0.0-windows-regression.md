## Decisions

1. The first-read guide limit is 5120 UTF-8 LF bytes (`docs/release-notes.md`, `docs/ai-run-configuration.md`). The file is 5105 LF bytes and 5185 raw bytes with CRLF. The guide stays. Tests measure LF bytes.
2. A named browser is kept. `CHROME_HEADLESS` is only the fallback when the captured browser is blank (`WorkspaceSeed.browserOrHeadless`). Seed keeps `pkb_parallel=auto` while `pickleball.workspace.seed` is set. The estimator caps at 24, so a captured `80` is a leaked explicit value, not the estimate. Docs and the existing seed contract win over replacing `firefox` or `auto`.
3. `AgentControl` frame lookup goes through `ElementOperations`. It is not added to the DOM allowlist. `PrimaryPathAuditTest` stays as written.
4. Accept and dismiss work while a JavaScript dialog is open. A dialog blocks the CDP socket, so `Runtime.addBinding` is not sent on that socket before the dialog is handled. This is a product bug on every platform; Windows is where the suite caught it.
5. `ProcessTree.kill` kills the Windows process tree. `ProcessHandle.destroyForcibly` on the parent leaves children alive. POSIX keeps the current destroy path. Tests that need a live or already-exited process use a Java child, not `sleep`, `true`, or `sh`.
6. A Java launch whose command line can exceed the Windows 32767-character limit uses an argument file. `StoreTestProcesses` already does this for store children.
7. Composite stdio fakes are a Java stub launched by a platform script (`.cmd` on Windows, a shell script on POSIX). Tests do not call `Files.setPosixFilePermissions` on Windows. On POSIX the execute bit is still set, because that is how the fake is launched. No Python.
8. `SuiteDualRunTest` copies or creates a junction when creating a symbolic link is denied. The scenario comparison still runs.
9. Wrappers are `mvnw.cmd` / `gradlew.bat` on Windows and `mvnw` / `gradlew` elsewhere. Product code that launches `pickleball-workbench.sh` uses the `.cmd` opener on Windows. `PickleballLocalStore` already writes that `.cmd`.
10. The five Maven scenarios get a dedicated tag so they can be rerun without `cucumber.filter.name` pipes through `mvnw.cmd`. `CUCUMBER_FILTER_NAME` is not the supported path.
11. No assertion is weakened or deleted. An `assumeTrue` for POSIX mode bits is used only when that behavior cannot exist on Windows, and the same test then checks the Windows ACL. Every such guard is listed at the bottom of this file.
12. `StoreGradleForwardTest` passed alone. The failure text was the class name plus a console erase. The check strips CSI sequences. The expected class name stays `tools.dscode.store.StoreCli`.
13. Warm-JVM tests that fail only under parallel load are a race on the same kill path, not a timeout to stretch. The pid is published before the ready mark, the tree is killed, and the test waits on the process handle.

Assumption guards added so far: none.
