# Pickleball 3.0.0 Query-Visual Design

**Status:** Implemented on branch `3.0.0`. This page describes the Control Engine query language as it behaves now (`dev.domengine.query` and the dictionary layer). `capabilities.display_name` is `Control Engine`. The CLI help first line is `domengine <version> — Control Engine for browsers and Windows, macOS and Linux desktops`.

## Locked direction

One query language for browsers and for Windows, macOS, and Linux desktops. The syntax layer parses and evaluates. The dictionary layer turns a phrase or a category into that syntax and keeps XPath as a fallback. Workbench, MCP, and Gradle only forward.

### Boolean combination

`>>` stays a sequential pipeline. Each stage receives the previous node set. `AND` is the intersection of the two sides applied to the same scope. `OR` is the union. `NOT` is the complement of the current scope. Parentheses outrank `NOT`, then `AND`, then `OR`. `>>` is the lowest precedence, outside the parentheses. Mixed `AND` and `OR` at the same level require parentheses.

Capitals are canonical. `Expressions.render` prints `AND`, `OR`, and `NOT`. A lowercase `and`, `or`, or `not` is still accepted. The first time each lowercase operator is seen in the process, the engine logs one warning: `lowercase operator 'and' read as AND; write capitals`. Quoted operator words are not operators. `DOMENGINE_LOG=expr` or `COMPOSITE_LOG=expr` logs evaluation and stays off unless the entity is named. The log is date-stamped and size-capped.

`domengine query --selector` and `--pipeline` both accept the expression. Example: `(css=button AND text="Submit") >> near=50`. Selenium fallback returns null for `AND`, `OR`, `NOT`, and for a relation form. A single `css=` or `xpath=` stage can still run on Selenium.

### Relations

Eight relations: `near`, `below`, `above`, `left-of`, `right-of` (`left` and `right` are aliases), `inside`, `after`, and `before`.

Stage form is a pipeline stage. `css=#anchor >> inside=button` uses the previous stage as the anchor set. `near=50` is a numeric limit, not an anchor query. Filter form is `<relation>(<anchor query>)`. The anchor is a full sub-query from the root, and the relation then filters the current scope. Example: `(role=button AND text="Save") AND after(role=region AND text="Billing")`. `in`, `from`, and `for` stay `<context> >> <target>`. The other context words (`after`, `before`, `above`, `below`, `left of`, `right of`, `near`, `inside`) become that filter form.

Geometry uses the document CSS-pixel box, or `visual_viewport_relative` when `--exposure human` and that box was stored. A candidate must have a box and be displayed.

- `above`: the candidate bottom is at or above the anchor top.
- `left-of`: the candidate right edge is at or left of the anchor left.
- `right-of`: the candidate left edge is at or right of the anchor right.
- `below` and `near` keep the geometry they already had. Hits sort by center distance.
- `inside`: the candidate box lies fully inside an anchor box (edges may touch). Hits sort by the smallest containing anchor area, then document order.

`after` is document order, XPath `following::`: the candidate follows an anchor and is not its descendant. `before` is `preceding::`: the candidate precedes an anchor and is not its ancestor, nearest first. Neither needs a box, so both work on a desktop tree in capture order. An anchor sub-query that matches nothing yields no hits for a positive relation.

Negatives drop candidates that satisfy the positive relation. `not-near=div`, `not-near(text="Cancel")`, `NOT near=div`, and `NOT near(text="Cancel")` are the same filter. `NOT` around any other expression stays the complement of that expression. `NOT not-near(x)` is invalid. An anchor that matches nothing keeps every candidate when the relation is negated, and `--explain` says `anchor matched 0`. The trace engine name is `not-near`.

A weight is `near@2` or `inside@0.5(role=dialog)`. It is stored on the term (`weight()`). The filter does not use it. `@1` is omitted from `canonical()`. `--explain` adds `relations`: each term's `relation`, `negated`, `anchor`, and `weight`.

`RelationTerm.parse` reads one filter-form term. `RelationTerm.parseAll` lists every term in a pipeline, including stage form (`css=#a >> near=input`). The grammar is:

```
term    := ["NOT" ws] ["not-"] relname ["@" weight] "(" anchor ")"
relname := near | above | below | left-of | right-of | left | right | inside | after | before
weight  := a decimal >= 0
anchor  := balanced text, quotes respected, then trimmed
```

`DOMENGINE_LOG=relation` records `anchors`, `candidates`, `kept`, and the space. It stays off unless named.

### Visual property: look

The engine name is `look`. It is not `attribute`, `style`, or `visual`. A stage is `look=color=red` or `look=opacity>0.5,background-color=#fff`. A comma is AND and a pipe is OR inside the stage. Neither splits inside quotes or parentheses, so `rgb(255, 0, 0)` stays one value. Named colors, `#rgb`, `#rrggbb`, and `rgb()` / `rgba()` compare as the same color. Numeric tests use doubles. `contrast` is the contrast of `color` against the first opaque painted `background-color` (canvas white when none is painted). It is not a screenshot match. There is still no engine named `attribute`.

A step may add `with look <prop> <predicate>` after the attribute clause, for example `with look color equaling red` or `with look opacity greater than 0.5`. `SelectorTranslator` maps that clause to a `look=` stage on the same query string. `with id attribute` and `with id noattribute` are unchanged. Cucumber step annotations stay single string literals. Several `with look` clauses joined by `and` become one comma group. `or` becomes a pipe. `pkb_composite_log=query` writes `forward selector=` and stays off unless named.

A stored computed-style map wins over the style attribute. Offline HTML uses the style attribute. Only inherited properties (`color`, `font-*`, `visibility`, and the other CSS inherited longhands) walk to ancestors. `display` and `background-color` do not inherit. The search is the light tree, the same tree `a11y` uses. `font-weight=700` matches `bold`.

On the production find, `LookFind` runs the same `(role AND look)` string through `Query` and keeps only the XPath hits that survive. `pkb_composite=off` fails the find instead of ignoring look. `DOMENGINE_LOG=look` records the matched properties and stays off unless named.

### EngineQuery and adapters

`EngineQuery` does not grow new fields. Boolean operators, relations, and look stages are text in `query.text()`. `DomCompositeAdapter` and `PageElementQuery.find(EngineQuery)` forward that string. Workbench, MCP, and the control bridge only forward the object.

`EngineQuery.seleniumFallback` returns null when the text has `>>`, a relation form (stage or filter, including a negative), or a leading expression (`Query.leadingEngine` is `expr`). A single `css=` stage, `xpath=` stage, a `//` path, or plain CSS still becomes a Selenium `By`. `visualRelative` recognizes the geometric names, including filter form `name(`. `after` and `before` are document order and are not visual relatives.

A phrase that also carries XPath sends both the pipeline and the XPath. `CombinedBy` finds through the XPath, so `pkb_composite=off` is unchanged.

### Layers

The syntax layer is `dev.domengine.query`. It may use `CdpException`, image, json, log, and tree. `QueryHooks` is the only file in that package that imports pre-map or affinity types. The live connection type stays in `LiveXPath` and in the xpath method of `Engines`.

The dictionary layer is `SelectorTranslator`, `CompositeSelector`, `EngineQuery`, `CombinedBy`, `XPathDefinitions`, and `ExecutionDictionary`. `LookFind` is the adapter-side bridge and reads page source through WebDriver. `ElementPhrase` and `VerbPlan` stay data carriers. Boundary tests reject a protocol import in either layer. Protocol drivers are not queried from the dictionary.

### Combined form and XPath fallback

`xpath=` is one clause. It can sit inside `AND`, `OR`, `NOT`, and `>>`. A query body that carries both a pipeline (`pipeline`, `expr`, or `selector`) and `xpath` runs the pipeline first. The XPath runs once, from the same root, only when that pipeline matches nothing. The result then has `"fallback": "xpath"`, and `--explain` adds a stage whose `why` is `fallback: combined matched 0`. The engine logs one `WARN query xpath fallback …` per distinct XPath per process.

`SelectorTranslator.phrase` emits the combined form. Target clauses (`role`, state, text, `look`, `css=`) are one AND group. Context clauses are another. A pure XPath definition sends only `xpath` and logs one deprecation warning per run and definition (`xpath-definition:<category>`). The definition still resolves. Pure CSS stays a `css` pass-through and is not deprecated.

`ExecutionDictionary.CategorySpec.combined(clause)` stores the engine clause. `combinedFor` adds the text predicate the operator can express. XPath builders still work. They are deprecated for a new definition that can be written as a combined clause. Built-in categories that have no faithful engine clause stay XPath and do not warn.

### Universal syntax

Browsers and desktops run the same query string through `Query.run`. `capabilities.platforms` is computed from `PageActions.VERBS`, `Query.QUERY_FLAGS`, `DesktopTree.VERBS`, and `NativeDesktop.verbs`. Desktop verbs today are click and type on `uia`, `ax`, and `atspi`. Desktop rejects `pierce`, `frame`, and `shadow`. Scroll, key, double-click, context-click, drag, and hover are listed under `platforms.desktop.unsupported` with the platform API that is not called yet. The same gap table is in the Group 2 roadmap.

### Pre-map and scoring hooks

`Query.run` calls `QueryHooks` once at each seam. `premap` runs before the stage loop. A `--session` flag asks `PreMapLookup.installed().current(session, doc-version)` once. That lookup is still a pass-through, so `current` is empty and the log says `premap=none`. An offline tree uses `PreMapLookup.forTree`. Each searchable stage then calls `candidates` once, from `Expressions`. A present id list keeps the hits that are in it. An empty list, or a list that matches none of the hits, leaves the engine hits unchanged.

`rank` runs after the stages and the XPath fallback, and before `within`, `nesting`, and `nth`. Order stays the engine order, and `--explain` sets `rank` to the string `"distance"`, unless a session pre-map came back or the flag is `--rank affinity`. Affinity scores each hit as the maximum of `AffinityScorer` over the anchors recorded while relations evaluated, then sorts descending. The previous order breaks ties. `--explain` then shows `rank.mode` `affinity` and one score per hit: `handle`, `total`, `parts`, `reasons`. A negated relation that the hit still satisfies lowers that total. The offline `forTree` index does not turn ranking on by itself, so a pass-through query keeps its old order.

`--strict` calls `one`. It builds a `Candidate` per remaining node (handle, role, accessible name, text of at most 40 characters, box, and the affinity score when rank stored one) and calls `OneMatch.resolve`. The policy is `Policy.resolve(0.15, no exempt roles)`, or `Policy.act` when the caller sets `__act=true`. Zero nodes throw `not found`. Two or more unscored nodes throw a message that starts with `ambiguous: N candidates`. The CLI JSON has `ok: false`, that message, `code` `ambiguous` or `not_found`, and the `candidates` array. `DOMENGINE_LOG=query` writes `premap=<hit|none> rank=<mode> one=<ok|error>`.

## Backward compatibility

Existing `>>` pipelines keep the same meaning. Existing a11y `|` and `,` groups are unchanged. CSS, XPath, and attribute matching are unchanged. Gherkin phrases are unchanged. The new relation filter is what the translator emits for the context words above. It does not add a Gherkin word. YAML Selenium browser configs and the ordinary Selenium path are unchanged. `pkb_composite=off` still finds by XPath. Logging stays off by default.

## Breaking-change list

None. No existing Gherkin token was removed. Cucumber step annotations stay single string literals.

## Implementation status

The Control Engine query language on `3.0.0` includes boolean combination with the lowercase alias, all eight relations in stage form and filter form, negatives and weights, `look`, the combined form with XPath fallback, the two layers, and the pre-map, rank, and one-match hooks. `QueryHooks` is the only query file that imports pre-map or affinity. G3's lookup is still a pass-through. Desktop click and type are wired. The other desktop verbs are reported as unsupported and are not invented.
