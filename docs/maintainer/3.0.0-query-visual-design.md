# Pickleball 3.0.0 Query-Visual Design

**Status:** Design locked 2026-11-12. Implementation on branch `3.0.0-query-visual` only (off tip of origin/3.0.0). Do not push to 3.0.0 itself.

## Locked Direction

Additive, backward-compatible extension of the Java engine query language (`dev.domengine.query`) and the Pickleball EngineQuery / dynamic-step path.

### Boolean Combination (AND / OR / NOT)
- Existing `>>` pipeline remains pure sequential: each stage receives the previous node set and returns the next set. Semantics unchanged.
- Boolean operators are an expression layer that combines node-set results of stages or parenthesized sub-expressions.
- Precedence: parentheses highest, then NOT, AND, OR; `>>` is lowest (outer sequential pipeline).
- AND is intersection of the node sets produced by each side applied to the same starting scope (or previous stage result). OR is union. NOT is complement relative to the current scope.
- Parentheses required for mixed expressions to avoid ambiguity. EngineQuery.seleniumFallback already returns null on AND/OR/NOT, so Selenium path is unaffected.
- CLI: `domengine query --selector "(css=button AND text=\"Submit\") >> near=50"` or equivalent flags.

### Visual Relatives (above, left-of, right-of)
- New pipeline engines parallel to existing `near` and `below`.
- Geometry: bounding box in document_css_px (or visual-viewport-relative when exposure=human). Requires hasBox and displayed.
- Definitions (consistent with below):
  - above: candidate.y + candidate.height <= anchor.y
  - left-of: candidate.x + candidate.width <= anchor.x
  - right-of: candidate.x >= anchor.x + anchor.width
- Sort by distance (like near). Pierce/shadow/frames as today. near and below unchanged.
- EngineQuery.visualRelative already recognizes them; engine now implements.

### Visual Property: "look"
- Name chosen: **look** (not "attribute", "style", or "visual").
- Reasons: zero collision with step-grammar existence keyword "attribute"/"noattribute", with CSS/XPath/a11y treating "attribute" as a real HTML attribute name, or with existing engines. Natural English ("the button that looks red").
- What it measures: computed style properties (color, background-color, opacity, display, visibility, font-size, font-weight, etc.) plus simple derived metrics (e.g. contrast if cheap to compute). Not screenshot pixels (image engine already covers template matching).
- Engine syntax (pipeline stage): `look=color=red` or `look=opacity>0.5,background-color=#fff` (comma AND, pipe OR inside the stage, similar to a11y).
- Pickleball step text: additive only. New optional clause "with look <prop> <predicate>" (e.g. "with look color equaling red" or "with look opacity greater than 0.5") that SelectorTranslator / adapter maps to a look= stage. Existing "with id attribute" / "with id noattribute" and all Gherkin unchanged. Cucumber annotations remain single string literals.

### EngineQuery and Adapters
- EngineQuery record does **not** grow. The Java engine simply honors more of the existing `query.text()` language (Boolean operators, the three new relative engines, and look stages).
- DomCompositeAdapter.findEngine / queryEngine and PageElementQuery.find(EngineQuery) continue to forward `query.text()` as the selector string. No new fields required on the wire.
- CLI-first: every new capability reachable from `domengine` CLI. Workbench / MCP / Gradle only forward.

### Backward-Compatibility Guarantees
- Existing `>>` pipelines keep identical meaning.
- Existing a11y `|` (OR groups) and `,` (AND predicates) unchanged.
- CSS/XPath/a11y attribute matching unchanged. There is still no engine named "attribute".
- Dynamic-step grammar and all existing Gherkin phrases unchanged. New look syntax is purely additive.
- YAML Selenium browser configs and the ordinary Selenium path unchanged.
- Element-type dictionary / XPathyAssembly unchanged.
- Logging remains off by default, toggleable, per-entity, date-stamped, size-capped (COMPOSITE_LOG / DOMENGINE_LOG, 10 MB front-trim).

## Implementation status

Phase 2 adds engines `above`, `left-of`, and `right-of`. `left` and `right` are aliases of `left-of` and `right-of`. The locked edge tests are unchanged. A candidate must have a box and be displayed. Hits sort by center distance. `near` and `below` are unchanged and stay on document boxes. `exposure=human` uses `visual_viewport_relative` when that box was stored; otherwise the document box is used. Shadow and frame reach is the same `css` search `near` and `below` already use. `DOMENGINE_LOG=visual` or `COMPOSITE_LOG=visual` records the geometry space and ranked count. That log stays off unless the entity is named.

Phase 3 adds the `look` engine. The name is not `attribute`, `style`, or `visual`. A stage is `look=color=red` or `look=opacity>0.5,background-color=#fff`. A comma is AND and a pipe is OR, and neither splits inside quotes or parentheses, so `rgb(255, 0, 0)` stays one value. Named colors, `#rgb`, `#rrggbb`, and `rgb()`/`rgba()` compare as the same color. Numeric tests use doubles, so `opacity>0.5` and `font-size>12` work, and `font-weight=700` matches `bold`. `contrast` is the WCAG ratio of `color` against the first opaque `background-color` (canvas white when none is painted). A stored computed-style map wins over the style attribute. Offline HTML uses the style attribute, and only inherited properties (`color`, `font-*`, `visibility`, and the other CSS inherited longhands) walk to ancestors. `display` and `background-color` do not inherit. The search is the light tree, same as `a11y`. `DOMENGINE_LOG=look` records the matched properties and stays off unless named.

Phase 4 leaves `EngineQuery` the same size. `DomCompositeAdapter.findEngine` / `queryEngine` and `PageElementQuery.find(EngineQuery)` still forward `query.text()`. The element-match pattern keeps the attribute group and adds an optional `with look <prop> <predicate>` group after it. `with id attribute` and `with id noattribute` stay in the attribute group. `SelectorTranslator` turns the new clause into `look=color=red` or `look=opacity>0.5` and ANDs that stage with the target role. Several look clauses joined by `and` become one comma group; `or` becomes a pipe. `pkb_composite_log=query` writes `forward selector=` and stays off unless named. No new CLI flag.

Phase 5 audit: no existing token was reinterpreted. `>>` is still the outer sequential pipeline. `near` and `below` are unchanged. a11y `|` and `,` are unchanged. There is still no engine named `attribute`. The breaking-change list stays empty. Targeted checks were BooleanQueryTest 6, VisualRelativeTest 4, SelectorParityTest 2, LookQueryTest 4, LookStepTest 2, SelectorAndAdapterTest 5, and Release216BehaviorTest.parsedButtonMatchingKeepsTheFullPattern 1, all with 0 failures. The full multi-module regression was not run.

Fix-back 1 closes the live-find gap. `ElementMatch.lookClause` is read by `ContextWrapper.getElements`, `getElementListFromSearchContext`, and the spatial `findAll` path. `LookFind` builds the same `(role=… AND look=…)` string `SelectorTranslator.phrase` already builds, runs it through `dev.domengine.query.Query`, and keeps only the XPath hits that survive. Attribute and noattribute grammar stay on that XPath. `pkb_composite=off` throws instead of matching on XPath alone. `EngineQuery.seleniumFallback` is not used for a look stage. `EngineQuery` is not grown. The breaking-change list stays empty.

### RelationTerm contract

`dev.domengine.query.RelationTerm` exists for G3's affinity scorer (`relation()`, `negated()`, `anchor()`, `weight()`). The `query` verb does not accept relation-term syntax yet: `not-near=…` and `near(…)` are still rejected with `invalid engine`. One filter-form term is:

```
term    := ["NOT" ws] ["not-"] relname ["@" weight] "(" anchor ")"
relname := near | above | below | left-of | right-of | left | right | inside | after | before
weight  := a decimal >= 0
anchor  := balanced text, quotes respected, then trimmed
```

`RelationTerm.parse` reads one such term. `RelationTerm.parseAll` lists every term in a pipeline, including stage form (`css=#a >> near=input`). Production `Expressions.parse` is unchanged.
