## Decisions for non-implemented rows

### 1. Browser facade over Selenium, Playwright, raw CDP + wide ranges
**Decision:** Introduce a thin `BrowserFacade` interface in `tools.dscode.browser` (or extend existing). Adapters: `SeleniumAdapter` (default scripted lifecycle + elements), `PlaywrightAdapter` (optional, wide version range via Gradle constraints `[1.40,2.0)`), `CdpAdapter` and `BidiAdapter` (agent-only). Scripted path uses library adapters by default.
**Approach:** Facade methods for lifecycle, find, click, type, snapshot. Protocol adapters implement them. Wide ranges in build.gradle.
**Files:** new facade classes, build.gradle deps, ElementOperations to prefer facade.
**Tests:** FacadeUnitTest, SeleniumAdapterTest, PlaywrightAdapterTest (optional).
**Docs:** configuration.md, getting-started.md, README update.

### 2. Libraries default for scripted; direct for agents + warn
**Decision:** Reverse current default. `pkb_composite` default becomes `off` or library-first. Direct CDP/BiDi only for agent sessions via MCP or explicit agent flag. Any fallback to direct in scripted logs WARN.
**Approach:** Change EngineConfig / CompositeRuntime default. AgentControl owns direct path.
**Files:** configuration, CompositeRuntime, AgentControl.
**Tests:** DefaultPathTest (scripted uses library), FallbackWarnTest.
**Docs:** all places stating composite as default.

### 3. Java owns agent protocol control (separate boundary)
**Decision:** Separate `AgentProtocolController` (Java) behind MCP. Scripted ElementOperations never call direct protocols.
**Approach:** MCP tools call AgentProtocolController which uses CdpAdapter/BidiAdapter.
**Files:** new controller, MCP handlers, ElementOperations guard.
**Tests:** AgentBoundaryTest.
**Docs:** dynamic-control-api.md, AGENTS.md.

### 4. WebDriver BiDi as Firefox path
**Decision:** Implement BiDi adapter for Firefox using Selenium BiDi client or raw WebSocket. Firefox uses BiDi; Chrome/Edge use CDP.
**Approach:** BidiAdapter in facade. Detect browser and select protocol.
**Files:** BidiAdapter.java, facade selection.
**Tests:** FirefoxBidiTest (live or fake).
**Docs:** configuration.md browser section.

### 5. MCP as single agent entry point
**Decision:** MCP is the sole public agent entry. Predefined parameterized commands (query, click, snapshot, observe, launch, etc.). Other paths become internal.
**Approach:** Expand MCP server in workbench/dom-engine to cover all agent needs. Document as the entry.
**Files:** MCP handlers, docs.
**Tests:** McpCommandTest.
**Docs:** pickleball-workbench.md, dynamic-control-api.md.

### 6. Control engine unifying browsers + desktops
**Decision:** Keep Java dom-engine as the Control Engine. Update naming in docs to "Control Engine" (unifying). No package rename required.
**Approach:** Docs update + capability reporting.
**Files:** AGENTS.md, README, configuration.md.
**Tests:** existing conformance.
**Docs:** all control references.

### 7. Layered architecture: syntax / dictionaries / protocol adapters
**Decision:** Formalize three layers: SyntaxLayer (query/Gherkin parser), DictionaryLayer (category mappings to combined selectors), ProtocolAdapterLayer (Se/PW/CDP/BiDi/Desktop).
**Approach:** Document and minor refactoring to clarify boundaries.
**Files:** architecture docs, possibly package moves.
**Tests:** existing query tests.
**Docs:** new architecture section or update AGENTS.

### 12. Scored label affinity
**Decision:** Implement scored affinity: score = distance weight + role match + text similarity + negative penalties. Labels bind via highest score.
**Approach:** New AffinityScorer in query package. Use in pre-map and runtime.
**Files:** AffinityScorer.java, query integration.
**Tests:** AffinityScoreTest.
**Docs:** query-visual-design.md update.

### 13. Negative relations
**Decision:** Support not-near, not-inside, not-above, etc. as negative operators that apply score penalties or filters. Feeds affinity scoring.
**Approach:** Extend expression parser and Engines for negative relatives.
**Files:** Expressions.java, Engines.java.
**Tests:** NegativeRelationTest.
**Docs:** query design.

### 14. Bounding boxes with size caps and one-match rule
**Decision:** Size caps on boxes in pre-map (configurable max area/width/height). One-match rule: query resolves to exactly one or returns error with why (candidates listed).
**Approach:** Add caps in geometry; enforce in resolution.
**Files:** DomNode / Query resolution.
**Tests:** BoxCapTest, OneMatchTest.
**Docs:** geometry section.

### 15. Section detection
**Decision:** Detect sections via headings, ARIA landmarks, roles, nesting in snapshot pre-map.
**Approach:** SectionDetector in snapshot production.
**Files:** SectionDetector.java, snapshot builder.
**Tests:** SectionDetectionTest.
**Docs:** snapshot design.

### 16. Universal composite snapshot on all 7 platforms
**Decision:** Build CompositeSnapshot artifact that combines screenshot + structure + paths + viewport mapping for Chrome/Chromium/Edge (CDP), Firefox (BiDi), Windows UIA, macOS AX, Linux AT-SPI. Use existing pieces; add desktop screenshot where platform allows.
**Approach:** New CompositeSnapshot class; platform-specific producers. Builds on engine-defects attach fixes.
**Files:** CompositeSnapshot.java, platform producers.
**Tests:** SnapshotCoverageTest per platform (targeted).
**Docs:** new snapshot.md or update.

### 17. Pre-mapping as CORE principle
**Decision:** Snapshot production always pre-maps: labels to interactables (via affinity), sections and nesting, bounding boxes (with caps), viewport coordinates, XPath indexes, image and color features. Runtime queries are light lookups against the pre-map. This is mandatory, not optional.
**Approach:** Integrate pre-map into CompositeSnapshot builder. Queries prefer pre-map.
**Files:** PreMapBuilder.java, query path changes.
**Tests:** PreMapTest, QueryUsesPreMapTest.
**Docs:** emphasize as core in AGENTS and snapshot docs.

### 18. Dalton central rather than opt-in
**Decision:** Flip to central: default `pkb_dalton=true` (or always on for new projects). Files remain Git source of truth; DB is the working copy for runs and edits. Opt-out via explicit false. Update all docs.
**Approach:** Change default in config resolution. Auto-hydrate on start.
**Files:** configuration, Dalton init, all docs.
**Tests:** DaltonDefaultOnTest.
**Docs:** AGENTS.md, README, configuration.md, dalton-design.md.

### 19. Rust to Java (no residuals)
**Decision:** Fully remove residual Rust support after Java parity confirmed (post engine-defects). Drop `pkb_composite_engine=rust`, remove vendored `dev.domcomposite` client and native classifier lookups.
**Approach:** Remove code paths and docs. Java only.
**Files:** build.gradle, CompositeRuntime, configuration, AGENTS.
**Tests:** NoRustLeftTest (no references).
**Docs:** remove all Rust override mentions.

**Approach:** none.

## Owner addendum items

### A. Agent in-page surfaces (PageSurfaces) to direct CDP/BiDi by default
**Decision:** PageSurfaces (html-write/replace/insert/overlay/remove/cleanup and overlay event capture) move to direct CDP by default on Chromium: `Page.createIsolatedWorld` for isolated injection context, `Page.addScriptToEvaluateOnNewDocument` for re-injection after navigation, `Runtime.addBinding` for push-based click/form events (no polling), `DOM.*` for structural writes. On Firefox use WebDriver BiDi equivalents (`script.addPreloadScript`, sandboxed `script.callFunction`, channels). Selenium `executeScript` only as a logged last-resort fallback. Keep all existing sanitizing, labeling, undo and cleanup behavior and tests.
**Approach:** Update PageSurfaces implementation to prefer protocol adapters. Fallback path logs WARN.
**Files:** PageSurfaces.java, CdpAdapter, BidiAdapter.
**Tests:** existing PageSurfaces tests plus new IsolatedWorldTest, BindingEventTest, FallbackLogTest.
**Docs:** direct-control-handoff.md, configuration.md.

### B. Universal agent surface popup
**Decision:** On Windows, macOS and Linux desktop sessions (and optionally for browsers), pickleball opens a small app-mode browser window (Chromium `--app` or equivalent, always-on-top where the OS allows) that hosts the agent chat, instructions and diagrams using the same HTML surface code and command set. Experience is identical on every platform. A thin native highlight box is kept only for pointing precisely at a native control.
**Approach:** New AgentSurfacePopup that launches app-mode Chromium and loads the shared HTML surface. Native highlight remains for desktop precision.
**Files:** new AgentSurfacePopup.java, desktop integration.
**Tests:** AgentSurfacePopupTest (launch and content check).
**Docs:** workbench.md, direct-control-handoff.md.
