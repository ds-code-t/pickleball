## Gaps list

- No single browser facade; Playwright completely absent; Selenium pinned narrowly.
- Direct CDP (via Java engine) is the default element path for scripted tests, not reserved for agents.
- No agent-only protocol boundary.
- No WebDriver BiDi.
- MCP is a forwarder, not the sole agent entry point.
- Pre-mapping as a core principle is missing.
- Dalton remains opt-in (not central).
- Residual Rust override, vendored client, and native lookups remain.
- XPath remains primary passthrough rather than equal clause with combined-form emission and fallback.
- Scored affinity, size-capped one-match bounding boxes, section detection, and fully universal multi-platform composite snapshots are incomplete or absent.
- Layered architecture does not match the exact syntax/dictionaries/protocol-adapters structure.

## Stale or contradicting doc lines

- AGENTS.md (Dalton section): "Dalton is opt-in... not central, not the core, and not the default" — contradicts "Dalton central rather than opt-in".
- README.md: Dalton described as opt-in; Selenium + Java engine only — contradicts facade and central Dalton.
- docs/configuration.md: `pkb_composite=auto` default uses Java engine; Dalton off unless `pkb_dalton=true` — contradicts libraries-default and central Dalton.
- docs/release-notes.md: native default, Java engine default, Dalton opt-in — same contradictions.
- docs/maintainer/3.0.0-dalton-design.md: explicitly opt-in, files source of truth.
- docs/direct-control-handoff.md and configuration.md: document `pkb_composite_engine=rust` override — contradicts "no Rust left".
- Multiple docs (README, getting-started, dynamic-steps, configuration) describe Selenium/Java-CDP paths without a facade over Playwright/raw CDP.
- Prior audit (`3.0.0-locked-decisions-prior-audit.md`) correctly flagged many of these; current tip remains consistent with those findings on the above points.
