### Grouping reasoning (from the code)

- **G1 = everything that decides *which wire* talks to a browser.** Rows 1–5 and A all land in the same seams: `CompositeRuntime` attach/default selection, `ElementOperations` path choice, `PageSurfaces` (which today drives CDP through Selenium's reflective `executeCdpCommand`, `PageSurfaces.java:925-934`, and falls back to `executeScript`, `:709`, `:1445`), the MCP servers (`dom-engine/.../mcp/McpServer.java`, `pickleball-workbench/.../mcp/WorkbenchMcp*.java`), and the Selenium pin in `build.gradle:195`. Addendum A needs exactly the CDP/BiDi adapters rows 1/3/4 create, so it belongs here, not in G4.
- **G2 = the query language.** Rows 6–11 and 13 all live in `dom-engine/src/main/java/dev/domengine/query/` (`Expressions.java` parses AND/OR/NOT, `Engines.java` holds engines and relatives, `Query.java` resolves) and the root dictionary/translator (`SelectorTranslator.java`, `ExecutionDictionary.java`). Row 13 (negative relations) is a parser/AST change in `Expressions`/`Engines`, so it sits with G2 even though it *feeds* G3's scoring; the AST term is the contract.
- **G3 = what a snapshot contains and what is pre-computed.** Rows 12, 14–17 are all producer-side: a new `CompositeSnapshot` + pre-map, section detection, box caps, scored affinity, and per-platform producers (`desktop/AtSpi.java`, `WindowsUia.java`, `MacAccessibility.java`, `DesktopTree.java`, root `seleniumextensions/CompositeSnapshotProducer.java` and `SnapshotProducers.java`). Row 12 (scoring) is kept with pre-map because the pre-map is where labels bind to interactables; runtime reuses the same scorer. Row 14's one-match rule is enforced by a G3-owned resolver that G2's `Query` calls at one hook (see contracts).
- **G4 = product surfaces and cleanup.** Addendum B (popup) is Workbench/desktop UI (`pickleball-workbench/.../ui/AgentChatPanel.java`, `WorkbenchNativeOverlay.java`, `ui/web/`), row 18 is `src/main/java/tools/dscode/dalton/DaltonConfig.java` (`enabled()` currently needs `pkb_dalton=true` or `dalton.properties enabled=true`), row 19 removes the Rust override from `dev/domcomposite/Client.java`, `CompositeBinaryLocator.java`, `CompositeRuntime.java:29`, `JavaEngineLauncher.java`, `DirectControlProvider.java`, `build.gradle`. Rows 20–22 are confirm-only. The docs sweep is last because it must describe what G1–G3 actually shipped.

## 4. Interface contracts between groups

Contracts are the only way a group touches behaviour another group owns. The **owner creates the contract type first** (a small, compiled, tested commit), then consumers use it. Names below are binding unless the owning Heavy renames them and updates this file in the same push.

1. **G1 → G3, G4: `BrowserFacade` and protocol adapters** (`tools.dscode.browser`). Minimum: `ProtocolSelector.forDriver(WebDriver)` → `CdpAdapter` (Chrome/Chromium/Edge) or `BidiAdapter` (Firefox) or Selenium fallback; adapter methods `send(method, params)`, `evaluateIsolated(worldName, fn, args)`, `addPreload(script)`, `addBinding(name, listener)`, `screenshot(options)`, `frameTree()`. Every Selenium fallback emits one WARN per run and reason. G3 producers and G4's popup use only these, never reflective `executeCdpCommand`.
2. **G1 → G4: MCP command registry.** G1 makes MCP the single agent entry with a registry (`McpCommand` name, JSON-schema params, handler). G4 registers popup commands (chat, instructions, diagram, highlight) by adding its own command classes; it does not edit G1's server classes.
3. **G1 → G4: shared HTML surface.** G1 keeps the PageSurfaces HTML/CSS/JS surface assets in one location with a loader API (`SurfaceAssets.html(kind)` or equivalent). G4's popup loads the same assets so the chat/instructions/diagram experience is identical in page and popup.
4. **G2 → G3: query AST.** G2 publishes `dev.domengine.query.RelationTerm` (record: `relation` enum incl. `NEAR, ABOVE, BELOW, LEFT_OF, RIGHT_OF, INSIDE, AFTER, BEFORE`; `negated` boolean; `anchor` sub-query; optional `weight`). Parsed from both positive and `not-<relation>` / `NOT <relation>` syntax. G2 lands this record (and its parser tests) in its first phase.
5. **G3 → G2: pre-map and scoring hooks.** G3 publishes `dev.domengine.premap.PreMapLookup` (`Optional<PreMap> current(sessionId, docVersion)`; `candidates(clauseKind, value)`), `dev.domengine.affinity.AffinityScorer` (`score(label, interactable, List<RelationTerm>) -> double` with explainable parts), and `dev.domengine.premap.OneMatch` (`resolve(candidates) -> exactly one | error listing candidates and why`). G2's `Query` calls these at one place each. Until G3's real implementations land, G3 ships no-op/pass-through defaults in its first phase so G2 never blocks.
6. **G3 → G1: snapshot command.** The MCP `snapshot` command (G1) returns G3's `CompositeSnapshot` JSON; G3 owns its schema (`docs/snapshot.md`).
7. **Engine-defects → all:** after engine-defects Phase 1, every attach is pinned to a page target; consumers rely on `CompositeRuntime.focusPage`/`focusedCdp` semantics as documented in `docs/direct-control-handoff.md`. No group re-implements attach.

## 6. Shared merge rule (every Build)

1. Work on `3.0.0` directly. Small commits, one logical change each, push after every change.
2. `git fetch origin && git rebase origin/3.0.0` before every push. Resolve conflicts only inside your own files; if a conflict is in another group's file, stop and report instead of editing it. Never force-push.
3. Never edit another group's owned files except through section 4's contracts. Never edit files the running engine-defects Build holds until that Build's gating phase is pushed and verified.
4. Before pushing docs: `python3 scripts/refresh_agent_index.py`, then `python3 scripts/refresh_agent_index.py --check` and `python3 scripts/sync_consumer_guidance.py --check` must pass. Never hand-edit `docs/agent/repository-index.md`.
5. Short targeted tests per phase only (named classes, `--tests` filters). No full regression until the integration gate. Do not run `validate --all`, first-start timing, or Maven `@all`.
6. Don't change existing Gherkin syntax. Don't weaken, skip, or delete tests. Cucumber annotations stay single string literals with identical values.
7. Docs and `AGENTS.md` are rewritten in place to describe only current implemented behaviour. `AGENTS.md` is not append-only. Remove stale Rust and superseded wording; history goes to `docs/release-notes.md`. Never overwrite a doc with a placeholder or an empty file.
8. CLI-first and logging checklist (engine-defects design): every new engine capability works from the `domengine` CLI first; Workbench, MCP and Gradle forward; logging is toggleable, per entity, date-stamped and size-capped.
9. After each push, verify the file contents on `origin/3.0.0` (`git show origin/3.0.0:<path> | wc -c`) and check CI for that SHA.
