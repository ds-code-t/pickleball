# 3.0.0 collaboration fixes roadmap

**Status:** in progress on `3.0.0-collab-fixes`. Base is origin/3.0.0 `d265a018` plus evidence commit `0b5c8131`.

**Goal:** two actors can share one headed `start` session. The agent uses control verbs. The human uses only doctor, snap, find, act, wait, and capture. A long wait must not freeze the other actor. Snap and find must show the collaboration state the person can see. Clicks, keys, chat, guides, and file hand-off must report what actually happened.

Evidence: `docs/maintainer/3.0.0-collab-test/` (`findings-2026-11-23.md`, `agent-notes.md`, `human-notes.md`, `helper-brief.md`, `plan.md`). Session `livedce7825a2acd`.

## Design decisions

**C1 wait lane.** `com.sun.net.httpserver.HttpServer` with a null executor runs every request on the dispatcher thread. One blocking handler stalls `/health` and every other verb, and the 2 s doctor timeout becomes `health=down`. The host uses a small daemon pool. Page work runs on one command lane (`HostLanes`). Blocking waits (`ask-and-wait` without `--async`, `answer-wait`, `ui-poll` when it waits, `chat-turn`, `chat_wait`, `wait`, `wait-for`, `watch`) increment `waits` and poll on an HTTP pool thread, not on the command lane. The sleep never takes that lane. A page call from the wait shares the CDP lock with the command lane and returns. `ask` already returns an id. `ask-and-wait --async` places the same card and returns `op=ask-and-wait`, `async=true`, and `id` with no wait. A bare `--async` does not consume the next token. `--async=false` stays blocking. `answer-wait --id=` polls the stored answer on the wait lane and returns the same fields as a finished `ask-and-wait` (`id`, `value`, `choice`, `applied`). `ui-poll --id=` returns that answer when it is already stored, and waits only when `--wait` is set, still off the command lane. `/health` never takes the command lane and does not probe CDP while `waits` is greater than zero and the Chrome pid is alive, so the 2 s doctor read cannot time out on the lock. It adds `waits=<n>` and stays `status=ok`. Doctor prints `waits=`. A wait in progress is not `health=down`. A dead Chrome pid is still `health=down` with `browser_lost`. `--timeout` on `ask-and-wait` and `answer-wait` stays milliseconds. A trailing `ms` or `s` is accepted. `chat-turn --timeout` stays seconds.

**C2 applied.** `applied` is `true`, `false`, or `unknown`. True when the target is removed or hidden, the DOM under its panel or card changes, a pkb answer, chat, or guide event is emitted, focus, value, or checked changes, or the document navigates. False only when a before/after pair was read and none of those signals moved. Unknown when the engine cannot read that pair. A false `false` is the bug. Press of Tab, Enter, Escape, and the arrows uses the existing CDP key path on the focused node (keyDown and keyUp) so focus moves as a person would. Click settle ends when a signal arrives or at 120 ms, not a fixed 500 ms. `form-fill` interaction rows set `source=agent`.

**C3 snapshot.** Compact snap rows and find items include, when present, `value` (password inputs stay redacted), checked or selected, `highlight=<preset>`, `card=<id> "<title>" <state>`, `guide=<id> step <n>/<total> -> <ref>`, placement or pin text, `purpose=`, and chat `msg` id, author, and status. The default includes them. `--include=values,highlights,cards,guide,placements` narrows the set; a missing flag keeps the full collaboration view. `--exposure=human|full` uses the composite v2 mask names on snap, find, and act (`full` is `full-access`). Panel controls get a stable accessible name, `data-pkb-purpose`, and counts on a separate `data-pkb-badge`. Highlighted targets get `data-pkb-highlight`. Guided targets get `data-pkb-guide-step`. Cards get `data-pkb-card-id`, `data-pkb-card-title`, and `data-pkb-card-state`. Messages get `data-pkb-msg-id`, `data-pkb-msg-author`, and `data-pkb-msg-status`. `cursors.chat` changes when chat or ui events change. `snap --since=<cursor>` returns added, removed, and changed rows. `wait --condition=new-control` runs on the wait lane. The first snap after navigation includes the panel when it is configured open, or reports `panel=pending`.

**C4 find and tabs.** Find ranks an exact accessible name, with badge text ignored, above a substring. `--purpose=chat-tab` and `purpose=` in the query select that control. When `--pick` is set and more than one candidate matches, the reply lists the candidates and the one that was picked and why. A substring never wins over an exact name. A tab click and `panel-open --tab=` switch the visible pane. `applied` follows that pane.

**C5 chat and cards.** `chat-send` sends only. `chat-turn` delivers the agent message first, returns `sentId` once status is `delivered`, and returns a human message only when it arrived after that send. An earlier unread is returned with `earlier=true` and is not treated as the reply. `ask-and-wait --timeout` stays milliseconds. `chat-turn --timeout` stays seconds. Both accept a trailing `ms` or `s`. The runtime dedupes by message id on re-render and after navigation. Unread counts messages the human has not seen. Replayed history does not increment it. `chat-read --last=<N>` is human-mode and read-only. It does not mark messages read unless `--mark-read` is set, so a 2 s poll does not ack the pane. Snap and `chat-read` include a `recent` list of cards that appeared and reached `timed-out` since the cursor. Default card timeouts stay as they are. `ask --min-show=<ms>` holds the card at least that long when set. Unset means no extra hold.

**C6 upload.** `act --kind=attach --query= --value=<path>` and `upload --ref= --file=<path>` both call the existing CDP `DOM.setFileInputFiles`. No new library. A control whose accessible name is "Upload File" resolves to the single associated `input[type=file]`. Several `--file` values are one list. Each path must exist. The call uploads only those paths. `applied` follows `input.files` and the change event. A human click on a file input or an Upload File control shows "Ask agent to attach a file" (`data-pkb-purpose=request-upload`). That click posts `upload-request` with the input ref and label. The agent answers with attach.

**C7 guide.** `guide` writes the step into the panel Guide pane, badges or selects the Guide tab, sets `data-pkb-guide-step` on the target, and is visible in snap and find. When the human types, blurs, or clicks that target, the guide advances and emits an event with `how=human`. The agent polls that event on the wait lane. Guide state is re-injected after navigation with the existing page-state restore.

**C8 navigate and docs.** `navigate --url=<url|fixture:name>` runs on the start host, reuses the Gherkin navigate URL rules, and keeps the panel and the session. MCP forwards it. User docs and their guidance mirrors describe the two-actor rule, the wait lane, chat-send versus chat-turn, `applied`, the `data-pkb-*` attributes, snap fields, chat-read, the upload hand-off, the guide flow, press keys, navigate, and a short human-mode guide. Release notes list every change and the flagged items.

**C9 toolbar.** One injected dock hosts the chat panel, guide, step editor, recording controls, popout, and the other injected tools. Each panel collapses into its own toolbar button. Collapse keeps state. Close ends that tool and asks for confirmation when an open guide, a recording, or unsent chat text would be discarded. Two buttons that do the same thing are not kept. The free-floating pill behavior is removed. A selector tests already use (`.pkb-pill`) remains on the toolbar button so those tests still find the reopen control, and the assertion stays that the control reopens the panel. The whole toolbar collapses to one handle. Pointer dragging keeps it on screen and off the focused element when that fits. Position, collapsed state, and the open panel persist per origin with the runtime's existing storage and survive navigation. Every control has `data-pkb-purpose`, a stable label, and `data-pkb-badge` for counts. The toolbar is excluded from recording the same way the panel is. Snap and find show it. `panel-state` reads the dock. `panel-open --collapsed` sets it. `--popout`, `--popin`, `panel-open --tab=`, and `panel-close` stay.

## Flagged (not added)

| Item | Reason |
|------|--------|
| Native OS file dialog | A person cannot drive it from human-mode verbs. The request-upload card is the hand-off. |
| New CDP, ONNX, OCR, or WebDriver library | Hard rule: no new dependencies. Upload uses `DOM.setFileInputFiles` already on the session. |
| FlaUI.WebDriver | Already flagged for desktop. This work does not add it. |
| Changing default ask, toast, or card timeouts | Short-lived cards are listed in the trail instead. `--min-show` is opt-in. |
| A second browser or a second start host per actor | Both actors share the one `start` session. |

## CLI-first and logging checklist

- Every capability is a CLI verb or flag first: `ask-and-wait --async`, `answer-wait`, `ui-poll --id`, `snap --since`, `snap --exposure`, `snap --include`, `find --purpose`, `find --exposure`, `act --exposure`, `act --kind=attach`, `act --kind=press`, `upload`, `chat-read`, `wait --condition=new-control`, `navigate`, `panel-state`, `panel-open --collapsed`, `ask --min-show`.
- MCP tools only forward those argv lists. Workbench does not grow a second implementation.
- Help text, `WorkbenchCommandLine`, `AgentHop`, `docs/roadmaps/workbench-cli-inventory.json`, and the MCP forwarders register each new verb and flag. Coverage gates are part of the phase that adds the verb.
- New code logs through `AgentFastLog` (`pkb_agent_log`, `pkb_agent_log_entity`, date stamp, `pkb_agent_log_max_bytes`). Entities: `wait`, `snap`, `act`, `chat`, `guide`, `upload`, `toolbar`. Off unless the entity is named. No secrets in cleartext.
- User docs under `docs/` stay identical to `src/main/resources/META-INF/pickleball/guidance/docs/`. This roadmap and the maintainer evidence stay out of the export.
- Cucumber step annotations stay single string literals. Gherkin syntax stays.
- Before each push: `python scripts/refresh_agent_index.py`, `--check`, `python scripts/verify_agent_contract.py`, `python scripts/sync_consumer_guidance.py --check`. Fetch and rebase onto `origin/3.0.0-collab-fixes`. No force-push. No tag, release, or Maven publish.
