## Decisions

### Row 6 — Control Engine naming
**Decision:** Rename all documentation and capability output from "Java DOM engine" / "dom-engine" to **"Control Engine"**. No Java package rename (dev.domengine stays; zero public breakage).  
**Approach:** In-place doc rewrites in owned sections; capability strings updated in Engines/NativeDesktop where exposed.  
**Files:** docs/custom-element-definitions.md, docs/dynamic-steps.md, docs/maintainer/3.0.0-query-visual-design.md, AGENTS.md sections, capability output in query package.  
**Tests:** Capability string assertions in existing query tests + new CrossPlatformQueryTest.  
**Docs:** All references updated to "Control Engine".

### Row 7 — Layered architecture
**Decision:** Explicit three-layer model documented and enforced in code comments/structure:  
1. Syntax layer (Expressions.java, Query.java, phrase parsing)  
2. Dictionaries layer (ExecutionDictionary, SelectorTranslator emitting combined selectors)  
3. Protocol adapters layer (owned by G1; G2 never calls protocol)  
**Approach:** Document in query-visual-design and dynamic-steps; keep query/* and translator free of any CDP/BiDi/Selenium protocol calls.  
**Files:** docs/maintainer/3.0.0-query-visual-design.md, docs/dynamic-steps.md, code comments in Query.java / SelectorTranslator.java.  
**Tests:** Boundary test ensuring no protocol imports in query package.  
**Docs:** Layer diagram and ownership clear.

### Row 8 — Unified Boolean query
**Decision:** Confirmed fully implemented in Expressions.java (AND/OR/NOT, parentheses). No functional change.  
**Approach:** Add confirmatory unit tests covering capital operators, nesting, precedence.  
**Files:** Expressions.java (read-only confirmation), new BooleanConfirmTest.  
**Tests:** `./gradlew --no-daemon :dom-engine:test --tests dev.domengine.query.BooleanConfirmTest`  
**Docs:** Confirm in dynamic-steps.md that capital AND/OR and parens are the canonical form.

### Row 9 — XPath as clause type; combined form preferred
**Decision:** SelectorTranslator emits combined (CSS/text/image/colour/accessibility/relative) form first. XPath is a first-class clause type but fallback. Pure XPath definitions still work; one WARN logged per definition on first use.  
**Approach:** Reverse current "XPath pass-through first" in SelectorTranslator.phrase. Build clause model on top of engine-defects Phase 3 (document.evaluate).  
**Files:** SelectorTranslator.java, CompositeSelector.java, ExecutionDictionary.java (after Phase 4 gate).  
**Tests:** CombinedFormTest, XPathFallbackTest.  
**Docs:** Rewrite XPath sections in custom-element-definitions.md and query-visual-design.md.

### Row 10 — Universal syntax
**Decision:** Same syntax and verbs on browsers and desktops. Platform differences only where physically required (e.g. desktop screenshot, AT-SPI vs UIA), reported via capabilities.  
**Approach:** Audit NativeDesktop.java verb dispatch; document differences in capability output.  
**Files:** NativeDesktop.java, Engines.java capability strings.  
**Tests:** CrossPlatformQueryTest.  
**Docs:** Universal syntax section in dynamic-steps.md and query-visual-design.md.

### Row 11 — Relative locators
**Decision:** near, above, below, left-of, right-of confirmed present. Add **inside**, **after**, **before** as geometry-based engines.  
**Approach:** Implement in Engines.java (and NativeDesktop for desktop). Parse in Expressions.  
**Files:** Engines.java, Expressions.java, NativeDesktop.java.  
**Tests:** RelativeLocatorTest (extend existing).  
**Docs:** Update relative locator list in query-visual-design.md.

### Row 13 — Negative relations
**Decision:** Parse `not-near`, `not-inside`, `not-above`, … and `NOT near …` into RelationTerm with negated=true. These act as filters or score penalties consumed by G3 AffinityScorer.  
**Approach:** Extend parser; RelationTerm.negated drives G3.  
**Files:** New RelationTerm.java, Expressions.java / Query.java parser, new NegativeRelationTest.  
**Tests:** NegativeRelationTest.  
**Docs:** Document negative forms.
