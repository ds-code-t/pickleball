# 3.0.0 Dolt Core Roadmap

**Start SHA:** `1c4bbd1cb1b08b5f78cefd694c5de1139befe423` (the commit that added this roadmap, the design and the Build prompt)

**Ladder start:** `b5b76595a8f5a7cccdd8ee46666f55b347b98816` (`origin/3.0.0` tip when implementation began; newer than the roadmap commit).

**Branch:** `3.0.0` only. No force-push, no tags, no releases, no publishing. Version stays 3.0.0. Do not touch `master`, `2.2.0` or `2.1.19`. Do not touch open PRs #2/#3 on `ds-code-t/dom-composite`.

**Goal:** replace the SQLite-backed "Dalton" layer with the Dolt-backed core, the single spine of "one spine, multiple adapters", add Dolt-branch sandboxes for isolated agent and test runs, and remove the Dalton name everywhere outside history files, with no aliases. Decided by Dan on 2026-11-15. The design, with every locked decision, is `docs/maintainer/3.0.0-dolt-core-design.md`.

**Every phase is mandatory.** Every item in every phase must be finished in full. Nothing in this roadmap is optional, deferred, "nice to have" or "follow-up". Do not stop early. Stop only on an honest test failure you cannot fix, a hard-rule violation, or a real blocker, and then report it.

Hard guardrails (copy into every Build phase):
- Work only on branch `3.0.0`. NEVER commit, push or merge to `master`, `2.2.0` or `2.1.19`. No tags, releases, publishing or force-push. Never run `./gradlew --stop`.
- Do not change Gherkin syntax. Cucumber step annotations stay single string literals with identical values. Do not weaken, skip or delete tests. A SQLite-specific assertion is replaced by its Dolt equivalent and listed in the phase's port table, never dropped.
- CLI-first: every capability is a `pickleball dolt` command. Workbench, MCP and Gradle only forward to it. The Workbench never opens a database, loads core store classes or starts the Dolt binary.
- The Cucumber adapter stays isolated. No Cucumber types or syntax enter the Dolt core.
- Logging for new code: toggleable, per-entity, ISO date-stamped, size-capped (`pkb_dolt_log*`).
- New code uses the new names from day one (`tools.dscode.dolt`, `pkb_dolt*`, `PKB_DOLT*`, `.pickleball/dolt/`).
- No cleartext secrets in rows, logs, diffs, sandbox dumps or commits.
- Docs are rewritten IN PLACE to describe what is implemented at that commit. History goes to `docs/release-notes.md`. Never replace or truncate `AGENTS.md` or `docs/agent/feature-map.md` wholesale; edit only the paragraphs a phase changes and check `wc -c` before each push.
- Regenerate `docs/agent/repository-index.md` only with `python3 scripts/refresh_agent_index.py`. Before every push run `python3 scripts/refresh_agent_index.py --check`, `python3 scripts/verify_agent_contract.py` and `python3 scripts/sync_consumer_guidance.py --check`. Delete `scripts/__pycache__`.
- Targeted tests only, named per phase: `timeout 600 ./gradlew --no-daemon <module>:cleanTest <module>:test --tests <filter>`. Do NOT run the full multi-module regression, `validate --all`, first-start timing, consumer-sim or Maven `@all`. Dan holds those until he asks. A failed targeted test stops the ladder.
- The diagnostic-report SQLite index and its "SQLite index parity" workflow are out of scope and stay as they are. `sqlite-jdbc` stays for them.
- Never write placeholder or 0-byte files.
- Exported guidance docs (`docs/agent/feature-map.md`, `docs/release-notes.md`, `docs/configuration.md` and the rest of the export) must not link to `docs/maintainer/`, `docs/roadmaps/` or `prompts/`; `verify_agent_contract.py` fails on that. Name those docs in words instead.
- Each phase ends with: targeted tests green, docs updated, commit, `git pull --rebase` then `git push origin HEAD:3.0.0` (never force), and this roadmap's scoreboard row filled.
