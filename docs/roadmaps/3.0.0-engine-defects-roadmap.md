# 3.0.0 Engine Defects Roadmap

**Status:** Mandatory phased plan. All phases are required. Design is locked in `docs/maintainer/3.0.0-engine-defects-design.md` (D1, D2, D11 in the first part; D3-D10, D12, G1-G6, the live Chrome flake, the uncertain items U1-U5, and the CLI-first and logging checklist in the appended parts).
**Branch:** `3.0.0` only. Version stays `3.0.0`. No force-push, no tags, no releases, no publishing. Never commit, push, or merge to `master`, `2.2.0`, or `2.1.19`.
**Planned against:** `origin/3.0.0` at `cb4825a1` (design complete). When the tip and this roadmap disagree, the tip wins; record the difference in the phase's scoreboard row.

## Process rules

- Push every completed implementation change to `origin/3.0.0`. Fetch and rebase onto the tip before every push. Never force-push.
- Before every push: `python3 scripts/refresh_agent_index.py` (when indexed files changed), then `python3 scripts/refresh_agent_index.py --check`, `python3 scripts/sync_consumer_guidance.py --check`, and `python3 scripts/verify_agent_contract.py --base-ref origin/master`. Never hand-edit `docs/agent/repository-index.md`.
- Between phases run only light targeted tests tied to the changed code (each phase lists them). If they fail or stall, record it on the push and in the scoreboard. A phase's own new required tests must pass before the phase is marked done. Do not weaken, skip, or delete tests to move on.
- The full multi-module regression is the last check (Phase 8), not the inner loop. Do not run the held suites: `validate --all`, first-start timing, and Maven `@all`.
- Temporary files go in `.agent-work/` only.
- CLI-first and logging checklist (design doc) applies to every phase: every new engine capability works from the `domengine` CLI first; Workbench, MCP, and Gradle only forward; logging is toggleable, per entity, date-stamped, and size-capped.
- Each phase rewrites the affected docs and `AGENTS.md` in place so they describe only current 3.0.0 behavior. History goes in `docs/release-notes.md`. Do not append a supersede note.
- After each push, check the CI run for that SHA (`gh run list --branch 3.0.0`, `gh run view <id>`) and record the result in the scoreboard.

## Phase 1 — Page/tab attach, loud fallback, lookup guard (D1, G1, G2; start U1)

**Functionality.**
- D1: at attach and join, a browser-level CDP URL (`/devtools/browser/`, including ChromeDriver `se:cdp`) is resolved to the current tab's page target (`/json/list` matched to the window handle, or `Target.getTargets`), and the engine joins the page socket. Covers `CompositeRuntime.attach`, join, `focusPage`, the Cucumber adapter, the native engine, Workbench, and direct control. The engine side (`BrowserSession.discover`) treats a browser endpoint as a browser and selects a page target; it never sends `DOM.*` to the browser target. A window or tab switch re-pins the page target.
- G1: `pkb_composite_fallback_log` (`warn` default, `info`, `off`), one line per run and reason for every `auto` fallback, a `composite.fallback` diagnostic event, INFO line for an explicit Rust override. `pkb_composite=off` stays silent.
- G2: guard test only (relative `COMPOSITE_BIN` resolves the same on both resolvers). No new resolver.
- U1: after D1 lands, run the consumer `@dom-composite` features on both engines and list every new failure in the design doc's U1 row.

**Docs.** `docs/configuration.md` row for `pkb_composite_fallback_log`; `docs/dynamic-steps.md` "DOM engine translation" note on the fallback line; `docs/direct-control-handoff.md` sentence that attach pins the page target; design doc U1 findings.

**Tests.**
- Root live (real Chrome, skip only when Chrome is absent): real ChromeDriver, `DriverConstruction.ready()`, then a composite find and click through `ElementOperations`; a second tab opened and switched to, then a find on the new tab.
- `dom-engine` live: `session attach --cdp ws://.../devtools/browser/<id>` then `query` succeeds.
- Root unit: G1 log cases from the design (missing, client failure, join failure, `off`, `info`, explicit override INFO, diagnostic event).
- `CompositeLocationTest` new relative-path guard test.

**Acceptance.** No `DOM.getDocument ... wasn't found` on the default path; consumer `@dom-composite` on `pkb_engine=cucumber` with default composite no longer fails on attach.

## Phase 3 — Full XPath 1.0 through `document.evaluate` (D2)

**Functionality.** Engine `xpath` evaluates with `Runtime.evaluate` / `Runtime.callFunctionOn` and `document.evaluate(expr, contextNode, null, ORDERED_NODE_SNAPSHOT_TYPE, null)` in the right document (frame documents from D7 once that lands), maps results to backend node ids with `DOM.requestNode` / `DOM.describeNode`, and keeps document order. A relative XPath under `within` uses the scope node as the context node. An invalid expression is an error (`invalid`), never 0 hits. The hand-rolled `Engines.xpathMatches` / `xpathPredicate` path is removed from the default path (kept only if an offline-tree caller needs it, and then it must raise on anything it does not support). `CompositeWebElement.actionBody` `localXPath` works for text-only elements.

**Docs.** `docs/dynamic-steps.md` and engine `capabilities` description: XPath is full XPath 1.0 evaluated by the browser.

**Tests.**
- `dom-engine` live: `//*[self::button or @role='button']`, `//*[@class='b' and @id='vis']`, `//*[normalize-space(.)='Visible']`, `(//button)[2]`, `//li/a`, `ancestor-or-self::`, `translate(...)`, `concat(' ', normalize-space(@class), ' ')`, a relative XPath under `within`; an invalid expression gives `invalid`.
- Root live through the adapter: the same set via `ElementOperations`, and a click on a text-only element via `actionBody`.

## Phase 4 — Honest capabilities and relied-on flags (D3-D9; U2)

**Functionality.** Per the design: per-verb flag sets and rejection of unrecognized flags (D3) with `capabilities.verb_flags`; `query --wait-for/--timeout-ms/--poll-ms/--stability-ms` re-reading the live tree per poll, and the same for `wait` (D4); `hover` action with `--force-hover` (D5); `--filter displayed` with the shared displayed test, applied before `nth`/`every`/`count-only` (D6); frame descent including late-loading and cross-origin frames, `--frame`/`--shadow` roots, CSS `--pierce open`, and adapter `popFrame`/`clearFrames`/`popShadow` (D7, with U2 cause recorded); `--node-id`/`--node-ids` identity with a `stale` error (D8); `--all-frames` with per-hit frame paths (D9). The adapter gates each on `verb_flags` and keeps its fallback when absent.

**Docs.** Engine and adapter javadoc for each flag; `docs/dynamic-steps.md` "DOM engine translation" flag list; `docs/direct-control-handoff.md` CLI examples for `hover`, `--wait-for`, `--frame`; design doc U2 cause.

**Tests.** Every test listed under D3-D9 in the design doc (`dom-engine` live and root live through the adapter), plus the fake-binary fallback tests listed there. Existing fake-binary / argv tests unchanged.

## Phase 6 — Workbench classpath, eval_nodes/limit, capability probe policy (G3, G4, G5)

**Functionality.** G3: `runtimeOnly` and `testRuntimeOnly` non-transitive `dom-engine` on `pickleball-workbench`, no compile dependency, no POM dependency, isolation tasks adjusted only for `dom-engine` if needed. **Docs.** `docs/pickleball-workbench.md` note that developer `run`/`installDist`/tests carry the engine; `docs/agent/feature-map.md` if canonical tests are added; adapter javadoc for `evalAll` and `limit`.
