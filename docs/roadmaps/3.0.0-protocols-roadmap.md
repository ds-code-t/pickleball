# 3.0.0 browser protocols roadmap

**Status:** in progress on `3.0.0-collab-fixes`, after D0–D15 (`docs/roadmaps/3.0.0-locked-followons-roadmap.md`, merged in #40).

**Goal:** control, monitor, listen to and log a browser through every protocol pickleball can reach: Playwright (D12–D14), WebDriver BiDi, the Chrome DevTools Protocol and Selenium classic. One engine layer picks the backend per capability; one event stream carries what the browser reports; DOM changes arrive by push instead of polling. Research and sources: [3.0.0-protocols-research.md](../maintainer/3.0.0-protocols-research.md) (retrieved 2026-11-24).

## Design decisions

**Protocol host.** Every CLI call is its own process, but routes, intercepts, dialog policy, subscriptions and the event ring must outlive one call. A per-project protocol host (`.pickleball/proto/host.json`, owner-only) is started on first use by a protocol verb. It listens on 127.0.0.1 only, on a random port, behind a random token, and holds the protocol sockets. `browser-events --stop` ends it and removes every route and mock it installed.

**Event schema.** One row shape, `urn:pickleball:browser-event:1`, for every backend (fields in [browser-events.md](../browser-events.md)). `seq` is monotonic per session and is the cursor; `at` is ISO-8601 with offset. `source` names the backend that produced the row.

**Fallback order.** Playwright when the session is Playwright-attached, then WebDriver BiDi (always on Firefox; on Chromium when a BiDi socket exists), then CDP (Chromium only), then Selenium classic, then `error: unsupported:` with a fix. Probed lazily, cached per session; an unknown-command reply marks that capability unavailable on that backend.

**Redaction.** Cookie values, Authorization/Cookie/Set-Cookie headers, password fields, tokens and secret-named JSON fields are replaced with `[redacted]` and named in `redacted[]` before a row reaches the ring, the NDJSON spill or a reply. `--reveal` (control tier) shows a value in the reply only; it is never logged.

**DOM push (E2b).** One MutationObserver script, three channels: Playwright exposeBinding, BiDi script.addPreloadScript with a channel argument and script.message, CDP Runtime.addBinding. CDP DOM domain events were not chosen (node bookkeeping on every change). Click-to-agent latency measured by DomPushLiveTest: push 1, 2, 1 ms against poll 36, 41, 31 ms.

**Persistence.** Rows spill to `.pickleball/runs/<id>/browser-events-YYYY-MM-DD.ndjson`, capped (`pkb_browser_events_max_kb`, default 8192) with one rotation. `pkb_browser_events=off` stops the spill and the ring; `pkb_browser_events_kinds=` keeps listed kinds only.

**BiDi on by default.** Selenium Chrome, Edge and Firefox sessions ask for `webSocketUrl=true`. `pkb_bidi=false` turns it off. A driver that rejects it falls back with one WARN per run.

**Push before polling.** DOM change listeners use the cheapest push channel per backend (E2b) and report `mode=push` or `mode=poll`.

## Could not verify (research §5)

- A per-command Chrome-vs-Firefox BiDi support matrix; pickleball probes at runtime and docs record what the tests observed.
- Whether Playwright 1.65 has a stable WebDriver BiDi channel for stock Firefox; assumed not.
- Selenium Java high-level `network()` handler names; checked against the pinned selenium-java javadoc in E11.
- Chrome DevTools MCP `--autoConnect` in Chrome 144, from its docs only.
- The permissions BiDi extension and BiDi `emulation.setNetworkConditions` support per browser.

## CLI-first and logging checklist

- Verb in WorkbenchCommandLine and WorkbenchAgentCommands; help entry and catalog line; inventory JSON (agentCore and tiers); `covers_command_<verb>` test; D4 tier.
- MCP forwards only.
- `--via=auto|playwright|bidi|cdp|classic`; replies say `via=<backend>`; unsupported combinations print `error: unsupported: <capability> on <browser>/<protocol>` and `fix:`.
- Toggleable per-entity, date-stamped, size-capped logging (`pkb_proto_log`).
- Docs mirrored by `scripts/sync_consumer_guidance.py`; release notes updated.

## Flagged (not added)

| Item | Reason |
|------|--------|
| Step/scenario linking of event rows (E2, partial) | Rows carry `step`/`scenario` when an agent sets them with `browser-events --step= --scenario=`. The scenario reporter does not set them automatically yet: the reporter runs in the test JVM and the ring lives in the protocol host, and wiring a per-step call into the reporter is a separate change. |
| Incremental composite snapshot and premap deltas from pushed changes (E2b, partial) | `snap --since` reports the pushed `delta` (batches, mutations, targets, unchanged) next to its existing diff; the composite snapshot and premap still rebuild by walking the page. Driving them from the batches needs a node-identity map between the observer and the snapshot rows, which is a larger change than this phase. |
| Selenium's DOM-mutation handler (E2b, choice) | Not used. It lives in the test JVM's WebDriver and depends on one `selenium-devtools-vNNN` module; the host and the agent verbs need one listener on every backend. The same observer runs through BiDi `script.message` instead. Recorded in docs/browser-events.md. |
| Panel collab events in the browser event stream (E2b, partial) | A person's card answers, typed fields and chat sends stay typed overlay and chat events in the agent store (and now wake waits at once). They are not copied into the protocol host's `browser-events` ring, which runs in another process. |
| Logpoints on pages opened later (E3, partial) | `logpoint` sets the breakpoint on the pages open when it runs. A page attached afterwards does not get it until `logpoint` is run again. |
| WebTransport and BiDi WebSocket frames (E4, partial) | No browser on the box exposes WebTransport sessions through CDP, BiDi or Playwright, and BiDi has no WebSocket frame events, so WebTransport is not reported and a BiDi session shows only the WebSocket handshake request. CDP and Playwright report frames. |
| Firefox network depth (E4, not run) | There is no Firefox on the box; the BiDi body and header paths are tested against Chrome's BiDi only. |
| CSP bypass over Chrome BiDi (E5, partial) | Chrome's BiDi does not implement `browsingContext.setBypassCSP`; `csp --via=bidi` is unsupported on Chrome and auto falls back to CDP `Page.setBypassCSP`. |
| Throttling over BiDi and Playwright (E5, partial) | BiDi `emulation.setNetworkConditions` and Playwright `setOffline` only do offline; `emulate --network=slow-3g` or numbers need CDP. |
| Playwright `net-auth` (E5, partial) | Playwright sets HTTP credentials only when a context is created, so `net-auth` on a live session uses BiDi or CDP. |
| Route steps in Gherkin (E5, not added) | The repo has no mock-response step phrase, so routes are CLI/MCP only; no new step text was invented. |
| Console argument previews (E3, partial) | Console rows join argument values or descriptions into `text`; object previews (`preview.properties`) are not expanded into separate fields. |
| Firefox BiDi live run (E2) | No Firefox on the build box; `BrowserEventsBidiLiveTest.firefoxBidiWhenPresent` runs a real Firefox flow when Firefox is installed and skips visibly otherwise. |
