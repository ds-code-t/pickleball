# 3.0.0 Embedded Store Roadmap

**Status:** approved by Dan on 2026-11-16 (decisions locked in t931u to t935u). Ready to build.

**Start SHA:** `cb494456934f84c600ed81b4de22480c36d810d3` on `origin/3.0.0` (the commit that already contained this roadmap). Work branch `3.0.0-embedded-store` was cut from that tip.

**Branch:** `3.0.0-embedded-store`, created from `origin/3.0.0`. Push only there. Do not merge into `3.0.0`; the orchestrator merges after verification. Never commit, push or merge to `master`, `2.2.0` or `2.1.19`. No tags, releases, publishing or force-push. Version stays 3.0.0.

**Goal:** replace the Dolt sql-server layer with an embedded SQLite store (`org.xerial:sqlite-jdbc:3.47.2.0`, already published): no server, no child process to open it, no port, no runtime download, no MariaDB driver, Maven Central only. Every sandbox is a fully independent SQLite copy. Large unchanged binaries are references to Git. `sandbox merge` does a three-way hash compare. Dolt is removed entirely and everything is renamed `dolt` to `store` with no aliases. Every decision and its reason is in `docs/maintainer/3.0.0-embedded-store-design.md` (section numbers below refer to it).

**Every phase is mandatory. Nothing is optional, deferred or "follow-up".** Finish every item in every phase in full, in order. Stop only on an honest test failure you cannot fix, a hard-rule violation, or a real blocker, and report it with what you tried.

## Hard guardrails (every phase)

- Branch `3.0.0-embedded-store` only. Never `./gradlew --stop`. `git fetch origin` and `git pull --rebase origin 3.0.0-embedded-store` before every push; never force.
- Gherkin syntax unchanged. Cucumber step annotations stay single string literals with identical values.
- Never weaken, skip or delete tests. Renaming a test class keeps the test. A test that exists only for Dolt-specific behavior (server, installer, journal, Dolt SQL traps, Dolt commits) is **replaced** by an equivalent store test named in that phase's port table, never just deleted. The total test count reported by Gradle must not go down from the count recorded in S1 except by the port table's one-for-one replacements.
- Do not touch dom-composite PRs #2 and #3. Do not open paid assistant sessions.
- CLI-first: every capability is a `pickleball store` command (`pickleball dolt` until S5). Workbench, MCP and Gradle only forward to it. The Workbench never opens a database or loads core store classes.
- The Cucumber adapter stays isolated: no Cucumber types or syntax in the store packages. The held move of the Cucumber step model out of Cucumber's package stays held.
- Opening and using the store starts no process, opens no socket and downloads nothing. No new dependency; stay on `sqlite-jdbc` 3.47.2.0.
- Logging for new code: toggleable, per-capability, per-entity, ISO date-stamped lines, size-capped (design 10.5).
- No cleartext secrets in rows, change logs, branch tables, logs, diffs, merge reports, commits or prompts.
- Held, do not run or fix: the full multi-module regression, `validate --all`, first-start timing, consumer-sim, Maven `@all`, and the execution-path audit fixes F1 to F12.
- Docs are rewritten IN PLACE to describe what is implemented at that commit; history goes to `docs/release-notes.md`. Never replace or truncate `AGENTS.md` or `docs/agent/feature-map.md` wholesale; edit only the paragraphs a phase changes and compare `wc -c` before each push. Keep the lines `verify_agent_contract.py` checks.
- Regenerate `docs/agent/repository-index.md` only with `python3 scripts/refresh_agent_index.py`. Before every push run `python3 scripts/refresh_agent_index.py --check`, `python3 scripts/verify_agent_contract.py` and `python3 scripts/sync_consumer_guidance.py --check`, then delete `scripts/__pycache__`.
- Exported guidance docs must not link to `docs/maintainer/`, `docs/roadmaps/` or `prompts/`; name those docs in words. In current docs, do not put "opt-in" next to the store name (`CurrentDocsTest`).
- Never write placeholder or 0-byte files. No effort or day estimates in docs.
- Targeted tests only: `timeout 600 ./gradlew --no-daemon <module>:cleanTest <module>:test --tests <filter>` on JDK 21 (root module is `:`, Workbench is `:pickleball-workbench`). A failed targeted test stops the ladder until fixed honestly. Timing tests print numbers and assert only a ceiling about ten times the design target.
- Each phase ends with: targeted tests green, docs updated, commit, fetch and rebase, push, the Agent Contract and SQLite parity CI runs for that push checked, and this roadmap's scoreboard row filled.

## CLI-first and logging checklist (every phase that adds or changes a capability)

- [ ] The capability is a CLI command or flag with `--json` output as one object and `fix:` lines on errors.
- [ ] `--help` text lists it.
- [ ] Gradle, Workbench and MCP only forward the same arguments; a forwarding assertion exists in `*CliForwarderTest`, `*GradleForwardTest` or `WorkbenchMcpServerTest`.

## S6 — Large-file references

**Functionality (design 7):** `pkb_store_binary_policy=skip|include` (`hash-only` replaced by `include`), `pkb_store_large_file_bytes` (default 262144, `0` = every binary), binary detection by extension and sniff. A large binary whose bytes equal its Git blob is a reference (location, hash, blob, commit, size; no bytes); otherwise its bytes are stored. `max-file-size` exempts references. Reading a reference verifies the hash and falls back to Git by blob id, then fails with the `error:` and `fix:` lines. Any write that changes a referenced file in a branch copies the bytes into that branch and stops referencing. Extract leaves unchanged references alone. `status` prints `refs=<n> owned-large=<n>`. Logging capability `refs`.

**Docs:** `AGENTS.md` binary sentences, `docs/configuration.md`, `docs/store-entities.md` if wording changes, release notes.

**Tests:** ported `StoreBinaryRefTest` (sets `pkb_store_large_file_bytes=0` for its existing reference assertions and adds a below-threshold inline case); new `LargeFileReferenceTest` (reference only when equal to Git; dirty large file stored; hash mismatch on disk falls back to Git; both missing fails with `fix:`; `max-file-size` exemption), `LargeFileBranchCopyTest` (a sandbox change copies bytes into the sandbox only; `main` and the project file unchanged; sandbox copy size stays small with a 5 MB referenced binary).
