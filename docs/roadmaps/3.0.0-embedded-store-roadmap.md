# 3.0.0 Embedded Store Roadmap

**Status:** approved by Dan on 2026-11-16 (decisions locked in t931u to t935u). Ready to build.

**Start SHA:** `cb494456934f84c600ed81b4de22480c36d810d3` on `origin/3.0.0` (the commit that already contained this roadmap). Work branch `3.0.0-embedded-store` was cut from that tip.

**Branch:** `3.0.0-embedded-store`, created from `origin/3.0.0`. Push only there. Do not merge into `3.0.0`; the orchestrator merges after verification. Never commit, push or merge to `master`, `2.2.0` or `2.1.19`. No tags, releases, publishing or force-push. Version stays 3.0.0.

**Goal:** replace the Dolt sql-server layer with an embedded SQLite store (`org.xerial:sqlite-jdbc:3.47.2.0`, already published): no server, no child process to open it, no port, no runtime download, no MariaDB driver, Maven Central only. Every sandbox is a fully independent SQLite copy. Large unchanged binaries are references to Git. `sandbox merge` does a three-way hash compare. Dolt is removed entirely and everything is renamed `dolt` to `store` with no aliases. Every decision and its reason is in `docs/maintainer/3.0.0-embedded-store-design.md` (section numbers below refer to it).

**Every phase is mandatory. Nothing is optional, deferred or "follow-up".** Finish every item in every phase in full, in order. Stop only on an honest test failure you cannot fix, a hard-rule violation, or a real blocker, and report it with what you tried.

- Never weaken, skip or delete tests. Renaming a test class keeps the test. A test that exists only for Dolt-specific behavior (server, installer, journal, Dolt SQL traps, Dolt commits) is **replaced** by an equivalent store test named in that phase's port table, never just deleted. - Exported guidance docs must not link to `docs/maintainer/`, `docs/roadmaps/` or `prompts/`; name those docs in words. In current docs, do not put "opt-in" next to the store name (`CurrentDocsTest`).

- Targeted tests only: `timeout 600 ./gradlew --no-daemon <module>:cleanTest <module>:test --tests <filter>` on JDK 21 (root module is `:`, Workbench is `:pickleball-workbench`). ## S6 — Large-file references

**Functionality (design 7):** `pkb_store_binary_policy=skip|include` (`hash-only` replaced by `include`), `pkb_store_large_file_bytes` (default 262144, `0` = every binary), binary detection by extension and sniff. A large binary whose bytes equal its Git blob is a reference (location, hash, blob, commit, size; no bytes); otherwise its bytes are stored. `max-file-size` exempts references. Reading a reference verifies the hash and falls back to Git by blob id, then fails with the `error:` and `fix:` lines. Any write that changes a referenced file in a branch copies the bytes into that branch and stops referencing. Extract leaves unchanged references alone. `status` prints `refs=<n> owned-large=<n>`. Logging capability `refs`.

**Docs:** `AGENTS.md` binary sentences, `docs/configuration.md`, `docs/store-entities.md` if wording changes, release notes.

**Tests:** ported `StoreBinaryRefTest` (sets `pkb_store_large_file_bytes=0` for its existing reference assertions and adds a below-threshold inline case); new `LargeFileReferenceTest` (reference only when equal to Git; dirty large file stored; hash mismatch on disk falls back to Git; both missing fails with `fix:`; `max-file-size` exemption), `LargeFileBranchCopyTest` (a sandbox change copies bytes into the sandbox only; `main` and the project file unchanged; sandbox copy size stays small with a 5 MB referenced binary).
