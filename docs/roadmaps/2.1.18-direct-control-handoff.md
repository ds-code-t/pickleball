# 2.1.18 Direct-control handoff

**Status:** Approved for implementation on branch `2.1.18`. Do not reopen the design.  
**Version:** stays `2.1.18`. Never commit to `master`. Master is merged at `35f84790`.  
**Philosophy:** Simplicity and elegance. One shared code path for session descriptors and handoff. No duplicated config or run-var logic. Normal non-Workbench runs remain byte-for-byte unchanged because every new branch is gated on an explicit opt-in (absent config = zero behavior change). Pickleball stays the sole owner of browser lifecycle.

dom-composite (the external direct-control tool under development) is **not** a dependency of 2.1.18. This version only exposes a stable, versioned contract so that tool (or any future one) can attach later without changes to Pickleball.

## Design

### Per-live-session descriptor

Every live Workbench session (headless isolate or GUI-driven) publishes a machine-readable **session descriptor**.

Fields (JSON, stable schema versioned as `session-descriptor.v1`):

- `sessionId`
- `runId`
- `workspacePath` (absolute)
- `browserType` (e.g. chrome, edge)
- `cdpDebuggerAddress` (the value of `goog:chromeOptions` `debuggerAddress` or the `se:cdp` capability when present; null if unavailable)
- `currentUrl` (or null)
- `windowHandles` (array)
- `state` (one of: `idle`, `running`, `paused`, `held`, `stopping`, `stopped`)
- `startedAt` / `updatedAt` (ISO-8601)
- `contractVersion` (`"1"`)

The descriptor is:

1. Written atomically to `.pickleball/runs/<runId>/session/descriptor.json` (and refreshed on meaningful state changes).
2. Reachable through the existing agent CLI surface (Workbench launcher / `WorkbenchSessionCommands` / `WorkbenchAgentCommands`):
   - `session list` — prints one line per live session (or `--json` for an array).
   - `session info <sessionId>` — prints the full descriptor; `--json` emits the raw object.
3. The GUI only displays what the CLI already prints. No second source of truth.

One shared writer in the live-session path (`WorkbenchLiveSession` / worker manager / control bridge) produces the file and the CLI response. No separate GUI-only path.

### Versioned handoff contract

Documented in:

- `docs/direct-control-handoff.md` (canonical)
- Packaged guidance copy under `META-INF/pickleball/guidance/` so `export-guidance` materializes it for consumers.

The contract states:

- How an external tool attaches: read the descriptor (file or CLI), connect to the published CDP address (or other future channel), and operate only while the session state allows it.
- Pickleball remains the owner of the browser process and WebDriver lifecycle. The external tool must **detach cleanly** (close its CDP connection, release any holds) before the session is stopped or the browser is closed.
- Safety rule: no concurrent conflicting actions while a Gherkin step is running. An agent (or the external tool via a documented request) can request a **pause/hold** state. While `held` or `paused`, Workbench will not advance steps; the external tool may act. On release, normal step execution resumes. The hold is cooperative and visible in the descriptor.
- Versioning: the descriptor carries `contractVersion`. Future versions are additive or explicitly negotiated. 2.1.18 ships only version 1.
- Absent or blank direct-control configuration produces **zero** extra behavior.

### Optional pluggable direct-control provider

An optional config key (workspace `runvars.properties` or a documented system property, default unset):

```text
pkb_direct_control_provider=<external-command>
```

When set, Workbench may launch that command, passing the path to the current `descriptor.json` (and optionally the session id) as arguments, and logs the provider's stdout/stderr into the run's short log / session log. The provider is responsible for attaching, acting, and detaching according to the contract.

- Off by default.
- Absent or blank key = no launch, no extra process, no log noise, no behavior change for any run.
- No hard dependency on any specific external binary (including the unfinished dom-composite). The interface is simply "run this command with the descriptor."
- One shared launch path used by both headless and GUI sessions. Normal non-Workbench `mvn test` / `gradlew test` never reads the key.

### CLI-first and logging checklist

Every new surface follows the existing Workbench rules:

- Agents drive via the launcher CLI (`-Dexec.args=...`). The GUI is a view only.
- New verbs (`session list`, `session info`, optional provider launch) are added to the same command parser and session command table.
- Short log (`.pickleball/agent-log`) receives start/stop and provider launch lines. Dense diagnostic logs stay unchanged.
- `record.json` gains an optional `sessionDescriptor` fingerprint or path only when a live session exists; normal runs are unaffected.
- Parallel 80 (drop to 12 on memory pressure). No failing tests. Never weaken assertions.

## Phases

Every phase is mandatory. Push after each phase. The phase number is in the commit message. Stay on branch `2.1.18` only.

### Phase 0 — Roadmap

This document. Push.

### Phase 1 — Session descriptor model and writer

Shared JDK-friendly descriptor record (protocol or launcher package) + atomic writer that lives next to the live session. Unit tests for field population, atomic replace, missing CDP (null), state transitions, and that a non-live run produces no file.

### Phase 2 — CLI surface

`session list` and `session info <id> [--json]` on the existing Workbench command line. Output matches the file byte-for-byte when both exist. Tests cover empty list, single session, `--json`, and unknown id.

### Phase 3 — Handoff contract docs and packaged guidance

Write `docs/direct-control-handoff.md`. Update `docs/pickleball-workbench.md`, `docs/consumer-agent-guide.md`, and the packaged guidance copies. `export-guidance` materializes the new doc. No code behavior change yet.

### Phase 4 — Optional provider

Config key reader (one place, workspace-aware). Launch helper that runs the named command with the descriptor path, captures logs, and never starts if the key is absent. Tests: absent = no process; present = command invoked with correct args; provider exit does not kill the browser; normal runs ignore the key.

### Phase 5 — Pause/hold safety

Cooperative `held` state requestable via existing session commands (or a new thin `session hold` / `session release`). Descriptor reflects it. Step execution is blocked while held. Tests prove a running step cannot advance under hold and that release resumes cleanly. External tools are documented to request the hold before acting.

### Phase 6 — End-to-end and release notes

Real isolate + GUI sessions publish a usable descriptor with a real CDP address when Chrome is used. Provider launch is exercised with a no-op command. Release notes for 2.1.18. Feature-map and repository-index updated if new files appear.

### Phase 7 — Final verification

After the last code change: `./gradlew test` (and workbench/protocol checks) plus the consumer `@all` suite at parallel 80 (12 on memory trouble). Report real pass/fail counts. Push.
