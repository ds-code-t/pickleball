# 2.1.18 Workbench Full CLI Coverage

**Status:** Mandatory multi-phase implementation on branch `2.1.18` only. Never commit, push, or merge to `master`. Version stays `2.1.18`.

**Philosophy:** Exhaustive coverage of every Workbench CLI command, subcommand, flag, env var, run var, exit code, output format, and launch mode. Prefer one shared code path for config and RunVar resolution between Workbench launches and normal launches (Dan's simplicity principle: fix by consolidation, not per-bug tweaks). Normal non-Workbench `mvn test` / `gradlew test` behavior remains unchanged. No failing tests; never weaken, skip, or delete assertions. Consumer `@all` runs at parallel 12 on low-memory boxes (80 where safe). Do not modify `CucumberScanUtil`, `ModularScenarios`, `StepData`, `DiagnosticReporter`, driver construction, or tag parsing (stop and report if a bug lives there).

## Config Matrix

Axes (generate combinatorial tests; full cross-product where cheap, pairwise + targeted otherwise):

- Run-var files: present / absent / multiple / overrides (workspace, profile, system, sealed)
- `globalTestProperties()` / `globalTestDefaults()` hooks
- Resolve-once design: resolve, save copy, agent edits copy, edited copy is final (no hooks reapplied)
- `pkb_configpath` set / unset
- Path prefixes: `file:`, `classpath:`, `wd-file:`, unprefixed
- `pkb_features` variants
- Tags expressions (including spaces, quoting, `--tags-file`, `--tags-b64`, xor rewrite)
- Parallelism (`pkb_parallel`)
- Headless / headed
- Windows-style paths & spaces (simulated), PowerShell / `mvnw.cmd` quoting
- Maven consumer vs Gradle
- Working directory variations
- Workspace config
- Sessions: list / info / hold / release
- Direct-control provider composite on / off
- Player
- Stale / corrupt / missing state files
- Concurrent runs
- Non-ASCII
- `maven.test.failure.ignore=true` (wrapper exit 0 while tests fail; Workbench must still report failure correctly via run-index / Surefire)

## Parity

Workbench launches and normal launches must resolve identical configs and RunVars through **one shared code path**. Add parity tests that assert equality of resolved RunVars / profiles for equivalent inputs. No duplicated resolution logic.

## End-to-end

Real-process tests that drive the built CLI (via Maven exec or equivalent) against `maven-consumer-project` scenarios. Assert stdout/stderr, exit codes, files created/updated (record.json, descriptors, summaries, indexes), and behavior under the matrix axes.

Every bug the new tests expose is fixed at root cause, preferring consolidation to a shared path. Log each in `docs/roadmaps/2.1.18-workbench-coverage-findings.md` with the repro test name, expected vs actual, and the fix commit.

- Short log (`.pickleball/agent-log`) receives start/stop and key events. Dense diagnostic logs unchanged.

- Parallel 80 (drop to 12 on memory pressure). No failing tests. Never weaken assertions.
