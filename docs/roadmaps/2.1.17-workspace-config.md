# 2.1.17 Workspace Config Roadmap

**Status**: Approved for full implementation on branch 2.1.17 (head 29b6d28d).  
**Philosophy**: Simplicity and streamlining. The logic that reads and resolves run vars and configs exists ONCE. Every launch mode uses it. Bugs are removed by deleting duplicated code, not by patching each quirk.

## Agreed Design (summary)

- **Per-run workspace**: `.pickleball/runs/<runId>/workspace/` holds `runvars.properties` and a full copy of `configs/`. A "profile" is simply an earlier workspace copied (`seed --from=<runId>`).
- **Capture (seed)**: Resolve-only step runs the consumer's real runner subclass from the cached classpath (`java -cp`). It performs the NORMAL resolution (properties files, `globalTestProperties()`/`globalTestDefaults()` hooks, `-D` values, profiles, defaults), stops before Cucumber, and writes the final values plus the configs copy into the workspace. Runs before any launch so agents and the GUI can edit the files. Project's own browser is kept; `CHROME_HEADLESS` is used only when the project names none. Workspace is never overwritten except with `--reseed`. Resolve results may be cached, keyed on properties files, test-classes timestamp, classpath, and `-D`/env inputs.
- **Launch**: Every mode (Maven discover/confirm, direct-java isolate, live workers, GUI) passes ONLY `-Dpkb_workspace` plus per-launch selection keys (tags, name, example, features, parallel, run id, agent id). ONE branch at the top of the `PickleballRunner` constructor loads only the workspace and skips hooks, file merges, `-D` merges, and `PickleballProfiles.apply`. It publishes the values as System properties and initializes configs from `workspace/configs`. Edits apply on the next start.
- **Fixed rules**:
  - Secrets are stored in runvars as protected references, never values. Configs copy stays a plain copy, with a seed-time warning if it contains a literal secret.
  - The six context keys are always written by the seed; a missing one is a hard error.
  - `pkb_parallel=auto` is stored as `auto`.
  - One SHA-256 fingerprint covers the whole workspace and is written to `record.json`.
  - GUI Config tab and agents edit the same files, using atomic writes and a changed-on-disk check, no locking.
- **DELETE**: Workbench sealed path (Apply-sealed, `writeSealed`, sealed branches), deprecating `pkb_overriderunvars` in the docs; the browser-choosing role of `AgentBrowserLadder`; both `LastDiscoverSnapshot` replay paths; the duplicate `applyCliRunVars` and compact parsers; the late `RunConfigCopy` in the test JVM; `ParsingMap.configPathForCurrentRun` and the double bundled `CHROME_HEADLESS` addition; the separate discover/confirm/isolate run-var builders; and the "replay forces parallel=1" coupling.
- **Documented caveats**: Surefire-only pom values don't appear in a `java -cp` capture; hook-computed time/env/random values are frozen at capture; hook side effects don't rerun at launch; protected refs read project properties at launch.
- **Normal non-Workbench `mvn test`**: Byte-for-byte unchanged, because everything is gated on `pkb_workspace`.

## Verification against 2.1.17 code (head 29b6d28d)

Design is viable. No hard impossibilities. Minor risks noted with simplest fixes that keep the design:

- **Constructor short-circuit**: Feasible. `PickleballRunner` constructor (src/main/java/tools/dscode/testengine/PickleballRunner.java) completes full resolution (hooks, merges, `Profiles.apply`, `ParsingMap.initializeConfigs`) and ends at `Phase4Timing.mark("runner-ready")` before any Cucumber discovery. Early check for `System.getProperty("pkb_workspace")` right after `INSTANCE = this` can load the workspace and skip the rest. Simplest fix: add the branch; no other changes required.
- **Resolve-only seed**: Viable via cached classpath `java -cp` (already used by `WorkbenchWorkerManager`). Constructs consumer subclass so hooks run. Stops before Cucumber. Simplest fix: new thin main class or reuse existing bootstrap; no blocker.
- **Protected refs**: Existing mechanism in `PickleballProfiles` / `SensitiveConfiguration`. Seed writes protected-ref form. Simplest fix: none; use existing serialize path.
- **Deletions**: `AgentBrowserLadder` (browser-choosing role), `LastDiscoverSnapshot` (both copies, including `writeSealed`), sealed branches in `PickleballProfiles`, late `RunConfigCopy` inside consumer JVM, and related replay logic are all present and can be removed for the Workbench path. Simplest fix: delete after the new path is proven; keep normal `mvn` path untouched.
- **Risks (documented caveats cover them)**: Side-effecting hooks run only at seed; Surefire-only `systemPropertyVariables` not present in `java -cp` capture. No design change needed.

## Phased Implementation (all phases mandatory)

### Phase 1: Workspace data model and short-circuit loader
**Goal**: Introduce the per-run workspace directory and the single shared loader. Normal `mvn test` unchanged.

**Code changes**:
- Add `WorkspaceResolver` (or equivalent thin class) that loads `runvars.properties` + `configs/` from a directory path and returns the resolved map + configs root. No external sources.
- In `PickleballRunner` constructor, add early branch: if `-Dpkb_workspace` is set, call the resolver, publish values as system properties, initialize configs from `workspace/configs`, and return. Skip `globalTestDefaults`, property merges, `globalTestProperties`, `Profiles.apply`, sealed logic, and late config copy.
- Add `pkb_workspace` system property constant.
- Unit tests for the resolver and the short-circuit path (workspace present vs absent).

**Docs**: Update `docs/ai-run-configuration.md` and `docs/pickleball-workbench.md` with the workspace contract and short-circuit rule.

**Tests**: Unit tests for load-only behavior; golden comparison that plain `mvn test` output is unchanged.

### Phase 2: Resolve-only seed
**Goal**: Capture the normal resolution into the workspace before any launch.

**Code changes**:
- Add a resolve-only entry point (thin main or Workbench command) that uses the cached classpath (`java -cp`), instantiates the consumer runner subclass, lets the constructor complete, captures final values (with protected refs) and copies the configs tree into `.pickleball/runs/<runId>/workspace/`, then exits. No Cucumber.
- Seed before Discover/Confirm/Isolate/GUI launch. Support `--reseed` and `--from=<runId>` (copy earlier workspace).
- Write the six context keys; fail if any is missing after seed.
- Store `pkb_parallel=auto` as `auto`.
- Compute SHA-256 fingerprint of the whole workspace and write it to `record.json`.
- Seed-time warning if configs contain a literal secret.
- Optional cache: hash sources (properties files, test-classes timestamp, classpath, `-D`/env) and reuse if unchanged.

**Docs**: Document seed behavior, caveats (Surefire-only pom values, frozen hook values, side effects, protected refs), and `--reseed`/`--from`.

**Tests**: Seed produces complete workspace; missing context key is hard error; fingerprint written; cache hit/miss; protected refs present.

### Phase 3: Launch path unification and deletions
**Goal**: Every launch mode passes only `-Dpkb_workspace` + selection keys. Delete the old complexity.

**Code changes**:
- Update Maven discover/confirm, direct-java isolate, live worker, and GUI launchers to pass `-Dpkb_workspace=<path>` and selection keys only. Remove per-path run-var builders, `applyCliRunVars`, and "replay forces parallel=1".
- Delete: Workbench sealed path (`writeSealed`, Apply-sealed, sealed branches in `PickleballProfiles`, `pkb_overriderunvars` handling), browser-choosing role of `AgentBrowserLadder` (reduce to seed default or remove), both `LastDiscoverSnapshot` replay paths, late `RunConfigCopy` inside the test JVM, `ParsingMap.configPathForCurrentRun` special case, and double bundled `CHROME_HEADLESS` injection.
- Deprecate `pkb_overriderunvars` in docs.

**Docs**: Full update of `AGENT-GUIDE`, `docs/consumer-agent-guide.md`, packaged guidance copies, `docs/pickleball-workbench.md`, `docs/ai-run-configuration.md`, and release notes. Document the single path and deletions.

**Tests**: End-to-end: agent edits `pkb_browser` in workspace to a non-headless config key and adds Chrome args/logging prefs in `workspace/configs`; launched run uses them in Maven, direct-java, and live-worker modes. Subclass hook value is captured then overridden by an edit. Plain `mvn test` golden comparison remains unchanged.

### Phase 4: GUI, agent file edits, and final verification
**Goal**: Same files for GUI Config tab and agents; atomic writes; final suite.

**Code changes**:
- GUI Config tab and agent commands edit the workspace files directly. Atomic writes + changed-on-disk check. No locking.
- Ensure fingerprint covers the whole workspace.
- Final cleanup of any remaining dual-path code.

**Docs**: Complete the documentation set. Add caveats section.

**Tests**: End-to-end as above. Rerun the consumer-style `@all` suite and `./gradlew test` after the last code change. Report real results. No failing tests; fix the product, never weaken assertions.
