# 2.1.17 Workbench workspace config

**Status:** Approved. Implement fully on branch `2.1.17`. Do not reopen the design.  
**Version:** stays `2.1.17`. Never commit to `master`.  
**Philosophy:** Simplicity and streamlining. The logic that reads and resolves run vars and configs exists **once**. Every launch mode uses it. Bugs are removed by **deleting** duplicated code, not by patching each quirk.

Normal non-Workbench `mvn test` / `./gradlew test` stays byte-for-byte unchanged, because every new branch is gated on `pkb_workspace`.

## Design

### Per-run workspace

Each run gets `.pickleball/runs/<runId>/workspace/` holding:

- `runvars.properties`
- a full copy of `configs/`

A "profile" is an earlier workspace copied: `seed --from=<runId>`.

### Capture (seed)

A resolve-only main next to `WorkbenchWorkerMain` runs the consumer's **real** runner subclass from the cached classpath with `java -cp`. It performs the **normal** resolution (properties files, `globalTestProperties()` / `globalTestDefaults()` hooks, `-D` values, profiles, defaults), stops before Cucumber, and writes the final values plus a copy of the configs directory that resolution chose.

- Excludes per-launch coordination keys and CLI projection (`pkb_options`, `pkb_run_profile`, cucumber CLI args). The seed process is not given launch selection. Project tags, name, example, features, and parallel that resolution produced are kept. A later launch `-D` overrides selection for that process only and does not rewrite the file.
- Runs before any launch, so agents and the GUI can edit the files before the first launch. Seed also runs automatically when a launch finds no workspace.
- The project's own browser is kept. `CHROME_HEADLESS` is written only when the project names none.
- A workspace is never overwritten except with `--reseed`.
- Resolve results are cached per project. The key is the properties files, the test-classes timestamp, the classpath fingerprint, and the `-D` / env inputs. The cache is invalidated when the key changes.

### Launch

Every mode (Maven discover/confirm, direct-java isolate, live workers, GUI) passes **only** `-Dpkb_workspace=<dir>` plus per-launch selection keys: tags, name, example, features, parallel, run id, agent id. One shared builder produces those arguments.

One branch at the very top of the `PickleballRunner` constructor, before `globalTestDefaults()`: if `pkb_workspace` is set, load only the workspace; skip hooks, file merges, `-D` merges, and `PickleballProfiles.apply`; apply the selection keys; resolve protected refs; publish the values as System properties exactly like `publishToSystemProperties`; initialize configs from `workspace/configs`; return. Edits apply on the next start. Never "run everything then overwrite".

### Fixed rules

- Secrets are stored in runvars as protected references (`${protected:key}`), never values. The configs copy stays a plain copy. Seed prints a WARN if that copy contains a literal secret.
- The six context keys are always written by the seed: `pkb_glue`, `pkb_features`, `pkb_datapath`, `pkb_callpath`, `pkb_componentpath`, `pkb_configpath`. A missing one at launch is a hard error. Blank values are allowed.
- `pkb_parallel=auto` is stored as `auto` and resolved at launch.
- One SHA-256 fingerprint covers the whole workspace (runvars + configs tree) and is written to the run's `record.json` as `workspaceFingerprint`.
- The GUI Config tab and agents edit the same files, using atomic writes (temp + move) and a changed-on-disk check (mtime and hash). No locking.

### Delete

Remove the code. Do not leave it dead.

- Workbench sealed path: Apply-sealed button, `writeSealed`, sealed branches used by Workbench in `LastDiscoverSnapshot`. `pkb_overriderunvars` is deprecated in the docs. It keeps working for plain non-Workbench runs, because removing it would change those runs.
- The browser-choosing role of `AgentBrowserLadder` (it must not force `CHROME_HEADLESS` over the project browser).
- Both `LastDiscoverSnapshot` replay paths.
- Duplicate `applyCliRunVars` and compact parsers. Keep one (`PKB_props`).
- The late `RunConfigCopy` in the test JVM.
- `ParsingMap.configPathForCurrentRun` and the double bundled `CHROME_HEADLESS` addition (the copy injects it and `ParsingMap` injects it again).
- The separate discover/confirm/isolate run-var builders. One builder replaces them.
- The "replay forces `parallel=1`" coupling. Isolate stays one scenario via selection, not via a forced parallel count.

### Caveats

- Surefire-only pom values (`systemPropertyVariables` / `argLine`) do not appear in a `java -cp` capture. Type them into the workspace.
- Hook-computed time, env, and random values are frozen at capture. Delete the key or `--reseed` to recompute.
- Hook side effects outside `pkb_*` System properties do not rerun at launch.
- Protected refs read project properties at launch. They are not frozen values.

## Golden baseline

`src/test/resources/workspace-golden/plain-resolution.txt` is the plain non-Workbench resolution of:

- an example runner with no hooks
- a consumer-style runner whose `globalTestDefaults` / `globalTestProperties` set the six context keys, browser, parallel, and a hook marker

`PlainResolutionGoldenTest` compares that text byte-for-byte. It does not set `pkb_workspace`. Phase 7 re-checks it after the last code change.

## Phases

Every phase is mandatory. Push after each phase. The phase number is in the commit message.

### Phase 0 — Roadmap and baseline

This document. Golden baseline captured. Push.

### Phase 1 — Workspace model and one loader

`Workspace` (JDK-only, shared protocol): layout, atomic `runvars.properties`, configs tree, SHA-256 fingerprint, `record.json` field, changed-on-disk check, context-key validation, protected-ref storage.

`pkb_workspace` branch at the top of `PickleballRunner`. `ParsingMap` loads `workspace/configs` for that branch only.

Unit tests: fingerprint stability and change, atomic write, stale-edit detection, missing context key is a hard error, `auto` parallel kept, protected refs never stored as values, secret-in-configs WARN, workspace launch skips hooks.

### Phase 2 — Resolve-only seed

`WorkspaceSeedMain` (`java -cp`, real consumer subclass, stops before Cucumber). Per-project resolve cache and its key. `seed`, `seed --from=<runId>`, `--reseed`. Browser kept from the project; `CHROME_HEADLESS` only when none is named.

Tests: consumer-style hooks are captured; cache hit and miss on each key input; existing workspace is not overwritten without `--reseed`.

### Phase 3 — All launch modes use the workspace

Maven discover/confirm (`ConsumerMavenTestRunner`), direct-java isolate, live workers (`WorkbenchWorkerManager`), and the GUI pass only `-Dpkb_workspace` plus selection keys through one shared builder. Seed runs automatically before the first launch of a run.

### Phase 4 — Deletions

Remove everything in the delete list. One compact parser. One run-var builder. No `parallel=1` coupling. `rg` proves the removed symbols are gone.

### Phase 5 — GUI and agent CLI

Config tab and run-var panel edit the workspace files (atomic write, changed-on-disk warning). No sealed UI. Agent commands show, edit, and seed workspaces.

### Phase 6 — Docs

`AGENT-GUIDE`, `docs/consumer-agent-guide.md` (CHROME_HEADLESS policy, sealed, `--runvar` on discover), `docs/pickleball-workbench.md`, `docs/ai-run-configuration.md`, packaged guidance copies / guidance export, release notes for 2.1.17 including `pkb_overriderunvars` deprecation and the caveats.

### Phase 7 — End-to-end tests

Real launches, not mocks:

- a) An agent edits `pkb_browser` in the workspace to a non-headless config key and adds Chrome args and logging prefs under `workspace/configs`. The launched run uses them (assert on the real driver options / capabilities) in Maven, direct-java, and live-worker modes.
- b) A consumer-style subclass hook value is captured at seed, then overridden by a workspace edit, and the edit wins at launch in every mode.
- c) Plain resolution output is unchanged versus this Phase 0 golden baseline.
- d) Secrets, context keys, `auto` parallel, fingerprint in `record.json`, `--reseed`, and `seed --from` verified end to end.

### Phase 8 — Final verification

Publish to Maven local. Rerun the consumer-style `@all` suite and `./gradlew test` after the last code change. Report real pass/fail counts. Push.
