**Pickleball 3.0.0 Java DOM Engine Roadmap**

**Status:** Mandatory multi-phase plan. All phases required. Implementation on branch `3.0.0` only.

### Process rules (Dan, 2026-11-12)
- Between phases, only light, targeted, quick tests tied to the changed code. If those tests fail or stall, leave them failing, note them on the push, and move on to the next phase. Do not weaken, skip, or delete existing tests.
- The full multi-module regression is the LAST check after ALL phases of this roadmap, not the inner loop, not between phases. Do not start it until every implementation phase is done. When it runs: fit it into memory without skipping tests (one module at a time if needed); on OOM/exit 137, kill leftover test JVMs, Gradle daemons, hung runs, and large capture files, then resume; never skip tests to "make it fit."
- Push each green (or noted) phase to branch 3.0.0 only. No force-push, no release, never master / 2.2.0 / 2.1.19.
- Do not truncate AGENTS.md or other docs. CLI-first and logging checklist on every phase: every capability reachable from the CLI; non-CLI surfaces only forward to the CLI; toggleable, per-entity, date-stamped, size-capped logging.

### Phase 0 — Docs and index (tiny, if needed)
- Confirm `docs/cucumber-compatibility.md` and `docs/agent/feature-map.md` correctly state native engine as default. Update if still stale.
- Append short pointers in AGENTS.md and docs index to the new design and this roadmap. Do not truncate.
- Targeted test: `WorkbenchLaunchCorrectnessTest` only if docs changed in a way that affects launch text.

### Phase 1 — Skeleton module + CDP basics
- Create `dom-engine` Gradle module. Core packages for CDP client, session, basic walker skeleton.
- Implement LiveTree equivalent for `DOM.getDocument` pierce + frame tree.
- CLI entry point `domengine` (or `composite`) with `version`, `capabilities`, `session create/attach/close`.
- Logging skeleton (per-entity, date-stamped, size-capped).
- Targeted tests: unit tests for CDP session attach, basic document walk on a fixture.

### Phase 2 — Query, selectors, geometry
- ContextSource walker (light, shadow, iframe).
- Pipeline engines: css, xpath, text, role, frame, shadow, near, below, desc, a11y.
- Geometry and bounds in top-document space.
- Targeted tests: selector parity against existing composite fixtures or offline HTML.

### Phase 3 — Actions, observe, image
- Actions: click, type, scroll, submit, key, dblclick, contextclick, drag, eval.
- Observe / wait / screenshot / snapshot.
- Image / template matching (optional tesseract or pure Java fallback).
- DesktopTree skeleton (fixture path; native AT where feasible).
- Targeted tests: action smoke on a live CDP fixture; observe parity.

### Phase 4 — CLI, MCP, switchover
- Full CLI surface matching current `composite` commands.
- MCP server that forwards to the CLI (or equivalent).
- Update `CompositeBinaryLocator` / `DomCompositeAdapter` to prefer the Java engine (in-process or process). Keep binary fallback behind a flag during transition.
- Dalton hooks (optional log/session recording).
- Targeted tests: adapter switch tests, MCP forward tests, existing ElementOperations tests still pass.

### Phase 5 — Conformance suite
- Port or reimplement the conformance suite against the Java engine.
- Ensure results match the previous Rust suite where fixtures exist.
- Targeted tests: the conformance suite itself.

### Phase 6 — Remaining 3.0.0 items (Central core / Log dashboard)
- Confirm Central core is the `dom-engine` module (done by prior phases).
- Confirm 10 MB file cap on history.log and apply identical pattern to new engine logs.
- Add Log dashboard if missing: CLI `log list|tail|show` + Workbench tab that only forwards. Surface capped logs.
- Targeted tests: log trim and dashboard forward tests.

### Phase 7 — Final full multi-module regression
- Run the mandatory full multi-module regression after every prior phase is complete.
- Fit into memory (one module at a time if needed). On OOM/exit 137 clean leftover JVMs/daemons/capture files and resume. Never skip tests.
- Record results. Push only if green or with explicit notes.

All phases are mandatory. Version stays 3.0.0. Start from the current tip of origin/3.0.0 (verify SHA on each pull).
