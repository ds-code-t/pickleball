## Decisions

### Row 12: Scored label affinity
**Decision:** Implement `dev.domengine.affinity.AffinityScorer` with explainable weighted score. Components: normalized distance (Euclidean + reading-order alignment), role compatibility, text similarity (token overlap + Levenshtein), section co-membership, explicit `for`/`aria-labelledby` evidence (strong boost), negative-relation penalties from G2 `RelationTerm` (negated=true). Highest score binds label to interactable. Used in pre-map construction and by runtime queries.
**Approach:** Real implementation over offline tree in W1; weights configurable but with sensible defaults. Score returns double + Map of part contributions.
**Files:** `dom-engine/src/main/java/dev/domengine/affinity/AffinityScorer.java` (+ weights config).
**Tests:** `AffinityScoreTest` (unit, offline tree fixtures).
**Docs:** `docs/snapshot.md` affinity section; update `docs/maintainer/3.0.0-query-visual-design.md` if needed.

### Row 14: Bounding boxes with size caps and one-match rule
**Decision:** `BoxCaps` applies configurable max area/width/height (config keys `pkb.premap.box.maxArea`, `maxWidth`, `maxHeight`; defaults relative to viewport or absolute px). Oversized discarded from candidate set. `OneMatch.resolve(candidates)` returns exactly one element or throws with full candidate list (id, score, why rejected/selected).
**Approach:** Caps during pre-map; OneMatch as the single enforcement point for G2 Query.
**Files:** `dev.domengine.premap.BoxCaps`, `OneMatch`.
**Tests:** `BoxCapTest`, `OneMatchTest`.
**Docs:** geometry/caps section in `docs/snapshot.md`.

### Row 15: Section detection with nesting
**Decision:** `SectionDetector` identifies sections from headings (h1-h6, role=heading), ARIA landmarks (banner, main, navigation, complementary, contentinfo, form, region), roles, forms, dialogs, tables, desktop panes/groups. Builds nested Section tree stored in pre-map.
**Approach:** Tree walk; nesting preserved for affinity and queries.
**Files:** `dev.domengine.premap.SectionDetector`.
**Tests:** `SectionDetectionTest` (nested fixtures).
**Docs:** sections section in `docs/snapshot.md`.

### Row 16: Universal composite snapshot on all 7 platforms
**Decision:** `CompositeSnapshot` is the single artifact: screenshot (base64 or path), structure tree, page source/HTML, XPath/path index, viewport mapping, pre-map. Producers for Chrome/Chromium/Edge (CDP via G1 adapters), Firefox (BiDi), Windows UIA, macOS AX, Linux AT-SPI. Desktop producers include screenshot capture (platform APIs) + a11y tree + bounds as viewport. Schema owned by G3, documented in `docs/snapshot.md`. MCP snapshot command (G1) returns it.
**Approach:** Model + schema in W1; desktop producers (screenshot+structure) in W1; browser producers in W2 after G1 adapters and engine-defects frames/rows.
**Files:** `dev.domengine.snapshot.CompositeSnapshot`, platform producers; root `CompositeSnapshotProducer`/`SnapshotProducers` additive.
**Tests:** `SnapshotCoverageTest` (per platform, targeted; live where available).
**Docs:** new `docs/snapshot.md` (full schema + producers); update `docs/maintainer/3.0.0-snapshot-coverage-audit.md` in place to as-built.

### Row 17: Pre-mapping as a CORE principle
**Decision:** Snapshot production always runs `PreMapBuilder`: labels→interactables via affinity, sections+nesting, boxes with caps, viewport coords, XPath indexes, image/colour features. Runtime queries are light lookups via `PreMapLookup`. Mandatory; no disable flag.
**Approach:** Builder over existing offline tree in W1; live in W2; G2 Query switches to real hooks in W3.
**Files:** `dev.domengine.premap.PreMap`, `PreMapBuilder`, `PreMapLookup`.
**Tests:** `PreMapTest`, `QueryUsesPreMapTest` (proves runtime path).
**Docs:** emphasize CORE in `docs/snapshot.md` and AGENTS.md (G4 sweep later).

**Contracts created in first phase (pass-through so G2 never blocks):** `PreMapLookup` (`current(sessionId, docVersion)`, `candidates(clauseKind, value)`), `AffinityScorer.score(...)`, `OneMatch.resolve(...)`. Control-api snapshot types additive only.
