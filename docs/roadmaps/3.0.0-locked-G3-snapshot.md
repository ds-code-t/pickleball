## What the code says today (read on `origin/3.0.0` at `9d42b532`)

- `DomEngineMain.snapshot` (`dom-engine/.../cli/DomEngineMain.java:492-518`) returns `LiveTree.toJson()`: a pierced CDP DOM tree plus frames. It has no screenshot, no HTML source, no XPaths, and usually no boxes.
- `LiveTree.enrich` (`tree/LiveTree.java:52-110`) makes three CDP calls per node (`CSS.getComputedStyleForNode`, `DOM.getBoxModel`, `Accessibility.getPartialAXTree`). Only `PageActions` calls it, for one or two nodes.
- `Observe.screenshot` (`action/Observe.java:44-64`) runs `Page.captureScreenshot` on its own.
- `Query.geometry` (`query/Query.java:349-357`) copies one box into four of the five named spaces.
- `Query` strict mode (`Query.java:82`) and `DesktopTree.one/resolve` (`desktop/DesktopTree.java:178-205`) throw a bare `"ambiguous"` / `"not found"` with no candidates and no reasons.
- Relatives `near`/`above`/`below`/`left-of`/`right-of` (`query/Engines.java:223-307`) filter on geometry and sort by distance. There is no scoring, no label binding, no section model, and no size cap. Any page-sized `<div>` can match.
- Desktop: `NativeDesktop.capture` → `WindowsUia` (PowerShell UIA), `MacAccessibility` (osascript System Events), `AtSpi` (gdbus). Results have a role, a name and screen bounds. There is no screenshot and no source. Handles are `uia-runtime-id` / `ax-path` / `atspi-path`.
- Root `CompositeSnapshotProducer` / `SnapshotProducers` build a per-element `ElementSnapshot`, not a page artifact. `SeleniumSnapshotProducer` leaves `bounds` null on Firefox.
- `pickleball-control-api` `MappingSnapshot` / `NodeMapSnapshot` hold scenario NodeMap data (`mapType`, `dataSources`, `values`). They are unrelated to page snapshots, and G3 does not change them. The groups plan listed them by name only.
- Logging: `dev.domengine.log.EngineLog` is already toggleable per entity (`DOMENGINE_LOG` / `COMPOSITE_LOG`), date-stamped and size-capped (`COMPOSITE_LOG_CAP_BYTES`). G3 adds entities and does not add a new logger.

## Decisions

### Row 12 — Scored label affinity
**Decision:** `dev.domengine.affinity.AffinityScorer` is a pure, deterministic, explainable scorer.

- **Contract (binding, groups plan §4.5):** `AffinityScore score(DomNode label, DomNode interactable, List<RelationTerm> relations)`. `AffinityScore` is a record of `double total`, `Map<String,Double> parts` and `List<String> reasons`. `double scoreValue(...)` returns `total` for callers that only want the number.
- **Explicit evidence short-circuits to 1.0** (part `explicit`): `<label for=id>`, `aria-labelledby` containing the label's id, a label that wraps the control, `<legend>` for controls in that `<fieldset>`, and on desktop the UIA `LabeledBy` / AX `AXTitleUIElement` / AT-SPI `LABEL_FOR` relation where the producer captured it.
- **Otherwise a weighted sum in [0,1]:**
  - `proximity` 0.30: `exp(-d/d0)`, where `d` is the gap between edges in the snapshot's visual space and `d0 = max(48px, 3 × label height)`.
  - `alignment` 0.20: reading order. Label left of the control on the same row (vertical centre overlap ≥ 50%) scores 1.0. Label directly above with left edges within 16 px scores 0.9. Label right of a checkbox or radio scores 1.0. Label below scores 0.2. Label after the control in document order with no geometry scores 0.1.
  - `role` 0.15: whether a label-like node (text, `label`, `legend`, heading ≤ h6, `dt`, `th`, desktop `text` / `static`) fits the control role (textbox, combobox, checkbox, radio, slider, spinbutton, listbox, switch, button without its own name). A control that already has its own accessible name from content scores 0.2.
  - `text` 0.10: the larger of token Jaccard and normalised Levenshtein similarity, comparing the label text with the control's `name`, `id`, `placeholder`, `title` and `aria-describedby` text.
  - `section` 0.15: 1.0 for the same innermost section, 0.5 for the same parent section, 0 for different top-level sections.
- **Relation terms (G2's `dev.domengine.query.RelationTerm`):**
  - A satisfied positive term adds `0.10 × weight` (default weight 1.0).
  - A satisfied negated term (`negated=true`, for example `not-near`, `not-inside`) subtracts `0.50 × weight` and records the reason `negated <relation> satisfied`.
  - The total is clamped to [0,1].
- **Weights:** `AffinityWeights.defaults()`.
  - Override with the engine env `DOMENGINE_AFFINITY_WEIGHTS=proximity=0.3,alignment=0.2,...`, the CLI flag `--affinity-weights`, or the root RunVar `pkb_premap_affinity_weights`, which the adapter forwards.
  - Weights are re-normalised to sum to 1. An unknown key is a usage error.
- **Binding:**
  - The pre-map binds each interactable to its best label with `total ≥ 0.35`.
  - The assignment is greedy one-to-one by descending score. Exceptions: a fieldset legend or group label may bind to many controls, and so may a table header for a cell column.
  - Ties within 0.02 are broken by document order.
  - Unbound interactables are listed in `premap.unlabeled`.
- **Runtime use:** the same scorer ranks `near` / `left-of` / `above` / label candidates when G2's hook asks (W3). Explain output carries `parts` and `reasons`.

**Files:** `affinity/AffinityScorer.java`, `AffinityScore.java`, `AffinityWeights.java`.
**Tests:** `dev.domengine.affinity.AffinityScoreTest`, `dev.domengine.affinity.AffinityWeightsTest`.
**Docs:** `docs/snapshot.md` § Label affinity.

**`RelationTerm` timing:** G2 lands `RelationTerm` in its Phase 1 (W1). If it is not on origin yet when G3 Phase 1 starts, G3 Phase 1 builds against an overload taking `List<?>`. G3 must not create `RelationTerm` itself (G2 owns `query/*`). It records "waiting on G2 Phase 1 for RelationTerm overload" and adds the typed overload as soon as the record exists.

### Row 14 — Bounding boxes with size caps and the one-match rule
**Decision — box caps:** `dev.domengine.premap.BoxCaps` decides whether a node may be a **target**. It never removes a node from the structure or from sections.

- **Caps:** `maxAreaRatio` 0.60 of the viewport area, `maxWidthRatio` 0.98, `maxHeightRatio` 0.98. Absolute caps `maxAreaPx` / `maxWidthPx` / `maxHeightPx` are off by default (0).
- **Configuration:** engine flags `--box-max-area`, `--box-max-width`, `--box-max-height`. Each takes a ratio (`0.6`) or pixels (`900px`). Env `DOMENGINE_BOX_CAPS`. Root RunVars `pkb_premap_box_max_area`, `pkb_premap_box_max_width`, `pkb_premap_box_max_height`, forwarded as flags.
- **Always excluded as targets:** `html`, `body`, the document node, and desktop `desktop` / `window` roots.
- **Exempt from caps:** nodes whose role is a container the query explicitly asks for (`dialog`, `alertdialog`, `form`, `region`, `main`, `navigation`, `table`, `grid`, desktop `pane` / `window` / `group`, or any section clause). Asking for a dialog therefore still works.
- **Recording:** a capped node gets `capped: true` and `cap_reason` (for example `area 0.92 > 0.60`) in the snapshot. Capped nodes are left out of target indexes and kept for sections.

**Decision — one match:** `dev.domengine.premap.OneMatch` is the single enforcement point. Its contract is `Resolved resolve(List<Candidate> candidates, OneMatch.Policy policy)`.

- **Step 1, hard filters in this order:** box caps (targets only), displayed (`hidden` row state / not displayed), satisfied negated relations (`policy.negativesFilter`, default true for act verbs), and interactable-only (`policy.actVerb`).
- **Step 2:** if exactly one candidate remains, return it.
- **Step 3:** if several remain and every candidate has a score (affinity or relation), pick the top only when it leads the second by at least `margin` (default 0.15; `--one-match-margin` / `pkb_premap_one_match_margin`). The explain output records `chosen by score margin 0.23`.
- **Step 4:** otherwise throw `OneMatchException`.
  - The message starts with `ambiguous: N candidates` or `not found`, so existing `codeFor` mappings and tests keep working.
  - The exception carries a `candidates` array, each entry with `handle`, `role`, `name`, `text` (≤40 chars), `box`, `score` and `reason` (`kept`, `rejected: box-cap area 0.92>0.60`, `rejected: hidden`, `rejected: not-inside dialog satisfied`, `tie: 0.81 vs 0.80 < margin 0.15`).
  - The CLI error JSON adds `candidates` next to `error`.
- **Scope:** the rule applies to verbs that need one element (resolve, click, type, hover, drag, desktop click/type/resolve, `--strict`). List queries still return lists, with `capped`/`reason` annotations when `--explain` is set.
- **Ownership:** `DesktopTree.one/resolve` is G3-owned and switches to `OneMatch` in Phase 1. The browser `Query` strict path is G2's and calls `OneMatch` at G2's single hook (G2 Phase 6).

**Files:** `premap/BoxCaps.java`, `premap/OneMatch.java`, `premap/OneMatchException.java`, `premap/Candidate.java`.
**Tests:** `dev.domengine.premap.BoxCapTest`, `dev.domengine.premap.OneMatchTest`, `dev.domengine.desktop.DesktopOneMatchTest`.
**Docs:** `docs/snapshot.md` § Boxes, caps and one match.

### Row 15 — Section detection with nesting
**Decision:** `dev.domengine.premap.SectionDetector.detect(DomNode root, Platform platform)` returns `List<Section>`. Each `Section` is a record of `id`, `kind`, `title`, `handle`, `box`, `depth`, `parentId`, `childIds` and `memberCount`, and every node gets a `section_path` (root → innermost section id).

- **The root section** (`document` or `window`) always exists.
- **Browser kinds:**
  - `landmark`: `header`/banner, `nav`, `main`, `aside`/complementary, `footer`/contentinfo, `search`, `region`/`section` with an accessible name.
  - `form`; `fieldset` (title from `legend`); `dialog` (`dialog`, `role=dialog|alertdialog`, `aria-modal`).
  - `table` (`table`/`grid`/`treegrid`, title from `caption` or `aria-label`); `tabpanel`; `details` (title from `summary`); `iframe` (frame document).
  - `heading`: an implicit outline. A section runs from an h1–h6 or `role=heading aria-level=n` to the next heading of the same or higher level inside the same container block.
- **Desktop kinds:** from the projected role: `window`, `dialog`, `pane`, `group`, `tab`/`tabpanel`, `toolbar`, `menu`/`menubar`, `list`, `table`/`tree`, `form`.
- **Titles,** in order: `aria-labelledby` text, `aria-label`, first heading inside, `legend` / `caption` / `summary`, desktop name.
- **Nesting** follows DOM or a11y containment. Shadow roots and frames nest inside their host or iframe section. Heading sections nest by level inside their container.

**Files:** `premap/SectionDetector.java`, `premap/Section.java`.
**Tests:** `dev.domengine.premap.SectionDetectionTest` (nested landmarks, heading outline, fieldset in form in dialog, table, iframe, shadow host, desktop fixture).
**Docs:** `docs/snapshot.md` § Sections.

### Row 16 — Universal composite snapshot on all 7 platforms
**Decision:** a single artifact, `dev.domengine.snapshot.CompositeSnapshot`, with JSON schema `pickleball.composite-snapshot` version 1.

- **Schema owner:** G3. Machine-readable schema at `dom-engine/src/main/resources/dev/domengine/snapshot/composite-snapshot.schema.json`. Human doc at `docs/snapshot.md`. G1's MCP `snapshot` command returns this JSON unchanged.
- **Builder:** `CompositeSnapshotBuilder` assembles snapshots from transport-neutral inputs: a `DomNode` tree, frames, a screenshot PNG, a source text and viewport metrics. Every producer, in-engine or in the root, uses this one builder, and **the builder always runs `PreMapBuilder`** (row 17).

**Top-level fields:**

| Field | Contents |
|---|---|
| `schema`, `version`, `id` | Schema name, version 1, snapshot id |
| `session_id`, `doc_version` | Session and the document version the snapshot describes |
| `platform` | `chrome`, `chromium`, `edge`, `firefox`, `windows-uia`, `macos-ax` or `linux-atspi` |
| `transport` | `cdp`, `bidi`, `selenium-fallback`, `uia`, `ax`, `atspi` or `fixture` |
| `captured_at`, `duration_ms` | ISO-8601 capture time with offset; capture duration |
| `viewport` | `css_width`, `css_height`, `device_pixel_ratio`, `scroll_x`, `scroll_y`, `visual {offset_x, offset_y, scale}`, `screen {x, y, width, height}` (desktop and window origin) |
| `screenshot` | `format: png`, `width_px`, `height_px`, `image_scale` (image px per CSS px or per screen point), `clip`, `sha256`, and `base64` or `path` (with `--out-dir`) |
| `source` | `kind` (`html` per frame or `a11y-xml` for desktop), `text` or `path`, `bytes` |
| `frames[]` | `id`, `parent_id`, `url`, `frame_path`, `offset` |
| `nodes[]` | A flat list, described below |
| `premap` | See row 17 |
| `warnings[]` | Warnings raised during capture |

**Each entry in `nodes[]` has:**
- `handle`, `parent`, `tag`, `role`, `name`, `text` (≤200 chars), `value`, `attributes`.
- `states`: the D10 row-state names `hidden`, `disabled`, `checked`, `selected`, `readonly`, `required`, `expanded`, `focused`.
- `frame_id`, `frame_path`, `shadow_path`.
- `xpath`: an absolute, index-qualified path per frame document, for example `/html[1]/body[1]/form[1]/input[2]`. Inside a shadow tree it is the path relative to the shadow root, with `shadow_path` listing host XPaths. On desktop it is an index-qualified path over the projected tree.
- `path`: the native handle (`uia-runtime-id`, `ax-path`, `atspi-path`; browser `backend_node_id`).
- `boxes`:
  - `document_css_px`, `layout_viewport`, `visual_viewport` and `frame_document`: really distinct values. Coordinates come from `DOMSnapshot` layout plus layout metrics, not copies of one box.
  - `screen_px` (desktop).
  - `image_px`: the box in screenshot pixels, so any node maps onto the image.
- `in_viewport`, `interactable`, `capped`, `cap_reason`, `section_path`.
- `paint`: `color`, `background`, `contrast`, `mean_rgb`, `dhash`.

### Row 17 — Pre-mapping as a CORE principle
**Decision:** `PreMapBuilder.build(DomNode root, SnapshotContext ctx)` runs inside every `CompositeSnapshotBuilder.build(...)`. There is no flag to disable it. A test asserts that every producer's output has a non-empty `premap`.

`premap` contains:
- `sections` (row 15).
- `labels[]`: `label`, `target`, `score`, `parts`, `reasons` (row 12); and `unlabeled[]`.
- `boxes`: caps used and the rejected count (row 14).
- `viewport_map`: handle → `image_px` / `visual_viewport` boxes.
- `indexes`:
  - `by_role`, `by_role_name` (with the bound label text as a name fallback for controls without an accessible name)
  - `by_text_token`, `by_tag`, `by_id`, `by_class`, `by_xpath` (absolute index paths), `by_section_title`
  - `interactables`, `in_viewport`
- `image`: per interactable and label, a 64-bit `dhash` and `mean_rgb` from the screenshot crop (`TemplateMatch.Features`), plus a 16×16 luminance grid of the screenshot.
- `colours`: per node foreground, background and WCAG contrast.

**`dev.domengine.premap.PreMapLookup`** (contract):
- `Optional<PreMap> current(String sessionId, String docVersion)`.
- `Optional<List<String>> candidates(String clauseKind, String value)`.
  - An empty Optional means the index cannot answer that clause, so the caller evaluates live.
  - A present list is the authoritative candidate set, possibly empty.
  - Clause kinds: `role`, `role-name`, `text`, `text-exact`, `tag`, `id`, `class`, `css-simple` (a single compound selector), `xpath-abs`, `label`, `section`, `image`.
- `PreMapLookup.forTree(DomNode root)` caches offline trees by identity.
- `PreMapLookup.store(sessionId, PreMap)` is called by the builder.
- **Phase 1 default (pass-through):** `current` returns `Optional.empty()` and `candidates` returns `Optional.empty()`. The pass-through classes are named `PreMapLookup.PASS_THROUGH` so G2 can wire its hooks without blocking.

**Document version (staleness):**
- **Browser:** `doc_version = "<loaderId>:<mutationCount>"`. The producer installs a MutationObserver counter in a CDP isolated world named `pkb-premap` (`Page.createIsolatedWorld` + `Page.addScriptToEvaluateOnNewDocument` with `worldName`) on the engine's own connection. One `Runtime.evaluate` in that world reads the version. In the root facade path the same script goes through G1's `addPreload` / `evaluateIsolated`.
- **Desktop:** a capture sequence number. `DesktopTree.click/type/walk` bump it and re-capture.

**Runtime (W3):** a session query reads the version.
- If `current(...)` is fresh, G2's `Query` asks `candidates(...)` and evaluates the remaining predicates only over those handles. Relatives are scored by `AffinityScorer`, and resolution goes through `OneMatch`.
- If it is stale or absent, the engine rebuilds the pre-map first (one `DOMSnapshot` call path) and then looks up. So **every session query is a pre-map lookup**.
- `--explain` reports `premap: hit|rebuilt <ms>` and the candidate count per clause. EngineLog entity `premap` logs `INFO premap hit|rebuild nodes=<n> ms=<t>`.

**Files:** `premap/{PreMap,PreMapBuilder,PreMapLookup,DocVersion}.java`, `snapshot/CompositeSnapshotBuilder.java`, `image/TemplateMatch.java` (additive `Features`).
**Tests:** `dev.domengine.premap.PreMapTest`, `PreMapLookupDefaultsTest`, `PreMapStalenessTest`, `QueryUsesPreMapTest`.
**Docs:** `docs/snapshot.md` § Pre-map (core). The `AGENTS.md` sentence describing snapshots is rewritten in place in Phase 8.
