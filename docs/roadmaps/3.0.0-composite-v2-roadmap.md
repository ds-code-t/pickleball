# 3.0.0 Composite v2 Roadmap

**Date:** 2026-11-23
**Branch:** `3.0.0-composite-v2` only, created from `origin/3.0.0` at `c337ea27`. Never `master` or any 2.x branch. No tags, releases, Maven publishing, or force-push.
**Design:** `docs/maintainer/3.0.0-composite-v2-design.md`

## Approved design

Composite is the only engine. Early 3.x accepts both snapshot versions. Producers emit v2. Consumers still read v1.

The canonical form is raw HTML per browser frame, including shadow roots and iframes, and a synthesized HTML-ish DOM for Windows UIA, macOS AX, and Linux AT-SPI. Flat `nodes[]` and `premap` are derived projections. Desktop keeps the native path and the original a11y-xml as side data. v1 stays `$id` `urn:pickleball:composite-snapshot:1`, schema `pickleball.composite-snapshot`, version 1. v2 uses `$id` `urn:pickleball:composite-snapshot:2` and version 2.

The Control Engine DSL stays the high-level query layer. `xpath=` and `css=` evaluate real XPath 1.0 and CSS on the canonical tree. Indexes stay fast paths. Human and full-access views are lazy masks applied before evaluation. Human is the default for tests that reflect real use: elements actually seen in the viewport, or reachable in the active accessible context by scrolling or expanding. Reachable is computed from state and geometry flags only. The engine does not scroll or expand to decide it. Full-access ignores overlap and the viewport. Human mode governs mouse and keyboard input only. A step that targets something outside the human mask is not a failure.

Replay records a fallback chain on each element: stable attributes, then native path, then fingerprint, then the positional index-qualified XPath. Replay tries that order and reports which locator matched.

OCR runs only on image, SVG, and icon elements, cached by image hash and shared by both views, gated per view. With no OCR runtime installed the result is `OCR runtime not installed`. Nothing is downloaded.

JDK 21. No FFM. No new dependency is added in this work.

## Flagged dependencies (not added)

| Item | Why it is named | Decision this branch |
|---|---|---|
| Microsoft-signed ONNX Runtime and a light OCR model | Locked perception stack for image, SVG, and icon text | Not bundled and not downloaded. The hook returns `OCR runtime not installed` until `pkb_ocr_runtime` or `PKB_OCR_RUNTIME` points at an existing file. A `pkb-ocr 1` text file is the only runtime this build reads. Any other existing file returns `OCR runtime cannot be invoked`. The file is not executed. |
| FlaUI.WebDriver (Windows) and other Grid-ready desktop drivers | Locked direction for live desktop attach | Not added. Capture stays on the existing UIA, AX, and AT-SPI producers. Synthesis reads that tree. A driver swap is a later change with its own license note. |

## Phase notes

Targeted tests only. No full suite and no consumer sims until a later program asks for them. Phase 9 runs the targeted tests from Phases 1–8 plus the snapshot, query, and coverage test classes.

Each phase commits on `3.0.0-composite-v2`, fetches, rebases onto `origin/3.0.0-composite-v2` once that branch exists, and pushes. Never force-push.

Phase 2 emits version 2 only when the source kind is `html` and the transport is not `fixture`. An explicit `CanonicalDocument` still wins. Offline fixture snapshots stay version 1 so the phase 1 schema and model checks keep validating v1 documents. Phase 4 switches offline `--file` to version 2 when `nodes[]` and `premap` are projected from the canonical HTML, and updates those checks to the schema for the document version. Desktop `a11y-xml` stays version 1 until phase 3. Canonical frame `url` is empty; `frames[]` still carries the producer URL. `data-pkb-frame` is serialized on the iframe and is not reparsed into a separate frame until phase 4. No new CDP calls were added.

Phase 3 emits version 2 for desktop snapshots. `canonical.kind` is `html-ish`, one frame id `desktop`, and `canonical.side.a11y_xml` is the same string as `source.text`. The role-to-tag map calls `NativeDesktop.mapRole` and does not add a second map. A capture root whose projected role is `desktop` is not emitted; its children are the body. UIA `AutomationId` and `ClassName` become `id` / `class` only for backend `uia`. Help text becomes `title` on every backend. Windows UI Automation now writes `ATTR` lines for AutomationId, ClassName, and HelpText when the element has them. That uses the existing UIAutomationClient assembly. FlaUI.WebDriver is still not added. Phase 4 projects `nodes[]` and `premap` from the canonical HTML. `data-pkb-shadow` becomes a shadow root and `data-pkb-frame` links the child frame. Desktop `data-x` / `data-y` / `data-w` / `data-h` become the screen box. Live boxes, roles, names, and states are copied onto the parsed elements because raw HTML does not carry accessibility geometry. Offline fixture HTML now emits version 2. A document with version 1 and no canonical tree still validates. Two builds of the same canonical HTML produce the same `nodes[]` and `premap`.

Phase 5 keeps the Control Engine DSL. An absolute path whose every step is `tag[n]` is answered by `XPathIndex`, and a miss is zero hits. The existing tag, attribute, and `contains()` subset stays. Anything else is XPath 1.0 through `javax.xml.xpath` on an XML document built from that scope's light tree. Shadow roots are separate documents when pierce is `open` or `all`. Iframes are not crossed. An invalid expression is an error. Live `document.evaluate` is unchanged. CSS adds the adjacent and general sibling combinators and the `~=` and `|=` attribute operators that the simple index refuses. No new XML or CSS library.

Phase 6 applies a lazy human mask when `exposure=human`. Seen means the box intersects the viewport, the node is displayed, and no later opaque node covers it when a paint order was stored. Scroll-reachable and expand-reachable use stored boxes, scrollport sizes, and collapsed regions only. The query does not scroll or expand. A collapsed control with no box and no stored region is not reachable. `exposure=full` and `exposure=full-access` keep every node. A query with no exposure stays unfiltered so existing structural queries keep matching. Real-use callers pass `exposure=human`. The mask is cached per tree and document version and is not a second tree. Index hits are intersected with it. An action lookup sets `mask=off`, so a click or type still finds a target outside the human view.

Phase 7 records `identity.chain` on each v2 node. The steps are a unique stable attribute (`id`, `data-testid`, `data-uia-automation-id`, then role plus name plus section), a desktop `uia-runtime-id`, `ax-path`, or `atspi-path` that is not all digits, a fingerprint of dHash, text, and relative bounds, and the index-qualified XPath with its shadow and frame paths. A missing source is omitted. Replay tries that order, stops at the first hit, and reports `matched`, the locator, and the chain index. dHash uses `TemplateMatch.prefilter` at 10 bits. Text must match after trim. Each relative component must be within 0.05. A version 1 document does not carry the chain.

Phase 8 runs OCR only for tag `img`, tag `svg`, role `img`, or role `image`. The cache key is the SHA-256 of the crop width, height, and pixels. One process cache is shared by both views. A hit does not open the runtime. The human mask is applied first. An element outside it is not recognized and is not a cache miss. A full-access call can fill the cache. A later human call for the same hash uses that entry when the element is in the mask. Resolution is `pkb_ocr_runtime`, then `PKB_OCR_RUNTIME`. A blank property falls through. A set property that is not an existing file does not. A directory is not a file. Unset, blank, or missing returns `OCR runtime not installed` with code `ocr_runtime_missing`. This build does not execute the file. A text file whose first line is `pkb-ocr 1` maps a crop hash to the rest of that line. A hash with no line stores an empty string. Any other existing file returns `OCR runtime cannot be invoked` with code `ocr_runtime_unsupported`. Failures are not cached. `image=ocr` keeps non-blank text. `image=ocr:<text>` keeps an exact match. A query with no eligible element does not call the runtime. ONNX Runtime stays flagged and is not bundled.

Phase 9 records the v2 contract in `docs/snapshot.md`, `AGENTS.md`, `docs/release-notes.md`, and the feature map. Version 1 still validates. `capabilities.snapshot_schema` stays 1. ONNX Runtime and FlaUI.WebDriver stay flagged and are not added. The final run is the phase 1–8 targets plus the snapshot, query, and coverage classes: 91 tests, 2 skipped because `microsoft-edge` is not on PATH, 0 failures. A live Windows desktop snapshot had hung in `HtmlTree` because an `input` or `img` with children was written with an end tag and the parser treated the tag as void, then spun on that end tag. The parser now keeps those children, leaves a void tag with no matching end tag empty, and skips a stray end tag. `DesktopSnapshotTest.textboxChildStaysInsideTheControlAndAStrayCloseReturns` covers that path. `SnapshotCoverageTest.liveDesktopWhenThePlatformExists` passed. `python scripts/verify_agent_contract.py`, `python scripts/refresh_agent_index.py --check`, and `python scripts/sync_consumer_guidance.py --check` passed.
