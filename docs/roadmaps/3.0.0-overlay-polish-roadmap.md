## Decisions for Dan (defaults are used unless he says otherwise)

- **D1 Live geometry.** Today the docs say "no `getBoundingClientRect` fallback" (`docs/dynamic-control-api.md:124`). New default: the box resolved in Java is used for the first paint and for pure x/y placements. Once the runtime holds the live element, it tracks it with `getBoundingClientRect`. Result fields `x`, `y`, `width` and `height` still report the resolved box, so existing assertions hold.
- **D2 Callout placement.** The overlay callout moves **beside** the target, with a ring on the target's own box. It no longer covers the target. `--at=over` keeps the old covering placement, now translucent and click-through.
- **D3 State storage.** Overlay state is stored by the agent by default in `.pickleball/runs/<run>/agent/ui-state.json` and replayed through a new-document preload. Page `sessionStorage` is opt-in with `pkb_ui_page_state=session` (the default is `off`), because page scripts can read it.
- **D4 Isolated world.** The runtime runs in the CDP/BiDi isolated world `pkb-surface`, out of reach of page scripts and page CSP. Selenium-only sessions (no CDP and no BiDi) fall back to the main world and re-inject lazily on the next agent command. This platform difference is documented.
- **D5 Old verbs stay.** The 34 existing verbs stay and are re-implemented on the runtime. A new batch verb `ui` and a catalog verb `ui-catalog` are added. Nothing is removed.

## Target design (shared by all phases)

- **One runtime asset:** `src/main/resources/tools/dscode/browser/surface/pkb-runtime.js`, loaded through `SurfaceAssets.script("pkb-runtime")`. It exposes `__pkbUi` in its world: `apply(ops)`, `remove(ids)`, `clear()`, `state()`, `drain(after)`, `version`. It is idempotent: a second install is a no-op that returns the version.
- **Layer:** one host `<pkb-layer data-pkb-agent="agent_injected">` on `document.documentElement`, with an open shadow root. Where supported it is shown with `popover="manual"` and `showPopover()` so it sits in the top layer above page dialogs; otherwise it uses `z-index:2147483647`. The layer is `pointer-events:none`, and only interactive chrome (panel, callout buttons, confirm/ask fields) is `pointer-events:auto`. Styles go through `adoptedStyleSheets` (CSP-safe) and nodes are built with DOM APIs (Trusted-Types-safe). Agent HTML passes through the existing Java `neutralize`, then a Trusted Types policy `pkb-surface` when the page allows one, else it renders as text.
- **Look:** CSS custom properties for tokens. System font stack, 13-14px, 8px radius, soft shadow, accent `#3b82f6`, tones info/ok/warn/danger. Light and dark follow `prefers-color-scheme` (forced with `theme=light|dark`). Transitions animate only `transform` and `opacity` (120-160 ms ease-out) and are disabled under `prefers-reduced-motion`. All positioning uses `transform: translate3d()`. Each frame reads every rect, then writes every transform, so there is no layout thrash.
- **Tracker (items 4 and 10):** for each anchored element:
  - **Listeners:** `document.addEventListener('scroll', schedule, {capture:true, passive:true})`, which catches every scrollable ancestor, nested ones included. Also `window` `resize`, `visualViewport` `resize` and `scroll` (pinch zoom and browser zoom), a `ResizeObserver` on the target and on each scrollable ancestor (`overflow` auto, scroll or hidden, computed once and refreshed on mutation), and `document.fonts.ready`.
  - **MutationObserver** on `document` (`childList`, `subtree`, `attributes` filtered to `class`, `style`, `hidden`, `open`). Only one rAF reposition is scheduled per frame. When a target is detached, the runtime re-resolves it from its stored locator (handle mark, CSS path, text and role). If that fails, the placement is hidden and emits `{k:"lost",id}`; it reappears if the target comes back.
  - Also `popstate`, `hashchange`, `pageshow`, and `visibilitychange` (pause while hidden).
  - **Clipping:** the visible rect is the target rect intersected with every scrollable ancestor's padding box and with the viewport. A placement that is partly visible is clipped with `clip-path: inset()`, and one that is fully out is hidden (`opacity:0`, `visibility:hidden`). A callout flips to the side where it fits.
- **Pass-through (item 5):** a ring is an outline only (`box-shadow` ring, no fill; `fill` at most 0.08 alpha only if asked). The spotlight is a dim layer with a hole made by a four-rect frame, so the hole receives clicks; the dim blocks only with `block:true`. The magnifier sits beside the target, never on it. Every non-interactive node has `pointer-events:none`.
- **Events:** the runtime pushes events through the CDP binding `pkbSurface`, added with `executionContextName: "pkb-surface"` (the BiDi channel is the equivalent). It also queues them in its own world, and `drain` reads that queue in the **same** world. The Selenium fallback reads the main-world queue as today.
- **State (item 6):** after every change, `ui-state.json` (ordered ops, panel position and size, guide progress, scope) is written under a lock, and the runtime preload is re-registered with an embedded state snapshot (`Page.removeScriptToEvaluateOnNewDocument` + `addScriptToEvaluateOnNewDocument` with `worldName`, or BiDi `script.addPreloadScript` with `sandbox`). On a new document the runtime replays only ops whose `scope` matches: `page` (same origin and path, the default), `origin`, or `run`. `clear` empties both the state file and the preload. Scenario end clears.
- **Compact agent surface (items 8 and 9):**
  - **Batch verb** `ui --ops='<json array>'` (or `--ops=@file.json`). Short keys: `op`, `t` (target), `id`, `n` (number), `say`, `at` (`auto|top|bottom|left|right|over`), `tone`, `block`, `scope`, `ttl`.
  - **Targets:** `h:<handle>`, plain CSS, `x:<xpath>`, `text:<visible text>`, `role:button[name=Save]`.
  - **Defaults:** `at=auto`, `tone=info`, `block=false`, `scope=page`. Ids are short (`o1`, `o2`, …) and unique per page.
  - **Reply:** `{"ok":true,"ids":["o1","o2"],"miss":[]}`. The full provenance body is returned only with `--verbose`.
  - **Inbox verb** `ui-poll --after=<cursor> [--wait=<s>]` merges chat, clicks, step and lost events into `{"c":"<cursor>","ev":[…]}`, so an agent does one long-poll instead of three polls.
  - **Toolbox:** `ui-catalog` prints the catalog (each component, options with defaults, a one-line example), generated from the same Java registry `UiCatalog` that validates ops, so the two cannot drift. MCP adds `ui`, `ui_poll` and `ui_catalog` with typed schemas, in a new class `WorkbenchUiTools`.
  - **Components:** `ring`, `callout`, `badge`, `arrow`, `spotlight`, `magnifier`, `label`, `border`, `panel`, `guide`, `toast`, `confirm`, `ask`, `remove`, `clear`. Old verbs map onto them: `highlight` and `overlay` → `ring`+`callout`, `step-badge` → `badge`, and so on.

### P4: Guided steps (item 7)

- **Functionality:**
