# 3.0.0-agent-fast roadmap

**Status:** in progress. Every phase is mandatory and must be completed in full. Nothing is optional or deferred.

**Goal:** fix every confirmed bug in the 2026-11-18 consumer field report and make Workbench and all Pickleball dynamic functionality fast, responsive and cheap for AI agents. See design.md for the locked decisions, target-agnostic API, tiers, fallbacks, watcher/push, frame/shadow, snapshot, compact formats, prebuilts, and what is deliberately not done.

**CLI-first and logging checklist (every phase):**
- CLI is the source of truth. Workbench, MCP and Gradle tasks only forward to the CLI.
- Toggleable, per-entity, date-stamped, size-capped logging (same pattern as StoreLog / EngineLog). No secrets in cleartext.
- Docs rewritten in place. History only in `docs/release-notes.md`.
- Never truncate `AGENTS.md` or `docs/agent/feature-map.md` (compare `wc -c` before push).
- Before every push: `python3 scripts/refresh_agent_index.py`, its `--check`, `python3 scripts/verify_agent_contract.py`, `python3 scripts/sync_consumer_guidance.py --check`, remove `scripts/__pycache__`.
- Exported guidance never links to `docs/maintainer/`, `docs/roadmaps/` or `prompts/`.
- Do not edit `.github/`. Draft PR #26 runs both CI workflows on every push via `pull_request`.
- Small pushes, at least one per phase. `git fetch origin && git pull --rebase origin 3.0.0-agent-fast && git push origin HEAD:3.0.0-agent-fast`.
- After each phase run ONLY its targeted tests. A failed targeted test stops the ladder until honestly fixed.
- HELD: full multi-module regression, `validate --all`, Maven `@all`, audit fixes F1-F12.

## Phase 1 — Critical bugs (B1, B4, B5, B2/P3, B14, B16)

**Functionality:**
- B1: guard `raiseLayer` against re-entry and ignore layer-originated `toggle` events in `pkb-runtime.js`. Selftest CPU assertion.
- B4: on worker stop/restart call `WebDriver.quit()` and `ProcessTrees.killTree`; emit `browser_lost`.
- B5: document the 120s/30s lease; hold the pause while any client (MCP or CLI) is attached via heartbeat; emit session-ended event. `--hold` available.
- B2/P3: CLI agent verbs POST to the live worker's `/v1/agent/command` when a session exists; fail fast with `error: no live browser` otherwise. No second transport.
- B14: quote `"-Dmdep.includeScope=test"` in the generated PowerShell opener; include `target/classes` and `target/test-classes` on the fallback classpath.
- B16: flag empty consumer glue as `noop:true` on step replies and warn in the run report by default. Opt-in may turn it into a failure.

**Docs:** rewrite relevant sections in place (`docs/consumer-agent-guide.md`, `docs/pickleball-workbench.md`, `docs/dynamic-control-api.md`, release-notes).

**Named targeted tests:** `UiCpuLoopTest`, `WorkerRestartBrowserTest`, `LeaseHoldTest`, `CliForwardToWorkerTest`, `OpenerQuoteTest`, `NoopGlueFlagTest`.

**Acceptance:** panel-open does not spin CPU; worker restart leaves no orphan Chrome; lease holds while client attached; CLI page verbs reach the live browser or fail fast; PowerShell opener works; no-op glue is flagged and warned.

## Phase 2 — Performance (instrumentation and measurable targets)

**Functionality:**
- Add timing fields to every agent reply.
- Compact defaults for inspect/page/step (P4). `screenshot --out=`. Avoid re-injecting the runtime when already present.
- Selftest `ui --cpu` bench mode.
- Targets (starting, Build must measure and report):
  - First warm verb after classpath cache ≤ 1 s
  - Per-step latency tracked
  - UI op p95 ≤ 150 ms
  - Idle CPU after panel-open ≤ 0.1 core within 500 ms
  - Compact reply size ≤ 2 KiB

**Docs:** performance section in consumer guide and release-notes.

**Named targeted tests:** `CompactReplyTest`, `TimingFieldsTest`, `SelftestCpuBenchTest`, `NoReinjectTest`.

**Acceptance:** timings reported; compact replies default; CPU idle after panel-open; no re-inject on warm path.

**Acceptance:** `start --url --browser` opens a headed browser; doctor reports health; chat cursor is session-scoped.

**Functionality:**

- Closed shadow via `DOM.resolveNode` in pkb world. Open via pierce.
- Virtualized list scroll-search as an AGENT one-call.
- Robust nested, dynamic, cross-origin, about:blank frames.

**Docs:** frame/shadow section.

**Named targeted tests:** `OopifAutoAttachTest`, `FrameInReplyTest`, `ClosedShadowResolveTest`, `VirtualizedScrollTest`.

**Acceptance:** cross-origin iframes covered continuously; replies include frame; closed shadow accessible; inspect parity or explicit report.
