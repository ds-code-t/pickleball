## Decisions

### Addendum B — Universal agent surface popup
- **Decision:** New `AgentSurfacePopup` (workbench UI package) launches a small Chromium/Edge/Chrome `--app` window (OS-specific discovery, always-on-top where OS allows) hosting the identical HTML surface (chat, instructions, diagrams) as in-page surfaces. Thin native highlight remains only via `WorkbenchNativeOverlay` for precise native control pointing.
- **Lifecycle:** Open on first agent chat/command for desktop sessions (optional for browsers via config); single instance per session; close on session end or explicit close command.
- **Channel:** Prefer CDP to the popup page via G1's `BrowserFacade`/`CdpAdapter`. Temporary local HTTP/WebSocket bridge for W1 until G1 contracts land.
- **Fallback:** If no Chromium-family browser found, log one WARN per run with reason and fall back to existing `AgentChatPanel` / Workbench panel.
- **Relation:** `AgentChatPanel` becomes the embedded/fallback surface. Popup and in-page share assets via G1 `SurfaceAssets` loader (temp local copy until G1).
- **Files:** new `AgentSurfacePopup.java`, updates to `AgentChatPanel.java`, `WorkbenchNativeOverlay.java`, resources under `ui/web/`, `AgentSurfaceEnd.java`. MCP commands registered via G1 registry (own command classes).
- **Tests:** `AgentSurfacePopupTest` (launch, content load, fallback).
- **Docs:** `docs/pickleball-workbench.md`, `docs/direct-control-handoff.md`.

### Row 18 — Dalton central by default
- **Decision:** Flip to central. `DaltonConfig.enabled()` returns true by default (no flag and no properties file means on). Explicit `pkb_dalton=false` (system prop, env, or properties `enabled=false`) opts out. Existing tests that pass `-Dpkb_dalton=false/true` continue to work. Files remain Git source of truth; DB is working copy. Auto-hydrate on start when enabled.
- **Approach:** Change resolution order in `DaltonConfig.enabled(Path)`. Update all docs to describe central default.
- **Files:** `DaltonConfig.java`, related Dalton runtime/hydrator, `docs/configuration.md`, `docs/maintainer/3.0.0-dalton-design.md`, `AGENTS.md`.
- **Tests:** `DaltonDefaultOnTest`, existing `Dalton*Test` classes.
- **Docs:** all Dalton sections rewritten in place.

### Row 19 — Rust fully replaced by Java, no residuals
- **Decision:** Remove all Rust paths and overrides. Drop `pkb_composite_engine=rust`, `COMPOSITE_HOME` / sibling `dom-composite` homes, `dev.domcomposite:composite-native` classifier lookups, and `composite` on PATH. Keep (or carefully rename) the stdio client (`dev.domcomposite.Client.java`) as the client used by the Java engine CLI. Keep `pkb_composite_bin` only if it retains meaning for an explicit Java engine binary override; otherwise remove. Rust wire-compatibility comments and vendored fixtures: move to historical notes in release-notes.md; keep fixtures if still used by Java `conform`.
- **Timing:** W4 only, after G1 W3 default-path changes and engine-defects Phase 8 are on origin.
- **Files:** `CompositeBinaryLocator.java`, `CompositeRuntime.java`, `DomCompositeAdapter.java`, `JavaEngineLocator.java`, `JavaEngineLauncher.java`, `DirectControlProvider.java`, `build.gradle` (shared-with-care), `Client.java`.
- **Tests:** `NoRustResidualsTest` (grep-style assertions on remaining references).
- **Docs:** remove all Rust-first/override text.

### Rows 20–22 — Confirm implemented
- **Decision:** Per sweep and design docs, all three are implemented. Confirm with targeted code reads and short test runs. No additional phases unless a concrete gap is found during confirmation (none expected).
- **Approach:** Run named tests for Cucumber optional/unified paths, Workbench edit coverage, DynamicControl/parity/default switch. Record results in scoreboard.
- **Files:** none if confirmed; otherwise minimal targeted fixes in owned files.
- **Tests:** existing Cucumber, Workbench, DynamicControl test classes.
