## Decisions

### Addendum B — Universal agent surface popup
- **Decision:** On Windows, macOS, and Linux desktop sessions (optional for browsers), launch a small always-on-top app-mode Chromium window (`--app=...`) hosting the agent chat, instructions, and diagrams using the identical HTML surface assets and command set as in-page surfaces. Thin native highlight box remains only for precise pointing at native controls. Identical experience on every platform.
- **Approach:** New `AgentSurfacePopup` (in `pickleball-workbench/.../ui/`). Discover Chrome/Edge/Chromium per OS. Lifecycle: open on first agent chat/surface command if desktop session and no existing popup; close on session end or explicit close. Communication: prefer CDP to the popup page via G1 `BrowserFacade`/`CdpAdapter` (once available); for W1 use a temporary local HTTP/WebSocket bridge owned by G4. Fallback: log WARN once per run with reason and fall back to existing `AgentChatPanel` / Workbench panel. `WorkbenchNativeOverlay` stays as the thin native highlight only.
- **Files:** new `AgentSurfacePopup.java`, updates to `AgentChatPanel.java` / `WorkbenchNativeOverlay.java` (fallback relation), resources under `ui/web/`, `AgentSurfaceEnd.java` (consume). Consume G1 `SurfaceAssets` loader and MCP registry (add own command classes).
- **Tests:** `AgentSurfacePopupLaunchTest`, `AgentSurfacePopupFallbackTest`.
- **Docs:** rewrite relevant sections of `docs/pickleball-workbench.md`, `docs/direct-control-handoff.md` in place.

### Row 18 — Dalton portable artifact central by default
- **Decision:** Dalton is central by default. `DaltonConfig.enabled()` returns true unless an explicit false is supplied via system property, environment, or `dalton.properties`. Files remain the Git source of truth; the DB is the working copy. Explicit `pkb_dalton=false` (or properties `enabled=false`) opts out. Existing tests that pass `-Dpkb_dalton=false/true` continue to work unchanged. Auto-hydrate on start when enabled.
- **Approach:** Invert the default in `enabled()` / `fileEnabled()`. Document the new default. Preserve all existing flag paths.
- **Files:** `src/main/java/tools/dscode/dalton/DaltonConfig.java`, related runtime/hydrator if needed for auto-hydrate, tests under `src/test/java/tools/dscode/dalton/`.
- **Tests:** new `DaltonDefaultCentralTest`; existing Dalton tests re-run to confirm flags still work.
- **Docs:** rewrite in place `AGENTS.md` (Dalton section), `README.md`, `docs/configuration.md`, `docs/maintainer/3.0.0-dalton-design.md`.

### Row 19 — Rust fully replaced by Java, no residuals
- **Decision:** Remove all residual Rust support. Drop `pkb_composite_engine=rust`, `COMPOSITE_HOME`, sibling `dom-composite` lookups, `dev.domcomposite:composite-native` classifier extraction, and `composite` on `PATH`. Keep `src/main/java/dev/domcomposite/Client.java` as the stdio client used by the Java engine (document this clearly; do not rename unless consumers require it). Keep explicit `pkb_composite_bin` only if it retains a Java-engine override meaning; otherwise remove. Rust wire-compatibility comments and any vendored conformance fixtures: retain only those still used by the Java engine; move pure historical notes to `docs/release-notes.md`.
- **Approach:** After gates, delete Rust branches and locator paths. Update comments. Coordinate rebase with G1 on `CompositeRuntime.java`.
- **Files:** `CompositeBinaryLocator.java`, Rust branches in `CompositeRuntime.java` / `DomCompositeAdapter.java`, `JavaEngineLocator.java`, `JavaEngineLauncher.java`, `DirectControlProvider.java`, `build.gradle` (classifier bits), `Client.java` (remove Rust launch paths).
- **Tests:** `NoRustResidualsTest` (grep-style assertion), existing engine tests.
- **Docs:** remove all Rust-override wording in the final sweep.
