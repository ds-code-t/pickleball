# Pickleball 3.0.0 Consumer-Ready Roadmap

**Branch:** `3.0.0-consumer-ready` (based on `3.0.0` at `6df91885` / current tip `f4748226`)  
**Owner:** One roadmap for Phases A–C. All items required unless explicitly deferred.  
**Source of truth:** This document + the branch docs. Check every report item against current code (file:line noted below).

## Phase A: Integrity and bug fixes

**Goal:** Stop the consumer-agent blockers. Worker lock-up and Workbench freeze first.

### A1. Workbench window freeze + JVM-exit/reuse
- **Location:** `pickleball-workbench/src/main/java/tools/dscode/workbench/ui/WorkbenchFrame.java:1025-1026` (`applyCatalog` → `picker.setCatalog`), `:2426` (success callback on UI thread), `:2454` (`publishWorkStatus` → `revalidate`). `FeaturePickerPanel.java:141-153` (`setCatalog` adds one-by-one), `:311-319` (`refreshScenarios` adds one-by-one).
- **Fix:** Build `DefaultListModel` offline, `setModel` once; `setFixedCellHeight(20)` (or prototype); single `setSelectedIndices`; reuse renderer `JLabel`; optional first-500 + paging. Exit JVM on last window close (or reuse existing process on `open-window`).
- **Tests:** `WorkbenchFrameLoadTest` (large catalog timing < 2 s UI), `WorkbenchWindowLifecycleTest` (close exits or reuses).

### A2. Worker lock-up + watchdog + working restart
- **Location:** Worker process (`src/main/java/tools/dscode/testengine/WorkbenchWorkerMain.java` and bridge HTTP). Report: JDK `HttpClient` selector thread stuck after ~2 min on Pega pages; `workbench_worker_restart` stops but never starts.
- **Fix:** Watchdog thread (CPU/timeout on selector); auto-restart that actually launches a new worker; health endpoint that fails fast. CLI `worker restart` and MCP forward.
- **Tests:** `WorkerWatchdogTest` (simulated stuck → restart succeeds), `BridgeHealthTest`.

### A3. Warm-JVM glue: DataTable converters + consumer `@Before`
- **Location:** Worker classpath / Cucumber glue loading in warm JVM path (not the cold Maven path). Report: "DataTable was created without a converter"; `@Before` state null.
- **Fix:** Ensure consumer glue + converters are on the warm worker classpath and registered before any step. Same for `@Before`/`@After` hooks.
- **Tests:** `WarmJvmGlueTest` (DataTable step + `@Before` state visible).

### A4. Accurate run history
- **Location:** Store recording (`src/main/java/tools/dscode/store/` especially history/query paths) and catalog (`run-catalog.json` writer).
- **Items:**
  - SKIPPED status recorded correctly (not as PASSED).
  - Nested component / `RUN SCENARIOS` steps stored.
  - Agent runs appear in the run catalog.
  - One source of truth: document and make `query` and `store` agree (prefer store as canonical; query is a view).
- **Tests:** `RunHistoryAccuracyTest` (skipped, nested, agent run in catalog).

### A5. Entity reference resolution
- **Location:** Mapping / entity lookup during step execution (likely `src/main/java/tools/dscode/common/mappings/` or runtime). Report: `<entity:Operator#ae-mgr-all.app>` stayed literal.
- **Fix:** Resolve `<entity:Type#id>` at runtime against the store / `.entity` files.
- **Tests:** `EntityResolutionTest`.

### A6. Run-id reuse never overwrites finished run
- **Location:** Store run recording / isolate path.
- **Fix:** Refuse or version a finished run id; never silently overwrite.
- **Tests:** `RunIdReuseGuardTest`.

### A7. Smaller defects
- `ui chat` returns ok but nothing appears (agentsurface / chat path).
- `inspect-page` reports no session while one is live (session publication).
- `java -jar pickleball-3.0.0.jar domengine` → `NoClassDefFoundError` (manifest / entrypoint).
- Diagnostic step text `null`.
- `store steps list` drops nested `:` steps.
- `store run` (fast path) slow (247 s for 4 steps) — optimize recording.
- **Tests:** One focused test per defect.

### A8. Store test failures from the 2026-11-16 full regression (at 6df91885)
- `StoreEdgeTest.parallelHistoryWritesShareTheWalDatabase` is a real bug: concurrent `StoreDatabase.open` races `CREATE TRIGGER` (`files_pkb_insert` / `files_pkb_update`). Make schema setup safe under concurrent opens (`IF NOT EXISTS` plus a guarded transaction or retry on SQLITE_BUSY/"already exists").
- `StoreEntityUsageTest.aRealStepRecordsTheLookup` and `StoreExecutionRecordingTest.aRunRecordsStepsAndLinksTheMatchingDefinition` depend on test order: leftover rows from consumer runs leak in. Give each test an isolated store, and never weaken their assertions.
- **Tests:** these three must pass both alone and in the full root `:test` order.

### A9. Tracking and Store tabs empty (consumer report P2-24)
Source: `docs/maintainer/3.0.0-consumer-report-2026-11-17/bug-p2-24-tracking-store-tabs-empty.md`.
- Cause: `StoreCliForwarder` (about lines 71-80) runs `java -jar <thin pickleball jar> store ...`; the jar has no `Class-Path`, so `org.xerial:sqlite-jdbc` (store) and Jackson (domengine) are missing and the command fails. `TrackingPanel` (about lines 223, 250) shows the failure only in the status label, leaving the table empty. The Store tab shares the forwarder.
- Fix (chosen approach, no distribution change): run the forwarder with the consumer classpath the Workbench already resolves, `java -cp <resolved cp> tools.dscode.launcher.PickleballWorkbenchLauncher store ...` (same for `domengine`). Do NOT turn the published jar into a fat/shaded jar (that would change distribution and licensing); keep it thin.
- Show forwarder errors (stderr and exit code) inside the table area of the Tracking and Store tabs, not only in the status line.
- Fix every doc example that says `java -jar ... store` or `java -jar ... domengine` so it works for a consumer (classpath form, or the B1 CLI once it exists). The B1 CLI must resolve the same classpath.
- Tests: forwarder builds a `-cp` command with sqlite-jdbc and Jackson present; a forwarder failure renders a visible error in the table; a populated store shows rows in the Tracking and Store tabs.

### Phase A rules
- "Location" lines marked "likely" are guesses. Find the real code first and note the real file:line in the scoreboard.
- Every A-item test must be deterministic. A1 asserts the model is set once, fixed cell height is set, and selection is a single call, plus a bounded-time check on a 10,000-row synthetic catalog. Don't rely only on wall-clock thresholds.
- Consumer tests use port 8765 (`LocalTestSite`). Nothing else may bind it during tests.

**Docs updates:** `docs/pickleball-workbench.md`, `docs/consumer-agent-guide.md`, `docs/release-notes.md` (fix-back notes).  
**CLI-first:** Every new command reachable from CLI; MCP/Workbench only forward. Logging toggleable, per-entity, date-stamped, size-capped.

## Phase B: Turnkey agent tools and instructions

**Goal:** An agent can start and work without custom relays or IDE MCP.

### B1. Ready-made CLI (MCP forwards)
- `start --url= --browser= --env=` → returns live session; subsequent CLI page commands target it.
- Blocking `chat_wait`.
- History summary + query.
- Entity lookup.
- Open a run in Explorer or Tracking tab.
- Bridge health signal.
- Fast launcher (cached classpath / `java -cp` path so agents avoid 10–16 s `mvnw` per call).

### B2. Supported agent route
- Exported consumer guide allows a pure-CLI route (no IDE MCP required). Document it clearly.

### B3. Fix missing instructions
- Headless meaning (Workbench headless ≠ browser headless; fallback behavior).
- Step-id format for `store entity use`.
- How to build the search index.
- former core name → `store` in release notes (already partially done; finish).

### B4. Update consumer agent guide
- Agent can start working from the guide alone (first-read + short notes).

**Docs updates:** `docs/consumer-agent-guide.md` (primary), `docs/ai-run-configuration.md`, `docs/release-notes.md`.  
**Tests:** CLI integration tests for each new verb; guide validation.

## Phase C: Polished static HTML dashboard

**Goal:** Passive, view-only dashboard generated from the same embedded SQLite store. No second database.

### C1. Data
- Add git commit SHA and feature-file path to runs if missing.
- Thin data-access layer (no hardcoded localhost) so a central backend can replace the local file later.

### C2. Features
- Rewindable timeline with markers (runs, scenarios, case IDs).
- Filters.
- Business-entity and case-ID panels.
- Common-error and case-type aggregation.
- Run detail.
- Links to feature file, data files, commit, artifacts.
- Virtualize long lists.
- Opened from Workbench and CLI (`dashboard` command). Existing Workbench features stay.

### C3. Constraints
- Vendored JS only (or zero external JS). No CDN downloads at runtime.
- Looks consumer-polished.

**Deferred (out of scope):** Central hosting, Java code views, case opened/closed lifecycle events.

**Docs updates:** `docs/pickleball-workbench.md`, new `docs/dashboard.md` if needed, release notes.  
**Tests:** Dashboard generation + smoke open; data layer unit tests.

## Acceptance (all phases)
- Named tests prove each item. No weakened, skipped, or deleted tests.
- CLI-first and logging checklist satisfied.
- Flag any distribution / licensing / security / external-download implications.
