## Phase 1: Boolean expression layer in the Java engine
**Functionality:**
- Implement lightweight expression parser in `dev.domengine.query` that recognizes parentheses, NOT, AND, OR.
- AND = intersection, OR = union, NOT = complement relative to current scope.
- Precedence as locked: parens > NOT > AND > OR; `>>` remains sequential outer pipeline.
- Existing pure `>>` pipelines unchanged.
- CLI: `domengine query --selector` (and `--pipeline`) accepts the new operators.

**Docs:** Update this roadmap. Append pointer in AGENTS.md if needed. Update engine CLI help if present.

**Tests:** Targeted unit tests in `:dom-engine:test` for Boolean combinations (AND intersection, OR union, NOT, parentheses, mixed with >>). Existing pipeline tests still green.

**CLI-first:** Boolean reachable from CLI. Logging of expression evaluation (toggleable).

## Phase 2: Visual relative engines (above, left-of, right-of)
**Functionality:**
- Add engines `above`, `left-of`, `right-of` in Engines.java parallel to `near` / `below`.
- Geometry definitions as locked (using hasBox / document_css_px or visual space). Sort by distance. Pierce as today.
- near and below unchanged.

**Docs:** Update design and this roadmap.

**Tests:** Targeted tests for each relative (above a button, left-of a label, etc.) against offline fixtures. Existing near/below tests green.

**CLI-first / Logging:** New engines reachable; log geometry space and distance ranking.

## Phase 3: "look" visual property engine
**Functionality:**
- Add `look` engine that matches computed style properties (color, background-color, opacity, display, visibility, font-*, etc.).
- Syntax: `look=color=red` or `look=opacity>0.5,background-color=#fff` (comma AND inside stage).
- CLI support.

**Docs:** Update design (confirm name and syntax) and this roadmap.

**Tests:** Targeted tests for look matches on style properties. Existing engines green.

**CLI-first / Logging:** look reachable; log matched properties.

## Phase 4: Pickleball adapter and step-text forwarding
**Functionality:**
- Confirm DomCompositeAdapter.queryEngine / findEngine and PageElementQuery.find(EngineQuery) forward richer text unchanged.
- Additive step-grammar support: optional "with look <prop> <predicate>" that maps to a look= stage (or full engine selector). Do not touch existing attribute / noattribute grammar or any Cucumber annotations.
- SelectorTranslator / related path stays thin.

**Docs:** Update dynamic-control-api.md or relevant docs if step text is documented. Update this roadmap.

**Tests:** Targeted tests that a step phrase with "with look color equaling red" produces a look stage and finds the expected node. Existing Gherkin / elementMatch tests green.

**CLI-first:** No new CLI; engine already covers it. Logging of forwarded selector.
