## Phases

### P1: Core hand-off on iframe apps (report priority 1 + round-3 a)

**Functionality:**

1. **Own UI is not a page candidate.** Covers round-3 a, D7, D10, 6.3.2 and 6.3.4.
   - Pickleball's own UI (panel, chat, cards, checklist, pins, toasts: any `data-pkb-*` / `pkb-` owned node) is never a candidate for page `find`/`act`/`highlight`/`upload --query`. The exception is when `--purpose=` names a pkb token, or the caller is in human exposure on the panel itself.
   - Page controls outrank pickleball text.
   - When exactly one candidate's role equals `--pick`, choose it instead of returning `ambiguous`.
   - An `ambiguous` reply lists each candidate with the reason it lost.
   - Reuse or redo `docs/maintainer/3.0.0-consumer-fixes/r3-item-a-wip.patch` (uncommitted S1 work: allOwn/preferPage/pkbOwned in TargetVerb, plus `pageControlsOutrankPickleballChatText` in RetestFixesLiveTest). Delete the patch file once the change lands.
2. **D1 / G3: bare boolean flags.** A bare boolean flag followed by another `--flag` means true. Fix `ConsumerReadyCommands.flag()` / `headed()`, and audit every other bare-boolean reader for the same "next token is the value" bug (`--panel`, `--human`, `--json`, …).
3. **D4, D5, 6.4.2: `--human-override` on every control verb.** This includes `act` and `call`.
   - Strip it before per-verb key validation.
   - The inner verb of `call` (and `--args-file` JSON via a `human-override` key) inherits it.
   - It stays owner-only and logged.
4. **Frame-aware short ids.** Covers D13, D14, D19, D16, L1, 6.1.1 and 6.1.2.
   - Short ids and handles resolve in the frame they carry. This applies to every verb that takes `--handle`, `--query=<short id>`, a guide `t`, `arrow`, `step-badge` / `unstep-badge`, `label`, `spotlight` and `highlight`.
   - `highlight --query=<short id>` expands short ids.
   - Guide steps accept `{"t":"s1.h165"}` and `{"role":..,"name":..,"frame":..}`.
5. **L2, 6.1.4: `find --role` searches every frame by default.** Add `--frame=top|all|<id>`.
6. **Typing and select in iframes.** Covers D8, D9, 6.2.1, 6.2.2 and the round-3 e "Upload click applied=false".
   - `act --kind=type` uses a fallback ladder: `Input.insertText` in the element's frame → key events → `input` chain at the element centre. The reply reports the rung (`"via":"cdp-insertText"`).
   - Verify-after-write for `type`, `select` and `form-fill`: read the value back and report `"value"` and `"verified":true|false`.
   - `applied` follows the verified result, so a selected option or an appeared upload offer counts as applied.

### P2: Broken verbs and desktop safety (report priority 2 + round-3 b, c, d)

**Functionality:**

1. **D20, 6.6.6 (fix part): `pw` parsing.**
   - `PwCommand` works with and without an explicit project dir.
   - Area and action come from positionals or `--area=` / `--action=`.
   - `pw run --steps=<file>` and `call pw --args-file` work.
2. **D22, 6.6.2: `tab-new`.**
   - `tab-new` no longer silently becomes the protocol target. Default is `--activate=false`; `--activate=true` switches to it.
   - Every protocol reply carries a warning when the protocol target differs from the visible tab.
   - `tabs` lists new tabs.
3. **D21, 6.6.3: `frame --list`** is served by the start host (iframe id, name, url, sameOrigin), even while an isolate worker is alive.
4. **E1, E2, 6.3.5: time budget.**
   - `--budget-ms` on `find` and `act`.
   - A stderr progress line every 2 s on long lookups.
   - When the budget runs out, return the best candidates found so far, with `budgetExceeded:true`.
5. **D26, L8, 6.2.4: desktop type.**
   - Type uses UIA `ValuePattern` / `TextPattern`, falling back to `SendInput`.
   - `act --kind=type` accepts a non-interactive Document/Edit text target.
   - Hyphen-as-space works for desktop `--query`.
6. **6.7.2: foreground guard.** Every desktop input refuses unless the target window is foreground and its title matches. The reply reports the window title.
7. **Round-3 b:** `doctor orphans=` never lists a live pickleball host (the browser-events protocol host), and `stop` cannot kill it.
8. **Round-3 c:** `wait --condition=new-message --from=agent|human|any`, and the help explains the semantics.
9. **Round-3 d:** `guide --steps=@file` on a missing file says "steps file not found" and names the base dir used for relative paths.

**Docs:**
- The `pw`, `tab-new`, `frame`, `find`/`act` `--budget-ms`, desktop `act` and `wait` help.
- `docs/browser-protocols.md` where `tab-new` is described.

**Targeted tests:**

### P3: Misleading replies (report priority 3 + round-3 e)

**Functionality:**

1. **D2, 6.8.7:** unknown positionals are rejected with `error:` unless the verb declares a directory argument. `looksLikeProject` requires an existing directory.
2. **D11, 6.3.3, round-3 e visibility:**
   - `input type=hidden` is not a textbox and is not listed by `snap`/`find` by default.
   - `snap`/`find` rows use layout visibility (display, visibility, size, ancestors, collapsed menus).
   - Human find on a collapsed panel returns `visible=false` rows.
   - A collapsed snap hides chat rows.
   - "Open agent panel" is hidden while the panel is open.
3. **D12:** the `stale_ref` fix line suggests `--refind=chain`.
4. **D15, D17, D18, 6.1.3:**
   - `step-badge` reports the badge's real visible state.
   - `checklist` and `ui-verify` overlaps include page controls. The default placement avoids them.
   - Anchored placements follow their element (ResizeObserver + MutationObserver, scroll and resize) and are `lost` only when the anchor is detached.
5. **D24, 6.8.3, G7:** `--fields` unknown names fail with `error: unknown field "x"; known: ...` on `chat-read`, `find`, `snap` and any other `--fields` verb.
6. **D25, 6.6.4 (fail-clear part):** collaboration verbs (overlay, chat-send, panel-open, cards, placements) given a `--target` that is not the start host or worker fail with `unsupported on attached target`.
7. **D27:** the act/query error names only flags that the verb accepts.
8. **D28, D29, 6.7.5:**
   - Desktop targets parse the same way for snap/find/act, including hyphenated app names and the warm hop.
   - Desktop replies carry `state.frame=desktop:<window title>`.
9. **L3, 6.6.1, G8:** `eval --await` (CDP awaitPromise; with Promise results returned by value) and `eval --frame=<id>`.
10. **L4:** `inspect-page` / `find-element` on a start host say an isolate worker is needed, and name the command.
11. **E10, 6.8.4:** lean placement replies `{id, kind, visible, rect, overlaps}`. `guidance`, `summary` and `sha256` move behind `--verbose`.
12. **E9, 6.2.3:** `input --text=<s> --at=<short id>` sends one `Input.insertText`.
13. **D23:** `tab-activate --page=<url substring>`.
14. **D3:** `doctor --protocols` reports the worker browser's backends when a worker is alive (both, labelled).
15. **Round-3 e rest:** the timeout fix hint is one line, not the full usage.

**Docs:** help for every changed verb.

**Targeted tests:** one test per item above, in the classes that own the verb (new methods). Windows live: repro D15, D16, D27, D28 and D29.
