**Design brief / component contract**

All visual components are first-class kinds under SurfaceAssets and placed by PageSurfaces. AgentControl.execute is the one spine. AgentSurfaceRouter.route runs first and sends the op to the page, the Chromium popup (`agentsurface` package), or native `NativeHighlightBox`.

CLI verbs (add to WorkbenchCommandLine.AGENT_CORE_COMMANDS, usage in WorkbenchCliHelp, inventory docs/roadmaps/workbench-cli-inventory.json):
- `arrow` / `unarrow` — visual arrow pointing at a resolved target or from/to points.
- `step-badge` / `clear-steps` — numbered visual badges on the page (NOT Gherkin editing).
- `magnifier` / `unmagnifier` — magnifier over the target.
- `spotlight` / `unspotlight` — dim the page, cut out the target using resolved bounds.
- `border` / `unborder` — standalone border component beyond highlight presets.
- `label` / `unlabel` — label command.
- Enhanced `overlay`: accept and store `--width` `--height` (w,h). When the target is resolved, the box uses the resolved element's bounds (same on CDP and native paths). Overlay remains one fixed callout style.
- Existing: highlight/unhighlight (PageSurfaces.highlight ignores its x,y,width,height args), html-*, popup-*, etc.

Geometry source:
- Prefer query-resolved element bounds (visual_viewport_relative) for any box, arrow, spotlight, border, label, magnifier over a resolved handle. Same way on CDP and native paths.
- Caller-supplied x,y,w,h only when no resolved target.
- rememberGeometry(handle, x, y) keeps only a point. Full bounds come from the resolved element at placement time.
- Overlay callout style stays fixed; new kinds have own CSS/JS in resources/tools/dscode/browser/surface/.

Cleanup / safety:
- Injected nodes carry `data-pkb-agent=agent_injected` plus a sentence.
- Parser strips scripts, on* handlers, javascript: URLs.
- IDs pkb-N under a file lock.
- Placements ledger `.pickleball/runs/<run-id>/agent/placements.json`.
- Undo outside the document. html-cleanup, kind-remove, and scenario end remove everything.
- `--target=auto|page|popup|native`, `--pane` where applicable.
- Same commands on Windows/macOS/Linux and across in-page/CDP, popup and native paths where practical; only required platform differences, documented.

Logging: toggleable per-entity (`pkb_composite_log=arrow,step,magnifier,spotlight,border,label,overlay,...`), date-stamped, size-capped. Off unless named.

MCP `McpRegistry` / `workbench_agent_command` / `surfaces`, POST /v1/agent/command, and Workbench only forward. No business logic there.

CLI-first and logging checklist (must be true at the end of every phase and the whole roadmap):

- [ ] Every non-CLI surface (Workbench, MCP, popup, HTTP, Gradle) only forwards.
