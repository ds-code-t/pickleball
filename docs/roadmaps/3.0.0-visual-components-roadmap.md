**Design brief / Component contract**

One spine (`AgentControl.execute`), multiple adapters (`AgentSurfaceRouter.route` → in-page `PageSurfaces` / Chromium popup `agentsurface` package / native `NativeHighlightBox`). Every new capability is a first-class `SurfaceAssets` kind + CLI verb, reachable from the CLI; MCP, Workbench, HTTP, Gradle, and popup only forward. No business logic outside the spine.

| Kind / CLI verb | Args (beyond common `--target=auto\|page\|popup\|native`, `--pane`, `--handle`/`--query`) | Geometry source | Cleanup | Routing |
|---|---|---|---|---|
| `overlay` (extended) | `--width`, `--height` (accept and store w,h) | Resolved element bounds when target resolved (same on CDP and native paths); else remembered point or explicit. Overlay remains one fixed callout style | `overlay-remove`, cleanup, undo, scenario end | `AgentSurfaceRouter` → page / popup / native |
| `label` / `unlabel` | `--text`, optional style | Resolved bounds preferred; boxes use element bounds | specific remove or cleanup | same |
| `border` / `unborder` | style preset or color/width (standalone beyond highlight presets) | Resolved bounds | `unborder` or cleanup | same |
| `arrow` / `unarrow` | from/to handles or target + direction | Resolved or explicit points | remove or cleanup | same |
| `step-badge` / `unstep-badge` | `--number`, optional `--text` (visual badges on the page only; NOT Gherkin editing) | Resolved bounds | remove or cleanup | same |
| `magnifier` / `unmagnifier` | zoom factor, target | Resolved bounds | remove or cleanup | same |
| `spotlight` / `unspotlight` | dim level, cutout target (dim page, cut out the target) | Resolved bounds | remove or cleanup | same |
| `highlight` (existing, tightened) | ignores extra x,y,width,height args | CDP `Overlay.highlightNode` or reversible style | `unhighlight` | same |

- Injected nodes: `data-pkb-agent=agent_injected` plus a sentence. Parser strips scripts/on* handlers/javascript: URLs. IDs `pkb-N` under file lock. Placements ledger `.pickleball/runs/<run-id>/agent/placements.json`. Undo outside the document.
- `PageSurfaces.highlight` ignores its x,y,width,height args. `rememberGeometry(handle,x,y)` keeps only a point. Query-resolved bounds used the same way on CDP and native paths.
- Label and border as first-class `SurfaceAssets` kinds (alongside html, overlay, highlight).
- CLI-first: every capability reachable from the CLI (`WorkbenchCommandLine.AGENT_CORE_COMMANDS` and usage). MCP, Workbench, popup, HTTP, Gradle only forward. No business logic outside `AgentControl`.
- Logging: toggleable per-entity date-stamped size-capped (`pkb_composite_log`) for every new kind (arrow, step, magnifier, spotlight, border, label, overlay).
- Same commands on Windows/macOS/Linux and across in-page/CDP, popup and native paths where practical; only required platform differences, documented.
- Gherkin syntax unchanged; step annotations stay single string literals; never weaken, skip or delete tests.
- Targeted tests only. No full regression, validate --all, first-start timing, or Maven @all.

### Baseline audit (recorded in this phase)

Checked against `AgentControl`, `AgentSurfaceRouter`, `PageSurfaces`, `SurfaceAssets`, `CompositeWebElement`, `NativeHighlight`, and `WorkbenchCommandLine.AGENT_CORE_COMMANDS`.

| Gap | Current behavior |
|---|---|
| Overlay width and height | CLI already copies `--width` and `--height` into the agent args. `PageSurfaces.place` never reads them. The callout CSS is fixed (`max-width: 280px`) with only left and top. |
| Resolved element bounds | `rememberGeometry` stores a rounded x,y point (`int[2]`). `CompositeWebElement` passes visual-viewport x,y and drops width and height. `geometryPoint` reads x,y from `visual_viewport_relative` and drops width and height. Native highlight uses query JSON or explicit x,y,width,height. The page overlay path does not. |
| Highlight geometry args | `PageSurfaces.highlight` takes x, y, width, and height and does not use them. CDP `Overlay.highlightNode` or reversible DOM style is the whole paint. |
| Kinds | `SurfaceAssets` sentences and files are html, overlay, and highlight (plus instructions and diagram, which share html). No label, border, arrow, step, magnifier, or spotlight kind. |
| CLI verbs | highlight/unhighlight, overlay/overlay-poll/overlay-remove, html-*, popup-*, chat-*. No label, border, arrow, step-badge, magnifier, or spotlight verb. |
| Logging entities | `pkb_composite_log` names used by surfaces are observe, launch, window, chat, highlight, overlay, html, and capture. No label, border, arrow, step, magnifier, or spotlight entity. |
| Merge marker | `docs/dynamic-control-api.md` contained a stray `>>>>>> d5f4d52f` line. Removed in this phase. |

Existing checklist for the surfaces that already ship: each of those verbs is on the CLI; Workbench, MCP, HTTP, and Gradle forward `AgentControl.execute`; logging for overlay, highlight, and html is toggleable, per-entity, date-stamped, and size-capped.
